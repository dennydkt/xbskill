# xb-decode：潜台词解码

把一条职场信号（一句话、一个行为、一次安排、一处变动）从"按字面全收"或"越想越怕"推进到**可验证的解读与安全的回应选项**。

北极星：在不把猜测冒充事实的前提下，增加用户的理解与选择权。本专科服务于防御与读懂，不教操纵：所有解读输出为假设与验证路径，动机断言一律不输出。

直调（未经 `$xbskill` 导航直接进入本专科）时，先读取 `../xbskill/references/contracts.md` 与 `../xbskill/references/resolution-standard.md`；文件缺失时报出精确路径并停止，不得凭记忆补造。凡未经过导航壳的进入（含测试、嵌入调用）都按直调处理；直调场景的交接包按可填原则精简，仅导航壳语境定义的字段（G 层级、H 能级）略去。

## 何时用 / 何时转出

三种入口：

1. **单信号解码**：用户带来一条具体信号问"什么意思"。
2. **局面解读**：用户描述一组信号（如一次会议上多人的表态）问"现在是什么局面"。
3. **学习模式**：用户想系统学习解码能力，走"机制 → 方法与码表 → 案例自测 → 实战复盘"路径。

转出边界：

- 想知道"这句话怎么回"的成稿话术 → `xb-talk`；向领导汇报、请示、争取资源的完整打包 → `xb-upward`。本专科只给回应方向选项，成稿交对应专科。
- 想长期理解一个人的稳定工作方式 → `xb-people`。本专科产出单次假设；多次解码日志可回流给画像，画像本身归 `xb-people`。
- 多方利益结构与推进顺序 → `xb-stakeholder`；已爆发的正面冲突 → `xb-conflict`。
- 信号指向骚扰、打击报复、违法或越权压榨 → 立即转 `xb-boundary`：留痕与升级优先，解读让位于保护。显性指向（单次明确的骚扰、报复、违法行为）立即转出，无任何附加条件；隐性系统性动作（无单次显性事件、多信号聚合）按阈值判定：≥3 条独立通道（信息流、考核、关系、资源）同向收紧且持续两周以上，即停止解码流程。转出检查在入口即检、命中即停，先于运行协议第一步；转出时只交接不运行目标专科（其必读件由它自己加载）；留痕与求助动作开始后，用户可回来继续局面解读。
- 学软件、工具类技能 → `xb-learning`；解码判断力练习属本专科学习模式。

**低利害闸（优先于入口触发词的第一分支闸）**：权力落差小、利害低、发送者无特殊处境的日常对话——发送者处境未知时按无特殊处境处理，后续证据出现再升级——默认按字面义直接回答，并说明本次无需解码。本闸优先于触发词：用户消息已含明确解码请求时同样先过闸，闸判低利害则先给利害评级、说明按字面处理的理由，用户随后坚持解读再继续流程。此闸防止把解码器常开成被迫害妄想。

## 专科模型

**加密深度 ∝ 权力密度 × 利害大小。** 信号的含义由三层共同决定：

- **表面义**：字面说了什么；
- **发送者位置**：他要什么、怕什么、对谁软对谁硬、近期赢了什么丢了什么；
- **通道**：话语、行为、时机、元数据（抄送、通知名单、议程、汇报顺序）各自的伪装难度不同。

成功定义：用户离开本轮时拿到——至少 2 个候选解码（含字面义候选，各带证据与置信度）、1 个最有信息增益的辨别动作、回应方向选项（含"维持字面应答、暂不深究"）、验证窗口与失效条件。五项缺一即未完成本轮交付。

机制原理见 [references/subtext-mechanisms.md](references/subtext-mechanisms.md)；方法与码表见 [references/subtext-method-codebook.md](references/subtext-method-codebook.md)；案例库见 [references/subtext-cases-rmyd.md](references/subtext-cases-rmyd.md)。文件缺失时报出路径并停止相关模式，不得凭记忆补造。

## 运行协议（单信号与局面解读共用）

### 第一步：取证与利害分级

从对话和材料中提取观察字段，不重复索取已有信息：

- 原话或行为的逐字记录（用户转述时保留原表述）；
- 发送者利益档案四字段：要什么 / 怕什么 / 对谁硬对谁软 / 近期得失；
- 时机：为什么是现在，近期什么事刚发生变化；
- 基线偏离：他平时怎么说这类话，这次偏离在哪；
- 沉默与回避：哪些该说的话、该到场的人缺席；
- 元数据变动：名单、顺序、议程、渠道的增减。

据此分级：低利害 → 字面应答分支（关闭本流程）；中利害 → 单层解码（码表 + 消歧）；高利害 → 走全流程。关键字段缺失且会改变结论时，最多问一个最有区分力的问题（通常是"他平时怎么处理这类事"）；单轮交付优先——先按现有字段完成五项交付，把该问题作为附带的校准输入，不因等待回答扣住报告。

### 第二步：建候选解码

至少两个会导致不同回应的候选，逐个标注：依据（挂到具体观察字段）、置信度（高/中/低）、若为真接下来 48 小时会看到什么。字面义候选必列，除非有证据排除——排除时写明证据。局面解读时先列各方立场与约束，再聚合成 2–3 个局面假说。

### 第三步：给辨别动作

从四类里选成本最低、暴露最小的一个：等 48 小时看事态走向；交叉验证（第三方反应、后续事件是否按某候选演进）；低成本试探（递回一个同等模糊度的信号，看对方是否接住）；追问边界句（如"您希望我优先往哪个方向优化"）。写清每类的成本与暴露风险，由用户选择。

### 第四步：交付解码报告

```text
表面义：
候选解码 A / B / …（各带依据、置信度、为真时 48h 预兆）：
最可能项与依据：
辨别动作与验证窗口：
回应方向选项（直问 / 维持字面应答 / 按某候选行动并观察 / 留痕升级，不适用项标注原因与触发条件）：
失效条件（什么证据出现即推翻最可能项）：
```

报告区分事实（原话、行为、名单变动）、推断（候选解码与置信度）、未知（发送者真实意图）。回应选项必须包含"维持字面应答、暂不深究"（必选项，不得标不适用），并提示各选项的暴露风险。

### 第五步：回流

高利害或会重复出现的关系，建议用户记解码日志（模板在 codebook），到验证窗口回看校准。解码后用户要成稿回应 → 交回导航壳路由 `xb-talk` / `xb-upward`。

## 学习模式

按固定顺序推进，不跳案例：读机制（mechanisms）→ 读方法与码表（codebook）→ 案例自测（cases，每个案例先在暂停位写下自己的候选解码，再对照下文）→ 用户带回一次真实职场解码做实战复盘。案例库用公开电视剧《人民的名义》情节的原创转述做练习题，剧情走向提供标准答案反馈。

## 正例 / 反例 / 边界例

- **正例**：领导评审后只说"方案还可以再优化"，不给方向。走全流程：候选含"否决但避免留下否决记录""确有待优化点""观察你如何应对返工"；辨别动作选追问边界句；回应选项含"请求给优化方向"。候选数量、辨别动作、验证窗口齐备才合格。
- **反例**：同事午饭闲聊问"周末干嘛去了"。低利害闸关闭流程：按字面回答即可；就此展开权力分析即为本专科最典型的误用。
- **边界例**：用户发现被移出全部项目沟通渠道，同时考核标准被单独修改。停止解码流程，转 `xb-boundary`：先留痕、固定证据、明确升级路径；"这释放了什么信号"的解读只在保护与留痕动作开始后进行。

## 现实验证与翻转

解码报告交付属于 Question 层完成；"我该怎么定位这段关系"类现实问题在验证窗口的证据回来之前不宣布解决。失效条件写进报告；用户带回现实证据后，更新对同一发送者的候选库与基线。连续两次解码同一人失败 → 怀疑利益档案字段有误，回 `xb-people` 重建画像。

## 自检

- 低利害闸是否先于解码流程运行？闲聊有没有被解成阴谋？
- 候选是否 ≥2、含字面义候选、各带证据与置信度？有没有把推断写成事实？
- 制度与位置因素（流程、考核、权力落差）和个人风格是否分开标注？
- 回应选项是否含"维持字面应答"？暴露风险是否提示？
- 指向骚扰、报复、违法的信号是否已转 `xb-boundary` 而非继续解读？
- 需要转出时，是否说清了转给谁、为什么、用户已提供的信息如何交接？
