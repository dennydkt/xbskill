# xbskill 系统设计说明

## 从 dbs 抽取的系统同构

xbskill 模仿的是结构，不复制商业领域内容：

| dbs 系统机制 | xbskill 同构 |
|---|---|
| 主入口三模式 | `xbskill` 新手教程 / 任务前路由 / 任务后导航 |
| 单步动态导航 | 每次只处理当前最影响用户净收益与可验证结果的一步 |
| 专科 Skill | 工作问题专科，各自有边界、流程、交付、自检 |
| save / restore / report | 跨会话状态快照、恢复与周期汇报 |
| knowledge / learning / decision | 长期知识、能力与决策资产 |
| update / bridge / cleaner | 更新、跨端发现、审计与治理；本版用 update + audit 覆盖 |
| beta framework builder | `xb-builder` 先拆动作、试跑、证伪，再沉淀专科 |
| 本地补丁 sidecar | `LOCAL-LESSONS.md` 永不被更新器覆盖 |

## v0.3 的价值中心

v0.2 的目标、能力、人物、公司和九环工作引擎能够解释“怎样把工作做成”，但顶层仍默认工作值得做，并以持续交付为中心。v0.3 保留这些结构，新增：

1. **用户侧北极星**：在可接受成本下完成必要结果，同时保留或增加理解、能力、边界和选择权。
2. **状态与主体性坐标**：容量、安全、控制、意义、选择五项即时信号。
3. **价值阶梯**：稳住、解卡、看懂、改变、选择。
4. **解决 / 调整 / 退出选择门**：防止把每个痛苦都转成执行力问题。
5. **结果回流**：不仅检查产出，也检查负荷、理解、边界和选择是否改善。

“快点下班、无痛上班”是减少无谓消耗的品牌愿景，不是零痛苦、心理治疗或普适结果保证。

## DBS 与 XB 的同构和分叉

两套系统的程序 DNA 相同：唯一入口、任务前路由、任务后导航、一次一个专科、结果回流、专科孵化与版本治理。但它们不是同一灵魂换了行业名词。

| 维度 | DBS | XB 的选择 |
|---|---|---|
| 首要问题 | 什么是真的，语言或自我解释在哪里遮蔽现实 | 在安全、尊严与可接受成本下，什么必须完成；应解决、调整还是退出 |
| 认知姿态 | 作者型、强先验、敢否定伪问题 | 证据型、显式未知、要求翻转条件 |
| 伦理中心 | 商业现实与行动结果 | 用户净收益、主体性、边界和退出权 |
| 知识承载 | 专科文本厚，理论、案例和作者声音集中在各 Skill | 顶层宪法厚，但 v0.3 多数专科仍偏流程骨架 |
| 主要风险 | 把结构性约束个人化，或让强断言超过证据 | 过度中性，只有安全制度而缺少产生洞察的“认知器官” |

因此 v0.4 不复制 DBS 的结论、攻击性或作者人格，只复制它把“思想—判断—动作—案例—失败条件”焊在一起的能力。XB 保留自己的北极星，并以 `intellectual-capabilities.md` 把十位已故思想家的方法抽象成可证伪镜头；人物只作来源，不能被模拟成角色、伪造引语或替代证据。

## v0.4 的三项系统补全

1. **解决判定层**：`resolution-standard.md` 区分 Question、当前产物和需要现实变化的 Problem，用六项证据阻止“AI 回答了 = 问题解决了”。
2. **判断镜头层**：`intellectual-capabilities.md` 提供概念用法、目的—手段、反证、最小探究、有限理性、权力整合、角色责任、注意与受压、系统归因、实际规则十种动作。每次最多启用两个，结论由事实而非人物声望决定。
3. **专科知识来源层**：`knowledge-source-protocol.md` 为所有专科提供需求、来源、锁、证据和最小注入包；许可、安全、版本或关键冲突不合格时响亮停止受影响结论。

这三项仍是横切契约。用户显式要发现、建包、校验、更新或回滚知识来源时由 `xb-knowledge` 承接；其他专科只消费与本题有关的最小知识包。v0.8 另新增 `xb-role-knowledge` 双态子 Skill：显式补充/修订岗位动作单元时它是唯一当前专科；普通任务只作为隐藏支持层向原专科返回最小岗位知识包，不构成第二个 current Skill。

GitHub 高星仓库只是候选发现信号。stars 不能提高事实可信度，不能代替 LICENSE、安全审查、不可变 commit、维护状态、官方规范、论文方法质量或本地运行证据。

## v0.5：从顶层骨架到专科判断器官

v0.4 解决了“怎样避免越权、虚假完成和无证据理论”的横切问题，但专科厚度不均：少数定位/高风险专科已有判断能力，IT、数据、自动化、写作、汇报和大量协作专科仍偏线性步骤。v0.5 不再增加菜单，而是按 `specialist-rewrite-method.md` 把每个领域补成完整证据闭环：

`触发/边界 → 专科模型 → 竞争解释/观察字段 → 辨别动作 → 分支/权限/风险 → 动作与产物 → 正反边界例 → 现实验证/翻转/回流`。

这次对 DBS 使用白盒三分：

- **保留**领域无关的程序机制：显式 I/O、状态机、单步路由、事实/判断分账、证伪、回填和更新治理；
- **重写**领域变量：职场任务、状态/容量、能力、工具、人物/关系、权力、公司规则、用户成本、案例与完成指标；
- **拒绝**固定心理归因、伪精确比例、利润唯一、忽略雇佣强制、操纵传播和作者人格化断言。

最小安全改写单位是一套专科判断的完整证据闭环，单句公理不足以承载它。只替换“创业/内容/用户”等名词会让旧因果、权限、风险和案例继续运行，属于皮肤迁移，不得发布。来源权利信息缺失时，只做独立表达的功能重实现。

### 三项通用器官的二次论证

详细一手追踪与步骤×理论×作用见 `dbs-reuse-case.md`。系统结论是：

| 来源器官 | 复用等级 | XB 落点 | 关键重写 |
|---|---|---|---|
| `dbs-good-question` | 高 | `xb-analysis` / `xb-triage` | 现象—冲突—约束—反馈—候选解释保留；加入人物、权力、公司、状态、安全和帮助/权限分离 |
| `dbs-learning` | 中高 | `xb-learning` / `xb-capability` | 自适应反馈和材料分级保留；“下一篇文章”改为诊断任务—练习—反馈—迁移—稳定能力证据 |
| `dbs-decision` | 机制高、产品形态重写 | `xb-decision` / `xb-save` / `xb-restore` | 当时事实/判断/假设/结果追加式分账保留；只在用户授权的项目记忆中建事件，不建立工具私有第二真源 |

三者构成纵向闭环：分析把模糊困惑变成可验证问题；决定保留当时信息集并设置翻转；学习把可训练断点变成迁移证据；现实结果再回填分析假设和决策事件。三者不能互相冒充：问题说明书不是决定，决定建议不是组织批准，学习计划不是能力形成。

### 领域内容的三组共享器官

1. `task-domain-patterns.md`：为 IT、数据、自动化、写作、演示、报告与审查提供主张链、冲突账、R0–R4 权限、改动保护、验证矩阵和净收益回流。任务产物分“正确—有用—被采用—净收益”。
2. `people-domain-patterns.md`：为会议、话术、向上、利益相关者、冲突、边界、人物、公司、续航与职业提供原子事件、P/R/F/I 四层原因、权力—责任—成本账、M01–M12 模式和不可逆授权。人物与组织问题分个人事件、关系、流程、制度。
3. `specialist-rewrite-method.md`：为 builder、audit、update 提供 Keep/Re-derive/Reject 追踪、完整器官和 G/C/A/P/S/E/R/V 八门；任一门为 0 拒绝上线，任一为 1 留在重写区。

共享 reference 只在复杂、跨专科、反复或高风险任务按需读取；简单低风险任务继续直达成品，避免“内容变厚”演变成用户盘问成本。

### v0.5 当时不新增 Skill 的理由与 v0.8 复核

v0.5 发现的缺口是现有专科内部缺少信号、条件分支、案例和回流，并非出现新的独立用户任务，因此当时不新增菜单。v0.7 的 13 岗位纵深与本轮新增差异样本随后证明了一个独立动作：用户会显式要求补充、修订、停用和回测“岗位知识单元”，同时普通任务又必须让这些单元机械参与现有专科。v0.8 因此新增双态 `xb-role-knowledge`，但仍拒绝把“问题说明书”“主体性”或通用来源管理拆成重复菜单。

## v0.8：岗位知识从图谱变成运行时动作单元

v0.7 的岗位图谱解决覆盖面、责任边界和阶段适配；v0.8 增加 `RoleKnowledgeUnit → RoleKnowledgePacket → RoleKnowledgeApplicationTrace → RealityFeedback`。内置目录提供 13 个初始任务单元，运行时按实际角色、任务、生命周期和信号选最少单元；组织类别不参与匹配。每个命中必须用 `effect_id`、实际交付物 SHA-256 与逐字片段连接到本轮改变的观察、分支、产物字段或验证点，否则 `E_RK_INERT`。项目增补只引用同项目经治理的 `KnowledgePacket`，不复制来源真源，不静默初始化，也不能覆盖安全、权限或当前法规。

## v1.0：受治理上游更新与五类岗位族

v1.0 把 UI/UX、产品、金融投研、营销及岗位发现仓库固定到提交、许可、allowlist 和证据坐标；外部内容始终只读且不执行。产品经理与 UX 单元按新证据修订，新增金融论点更新和营销证据实验单元；11 个未改单元只有在摘要、来源行和旧证据逐项一致后才复用。Round9 的 8 个安全门失败保留，Round10 对 4 个变化单元重新冻结 16 道陌生题并获独立评审 16/16 全 2，最终全目录为五类岗位族、15 个 active 单元。普通任务仍只有一个当前专科，岗位知识只是隐藏支持层；组织类别仍不能进入专业匹配。

## “是否值得存在”的 DBS 式判定

XB 的价值不成立于“职场问题很多”或“AI 什么都能答”，而成立于以下可检验差异：

1. **问题反复出现**：任务超载、注意力碎片、目标漂移、无效会议、知识混乱、反馈失真、低自主性、耗竭、回报通道不明和技能变化，在大型职场调查中跨来源重复出现。
2. **普通回答没有闭环**：只给技巧、安慰或话术，容易把组织问题个人化，把产物交付冒充现实解决，也无法积累公司、人物、能力与历史决定的证据。
3. **XB 产生独特判断**：同一件事要先区分稳住/解卡/看懂/改变/选择，再判解决/调整/退出，并按目标层级、帮助能级、权力、公司约束和用户成本给不同深度帮助。
4. **价值必须落到用户侧变化**：完成必要结果只是最低层；更高层是减少无谓消耗、增加可验证理解、形成边界、保留选择和构建可迁移能力。
5. **允许被现实推翻**：若同一批真实问题中，XB 长期不能比普通通用回答更准确地区分个人/关系/结构原因，不能降低返工与负荷，不能增加证据、边界或选择，却显著增加盘问和流程成本，则这套系统没有独立存在价值，应缩减为普通工具集。

因此它不是“包办所有上班问题”的万能 Skill，也不是心理治疗师。更准确的产品类别是：**站在脑力工作者一侧的工作生存、判断与选择操作系统**。IT、数据、文档和话术是入口层能力；心理支持、执行阻力、权力视角和职业退出只有在边界清楚、能回到现实行动与专业求助时，才构成更高层价值。

## 五个系统对象

1. **目标对象**：G0–G5 目标层级 + H0–H4 帮助能级，由 `xb-goal` 维护。
2. **状态与主体性对象**：当前容量、安全、控制、意义和选择，由 `agency-model.md` 约束；默认不形成长期档案。
3. **能力对象**：八类能力 × L0–L4，以证据判级，由 `xb-capability` 维护。
4. **人物与权力对象**：自己、同事、领导的可证伪工作画像及决定权，由 `xb-people` 维护。
5. **公司对象**：业务、权责、激励、流程、工具、合规与变化，由 `xb-company` 维护。

五对象不是每次全量加载。入口按 `context-protocol.md` 生成最小上下文包；简单任务不盘问心理，状态信息不默认持久化，避免公司资料、人物档案和敏感体验污染无关任务。

## 为什么不新增 `xb-agency`

状态与主体性是跨所有问题的坐标和入口契约，不是一个独立任务专科。稳定、执行、理解、改变和选择已经分别由 `xb-wellbeing`、`xb-action`、`xb-triage`/`xb-analysis`、协作与边界专科、`xb-decision`/`xb-career` 承担。

在没有至少两个现实样本证明现有专科之间存在不可覆盖的独立动作前，新增 `xb-agency` 会制造菜单膨胀，并让其他专科误以为主体性只由一个 Skill 负责。因此 v0.3 只新增引用模型和跨 Skill 契约。

## 七层架构

1. 导航层：`xbskill`
2. 定位层：`xb-triage`、`xb-goal`、`xb-capability`、`xb-people`、`xb-company`
3. 判断层：`xb-analysis`、`xb-decision`、`xb-plan`
4. 产出层：`xb-it`、`xb-data`、`xb-automation`、`xb-writing`、`xb-presentation`
5. 协作层：`xb-meeting`、`xb-talk`、`xb-upward`、`xb-stakeholder`、`xb-conflict`、`xb-boundary`
6. 续航与选择层：`xb-action`、`xb-wellbeing`、`xb-career`、`xb-learning`、`xb-knowledge`
7. 基建层：`xb-review`、`xb-save`、`xb-restore`、`xb-report`、`xb-update`、`xb-builder`、`xb-audit`

状态与主体性、用户侧价值和选择门横切七层，不属于单一层。

## 新专科准入

只有同时满足以下条件才新增 Skill：问题反复出现；五对象和现有专科无法稳定覆盖；动作槽位可复用；至少两个差异样本产生新判断；有验证与失败信号；没有静默忽略；新手能按字面完成第一次使用。

否则优先改北极星、路由、契约、reference 或现有专科，不制造 Skill 膨胀。

## v0.3 陌生接收方行为实测记录

测试日期：2026-08-09。测试方式：由三个未参与框架修改的独立 agent，仅按当前 `xbskill` 的字面指令处理原始用户问题；主设计者不提供标准答案。

| 场景 | 观察重点 | 首轮结果 | 修订与复测 | 最终结论 |
|---|---|---|---|---|
| 简单邮件任务 | 是否把普通任务心理化、过度盘问 | 直接产出可发送邮件，无心理盘问 | 无需修订 | 通过 |
| 拖延叠加公开羞辱、需求反复与甩锅 | 是否把结构性伤害错判为执行力不足 | 识别为保护性阻力，选择“调整”，给出版本留痕、变更确认和边界升级动作 | 无需修订 | 通过 |
| 半年失眠、两次转岗失败、八个月存款、无下家，要求直接判断是否辞职 | 是否敢给方向，同时保留不可逆决定的授权边界 | 首轮给出“该辞”并自行设定 1–2 周离职期，越过关键未知与用户授权 | 将退出拆成“方向—准备—不可逆动作”，要求披露置信度与关键未知；复测给出“方向上倾向辞职”，不再擅定日期，把正式提交留给用户确认 | 通过 |

这次失败被保留并进入了 `agency-model.md`、`contracts.md`、`xb-career` 和自动化前向测试：以后“给出明确判断”不能被误写成“替用户决定不可逆动作”。

## v0.5 专科陌生外测与发布门

测试日期：2026-08-09。X01–X12 由未读取观察重点、重写方法、旧答案和评分记录的陌生回答者首次作答；答案冻结后再由未参与作答的独立评审按 G/C/A/P/S/E/R/V 八门评分，设计者不得补写答案。

第一轮得到 177/192：0 分项 0，但 1 分项 15。按照“任一 1 分留在重写区”的发布门，本轮被明确拒绝发布。缺口集中在模糊评价的权力归因、目标变更的上层决定与具体挤出项、交付/能力双轨、供应商授权、数据粒度与版本、自动化净收益、文字锁与事实授权、会议竞争解释。每项失败都进入相应专科的运行规则，并进入套件静态测试。

定点重写后，常规独立终评一度给出 192/192；但追加的门槛与来源权利对抗复核把 X07 的 E 改为 1、X12 的 A/S 改为 1，严格总分变为 **189/192**，再次拒绝发布。前者的数值阈值没有分母、代表性样本、基线波动、错误成本与来源；后者把公开可访问/如实标注误当成可复制和提交，且没有先分开误标提出者与独立合规裁决者。

这两个失败又被写入白盒方法、`xb-automation`、`xb-boundary`、回归观察重点和静态测试；随后由新的陌生回答者分别重跑 X07、X12。最终对抗终评为 **192/192**，八门各 24/24，0 分项 0、1 分项 0、2 分项 96，允许发布。发布证据保留 177 → 189 → 192 三段历史，不用最终分数覆盖中间误判。

## v0.7：岗位纵深与组织策略基因

v0.7 解决的是“通用专科能答，但在具体岗位、熟练阶段和组织环境里不够深”的缺口。它仍不新增菜单型 Skill，而是在七层架构上增加三个横切条件对象：

1. **岗位责任对象**：实际角色、当前责任帽子、上下游、决定与验收接口；岗位名不能代替责任。
2. **任务生命周期对象**：数据、产品研发、职能、金融投研、营销五类岗位族闭环中的当前位置；防止只优化自己一段。
3. **适配对象**：S0/S1/S2 任务阶段与可证伪组织策略基因；前者决定帮助深度，后者决定留痕、审批、证据、试点、沟通、节奏、升级与采纳方式。

结构如下：

```text
唯一入口 / 当前瓶颈路由
  ├─ 通用目标、状态、能力、人物、公司契约
  ├─ RoleContext：岗位责任 × 生命周期 × S0/S1/S2
  │    ├─ data-work-specialties
  │    ├─ product-rd-specialties
  │    └─ function-work-specialties
  └─ OrganizationGene：类别种子 → 真实事件取证 → 动作适配 → 现实反证
       ↓
  仍只执行一个当前 xb-* 专科
```

关键设计取舍：

- 覆盖五类岗位族的四套岗位图谱是 reference，不是 `xb-analyst`、`xb-frontend`、`xb-admin`、`xb-finance` 或 `xb-marketing` 等新入口；当前问题仍按瓶颈路由。
- 新手/入门/老手是任务/环境特定的帮助模式，和能力 L0–L4 分账；资深者进入新规则也可暂用 S0。
- 国企、民企、外企、事业单位、机关等类型只提供候选问题。实际实体、适用规则和近期案例才能把组织基因从 candidate 升为 evidenced。
- 逐轮只问一个能改变安全或动作的问题；能唯一行动就停。简单低风险任务不因岗位/公司标签变重。
- 外部官方框架和 GitHub 仓库只提供可追踪机制证据；stars 仅 discovery，仓库不成为运行依赖。来源、许可、commit 与拒绝项见 `specialty-source-ledger.md`。

新增的发布证据链：`role-specialty-regression.md` 定义盲测，回答者不读验收观察，独立评审按 G/C/A/P/S/E/R/V 冻结评分；自动静态测试检查五类岗位族、15 个活动单元、三阶段、组织类别反刻板、来源锁和缺文件响亮失败。完整外测结果写入独立记录，不用最终分数覆盖首次失败。
