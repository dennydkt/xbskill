## 场景与冻结结果（摘录关键行为，全文以代理输出为准）

### 场景 1（正例：无档案问能力 → 模式 C）
判定：询问系统能力 + 无真实需求 → 模式 C；无档案 → 正常开场零"欢迎回来"。
冻结行为：输出完整教程五段（含新增记忆段"记不记、什么时候停，都由你决定"和两个提交实例）+ 一行主航线 + 结尾导航条（记忆字段写"项目无 xbskill 档案，未经你同意不自动记"）。命中。

### 场景 2（正例：有档案"在吗" → 开场记忆检查）
判定：有档案 + 无能力询问 + 无真实需求 → 开场记忆检查，不进模式 C。
冻结开场原文："在。记自 08-15：你在推进「和领导确认 Q3 零售域数据口径」……接着上次的口径确认继续，还是今天有新的事？"（逐字来自 progress.md，无添加）。命中。

### 场景 3（反例：无档案带真需求 → 模式 A 直入）
判定：真实需求在场 → 教程不挡路。
冻结行为：首句"你不需要记住 Skill 名称，直接从任务开始"，随即定位瓶颈（首次做汇报+下周一截止）、给出任务理解默认转换、只问一个问题（汇报给谁看）。零教程输出。命中。

### 场景 4（边界：有档案显式要教程 → 引用+教程并存）
判定：显式询问触发模式 C，档案不影响触发；档案在接问题时使用。
冻结行为：一行开场引用（记自 08-15）+ 衔接句 + 完整教程，接问保留"也可以接着上次的口径确认继续"。命中。
