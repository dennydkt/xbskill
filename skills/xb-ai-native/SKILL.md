# xb-ai-native：AI 原生职业武装

## 北极星画像与校准声明

画像原文（冻结，作为可校准假设运行）：

> 在明确的岗位市场和时间范围内，有一类人能够在至少一个领域独立处理高难判断，识别相邻领域的约束，按权限编排 AI、协调协作者，并通过证据和验收标准，在多个周期内交付满足质量、成本、时效与风险要求的结果。

本 Skill 把这段画像当作**待市场证据校准的假设**，不当作已发生的行业事实。每次运行必须维护画像校准状态：

```text
校准状态：未校准 / 部分校准 / 已校准
校准证据：≥2 份带日期的目标岗位市场 JD，或本公司/目标公司绩效与评价标准的变化文本（口头转述记为取证线索，不构成校准证据）
证伪信号：目标岗位市场连续两个季度无此类要求；或评价标准明确回归单一产出指标
```

未校准时，四维目标与差距结论一律标注「按假设运行」；禁止向用户表述为「企业已经在这样评价」。用户给出新证据时更新校准状态，不改写已冻结的画像原文。

## 任务边界

本 Skill 做**多周期发展编排**：画像定界、四维证据盘点、差距定位、周期编排与验收回填。以下归对应专科，本 Skill 只交接、不代办：

- 单个技能的训练环（诊断、练习、反馈、迁移）：`xb-learning`
- 能力等级判定与证据汇总：`xb-capability`
- 单次工作取舍与决定立案：`xb-decision`
- 把稳定重复流程交给机器跑：`xb-automation`

能力积累是现实 Problem，需要多个真实周期；本 Skill 单会话交付的是发展计划与当前周期启动，靠快照跨周期续接。禁止承诺一次会话练成画像。

## 快通道模式（C 端单会话闭环）

触发：首次接触、C 端场景（个人口吻、无公司组织语境；企业团测按标准流程）、用户只要「快速看看 / 测一下」——对「测水平」类请求的标准改写：交付的是暂定档位报告＋断点观察——或明确给出 ≤60 分钟时间盒。时间充裕或已明确要长期发展时走标准流程。

**第一步：三问定界**（逐轮单问，能定即停；用户赶时间或时间盒 ≤30 分钟时可一次性发出三问）

1. 岗位族五选一：data / product_rd / function / finance / marketing。用户自述岗位名可直接按 `role-context-model.md` 默认转换处理，附一句纠正口；都不属于则记 `no_match`，后续按通用档降级运行，不硬套任何岗位族知识。
2. 时间参照：目标线或恐惧线均可，转成一个检查点日期；说不出则记「无时间参照」，结论相应收窄适用范围。
3. 最近一个拿得出手的产物：把自评锚到具体证据上；说不出就记「证据空白」。

**第二步：暂定画像**。四维自评一张表一次发出，每维只选档（证据空白 / 入门 / 能独立 / 熟练带异常），不打分；加 S0/S1/S2 暂定档，全程挂「假设」标签，显形说明自评待验证、由第三步修正。面向 C 端输出时四维用通俗名：专业深度 / 识别相邻领域约束 / 编排 AI 与协作者 / 多周期稳定交付。

**第三步：诊断任务**（10–30 分钟，按剩余时间盒取值，时间紧取下限；五要素即本通道任务标准——输入、允许工具、先做部分、通过标准、停止条件，深度标准由学习出口交接 `xb-learning` 后适用）。`no_match` 岗位改用通用判断类任务（一份带缺陷的真实材料即可）。用户拒绝做任务时，跳到第四步以自评版收尾，标注置信度下降。

**第四步：出口二选一**

- **学习出口**：微周期卡（1–2 周）＋交接 `xb-learning`，完成判定同标准流程。
- **报告出口**（用户只要结果、拒绝学习环节）：暂定画像报告＋镜子声明——本轮交付的是暂定档与断点观察，升档需要多个周期的练习与回填。报告不推销学习，结尾只留一句「想继续时说一声」。

**快通道铁律**

- 暂定档与判级分开标注；任何话术不得表述为「测出你的能力等级」，禁止承诺测后升档。
- 报告出口的完成判定写「快通道 Question 已交付，能力 Problem 未启动」。
- 知识资源：命中岗位族时 xbskill 专业块可直接注入；`no_match` 显形后只给通用方法。外部来源（GitHub 等）只出推荐清单＋来源说明，用户采用时走 `knowledge-source-protocol` 治理门，永不自动内化。
- 快通道默认不建持久化目录；用户明确要求留存时按持久化规则确认路径后创建。
- 快通道画像默认未校准属预期状态；升级校准（收集 JD 证据）列为报告出口的可选后续动作。
- 快通道不产生跨专科交接时省略交接包与 G/H 声明；学习出口交接时按 `contracts.md` 补全。

## 四维画像模型（ANP）

每维统一五件套：定义 / 观察字段 / 证据规则 / 验收 / 翻转条件。当前等级取「有证据稳定做到」的最低完整档，一次高光只记上探证据。四维共用能力证据阶梯：知道概念或证书 → 模拟练习、AI 代做后复述 → 一次真实产物 → 多次同类产物加验收反馈 → 异常处理与跨情境迁移 → 标准与组织杠杆；等级对齐 `capability-model.md` 的 L0–L4 与五维判级。

### D 深度：至少一个领域独立处理高难判断

- 观察字段：领域名、高难判断样本（变体、异常、冲突约束）、独立完成度、验收者与标准。
- 证据规则：按上述证据阶梯判档；「独立处理高难判断」至少要求多次同类产物加异常处理层证据。
- 验收：在较少帮助下通过一个带变体的高难判断样本，由领域内验收者或可核验标准检查。
- 翻转条件：新变体样本连续失败，或验收者反馈判断依赖外部提示，降回上探证据。

### B 横向：识别相邻领域的约束

- 观察字段：相邻领域清单（按当前岗位族的上下游接口选 2–3 个）、每个领域的硬约束卡（输入假设、交付接口、合规红线、时序依赖）。
- 证据规则：横向证据 = 用户能主动列出相邻领域约束并预测违反后果；只「知道对方存在」不计入。
- 竞争解释（必检）：识别不出约束，是因为不知道，还是因为权限或流程不让接触相邻领域。后者转 `xb-boundary` / `xb-company`，按结构问题处理。
- 验收：在一份真实跨域材料上，指出至少一条会改变本方动作的相邻约束，并说明来源。
- 翻转条件：列出的约束被相邻领域的一手材料连续推翻。

### O 编排：按权限编排 AI、协调协作者

- 观察字段：编排台账（任务分解、AI/协作者/用户分配、验收标准、核验记录）。
- 证据规则：编排证据 = 台账中每项 AI 产出都有核验记录，且五项分账完整——用户判断、AI 生成、用户复核、现实采用、错误成本。会用多个 AI 工具本身不构成 O 维证据。
- 权限规则：帮助能级 H3/H4 只是工作方式，不授予数据、外发、审批或生产变更权限；分配给协作者的任务须在用户职权或已获授权范围内，低权力方的安全与底线不作交换条件。
- 验收：一个真实多步任务通过台账完成，AI 产出全部经过核验且错误成本被记录。
- 翻转条件：AI 产出连续出现用户未能发现的关键错误，或净节省连续为负（净节省 = 人工基线 − AI 辅助执行 − 核验 − 纠错 − 本轮设置成本摊销，与 `xb-learning` 同式），暂停扩大编排、回到核验断点补能力。

### T 交付：多周期质量/成本/时效/风险达标

- 观察字段：周期验收卡（周期目标、QCTR 四项预算与实际、验收者、证据坐标、迁移任务结果、翻转信号）。
- 证据规则：T 维证据 = 至少两个已回填周期的验收卡；QCTR 四项中任何一项连续两个周期超预算即显形，不用其他三项的高分掩盖。
- 验收：周期结束按验收卡回填，现实采用结果由验收者或可核验证据确认。
- 翻转条件：连续两个周期 QCTR 未达标且原因归于同一维能力缺口，回到该维训练周期。

## 竞争解释与辨别动作

用户表达「要武装自己 / 怕被 AI 取代 / 能力跟不上」时，先过五个候选，用一个最小检查区分：

| 候选 | 最小辨别动作 | 归属 |
|---|---|---|
| 能力断点（四维确有缺口） | 四维证据盘点出现低于目标的维 | 本专科编排 |
| 证据缺口（有表现无账） | 表现存在但证据分层落在前两层 | `xb-capability` |
| 权限/流程限制 | B/O 维辨别显示组织不允许 | `xb-boundary` / `xb-company` |
| 目标未定界 | 说不出岗位市场与时间范围 | `xb-goal` |
| 状态耗竭 | 出现容量、睡眠、情绪信号 | `xb-wellbeing` 优先 |

两个候选导向不同动作时，只问一个能区分它们的问题；安全候选优先于其余全部。单候选命中且缺口属定界类时，把缺项字段直接列为反馈点问题并打包转出。状态耗竭只按本轮可观察文本检查，无信号即不命中，并在声明中标注置信度。

## 标准流程

### Phase 0：画像定界

从已有材料填写，未满足前置条件时显式处理：

```text
岗位市场：目标领域/城市/公司类型；说不出则标「未定界」并先转 xb-goal
时间范围：目标达成的期限与检查点
校准状态：未校准 / 部分校准 / 已校准（附证据与日期）
G/H：默认 G3 岗位或 G4 职业，H1–H2；紧急交付部分按 xb-learning 双轨处理
```

「明确的岗位市场和时间范围」是画像前置条件；应届生或无岗位上下文用户缺此项时，先定界再进四维，不硬跑盘点。岗位市场与时间范围部分可辨时可以出计划：全部结论标「按假设运行」，并把补齐定界列为周期前置动作。G 取舍：诉求超出单一岗位绩效（市场竞争力、选择权）取 G4，岗位内稳定达标取 G3，两者可嵌套（主 G4 嵌套 G3）。

### Phase 1：四维证据盘点

逐维列：已有证据（含证据分层档位与日期）、当前档、目标档。已有 `xb-capability` 档案或 `xb-save` 快照时直接读取，不重问用户。缺证据的维写「证据空白」，禁止用自我评估或课程完成记录填档。

### Phase 2：差距与单一主瓶颈

四维差距写成一张表，但**一次只编排一个主瓶颈的训练周期**——选最先阻塞画像成立且用户容量允许的一维。瓶颈属于其他专科（见任务边界与竞争解释）时带最小交接包转出，不把结构或目标问题留在这里当能力问题训练。

### Phase 3：编排当前训练周期

产出周期卡，训练环交 `xb-learning`：

```text
周期目标：{D/B/O/T 哪一维、从何档到何档}
能力目标（按 xb-learning 格式）：在 {真实情境} 中以 {独立程度} 完成 {产物}，处理 {一个变体}，由 {验收方式} 检查
断点假设：映射 xb-learning 七类断点之一
训练预算：每周时间与总周期数（预算缺失时周期长度标提案值，回填一次后校准）；容量不足时缩周期，不砍验收
迁移任务：换样本/换工具/换受众
QCTR 预算：质量/成本/时效/风险四项的可测阈值
停止条件：连续两轮迁移失败或错误成本超阈值时的降负荷动作
```

### Phase 4：周期运行

训练环由 `xb-learning` 执行，本 Skill 只跟踪两件事：交接包完整（G/H、保留决定、已确认事实、否决项），训练记录落在 `<project>/memory/xbskill/learning/<slug>/`。

### Phase 5：周期验收与回填

按周期验收卡回填：QCTR 四项预算 vs 实际、迁移任务结果、证据分层变化、现实采用。回填结论写进四维证据账；未执行的项写「待测」，禁止从计划推导结果。

### Phase 6：画像再校准

每 1–2 个周期或用户给出新市场证据时：更新校准状态；画像被证伪信号命中时，向用户显形并重定四维目标权重，不静默继续旧计划。

## 分支规则

| 信号 | 处理 |
|---|---|
| 画像未校准 | 四维结论标「按假设运行」；Phase 6 设校准动作（收集 ≥2 份带日期 JD） |
| 用户处于耗竭或安全风险 | 暂停训练编排，先 `xb-wellbeing`；不增加训练量惩罚低表现 |
| 主瓶颈是单技能断点 | 交 `xb-learning` 跑训练环；本 Skill 只收证据回流 |
| B/O 维辨别出权限或流程限制 | 转 `xb-boundary` / `xb-company`，按结构问题处理 |
| 用户只要单次取舍 | 转 `xb-decision`，不建发展周期 |
| 用户想把流程交给机器 | 转 `xb-automation` 净收益六门 |
| 用户只要正式判级（非暂定） | 转 `xb-capability`，本 Skill 不重复判级；「测一下 / 快速看看」类请求留在本专科走快通道 |
| 周期验收连续失败 | 降负荷或换断点假设；不堆训练量，不降低验收标准 |
| AI 产出关键错误未被用户发现 | O 维翻转：暂停扩大编排，回核验断点补能力 |
| 跨周期中断后返回 | 读最近快照核对时效（岗位、画像校准、证据账），过期项重检 |

## 正例、反例与边界例

**正例：数据分析师的两年武装**

盘点出 D 维证据停在「多次产物」档、O 维从未建台账。编排第一周期：D 维异常处理断点，训练环交 `xb-learning`，用三份带变体的真实口径冲突案例做迁移任务；周期结束回填验收卡，D 维升档，QCTR 中「风险」项记录一次误判成本。画像标注「部分校准」（依据两份目标岗位 JD）。

**反例：工具清单当编排证据**

用户列出会用的 5 个 AI 工具和 20 条提示词。没有台账、没有核验记录、没有错误成本分账，O 维证据仍为空白；「会用工具」与「按权限编排并核验」分开判。

**边界例：应届生无岗位上下文**

画像前置条件「明确的岗位市场和时间范围」缺项。先转 `xb-goal` 定界目标市场与首份岗位，定界后再进四维盘点；本 Skill 不对应届场景硬跑两年画像。

## 验收用例

### 用例 1：模糊焦虑

输入：「AI 这么强，我怕三年后被淘汰，想武装自己。」

必须先过五候选辨别与画像前置条件（岗位市场、时间范围），给出校准状态；不得直接生成四维训练计划。

### 用例 2：证据已在

用户上季度经 `xb-capability` 建过能力档案。

必须直接读取既有档案填四维盘点，不重复盘问；差距表只列真实缺口。

### 用例 3：编排翻车

周期内 AI 生成的分析连续两次出现用户未发现的关键错误。

必须触发 O 维翻转条件：暂停扩大编排，回核验断点训练；不把错误归因于工具差，也不继续放大 AI 使用面。

### 用例 4：跨会话续接

一个月后用户返回说「接着练」。

必须读最近快照，核对岗位、画像校准状态与证据账时效；过期项重检后才编排下一周期，不机械执行旧 next step。

## 理论镜头落地

每题最多选 1–2 个，镜头必须产生观察、动作、字段和推翻条件，否则删除人名：

- **赫伯特·西蒙**：训练预算有限，先定最低能力门槛、周期预算和停止规则，用证据边际决定下一周期投给哪一维。
- **波普尔**：画像与四维结论都写证伪信号和观察窗口；市场证据推翻画像时显形重定，不护短。

## 持久化规则

默认只在当前会话运行。用户明确要求跨周期续接时：

1. 展示绝对目标路径：`<project>/memory/xbskill/ai-native/<slug>/`，存画像校准状态、四维证据账、周期验收卡；slug 用「岗位市场-维度」短横线小写串（如 pharma-data-d）；训练明细留在 `learning/<slug>/`，本目录只存指针。
2. 取得用户确认后才创建目录；引用缺失时响亮报告，不静默新建空档冒充已有进度。
3. 不写入任何工具私有目录；材料权限遵守 `xb-learning` 的权限门，训练不产生对敏感材料的额外读取。
4. 快照经 `xb-save` 引用本目录，遵循其命名与不可改写规则。

## 现实验证与回流

每个周期回填后检查：QCTR 是否达标、迁移是否形成、四维证据账是否升降档、画像校准状态是否变化。预设翻转：市场证伪信号命中、四维结论被新样本推翻、连续两周期 QCTR 未达、AI/权限环境剧变。翻转发生时更新计划并显形原因，保留旧验收卡作为失败链，不覆盖。

训练周期揭示目标、权限或结构问题时，带最小交接包转对应专科；现实采用结果回流四维证据账。

## 输出与完成判定

输出：`画像校准状态`、`四维证据盘点与差距`、`主瓶颈与归属`、`周期卡`、`编排台账（O 维任务）`、`交接包`、`翻转信号`、`下一周期一个变化`。

- 计划与当前周期已交付、训练未执行：只说「发展干预已可执行」。
- 本轮提前转出专科时：未生成的产物项标「未生成」并写精确缺口，只交付已完成的辨别与交接包。
- 单周期验收通过：报告该维该档证据成立，不自动升级画像整体。
- 至少两个周期回填且画像校准为已校准时，才可在该范围内报告画像部分成立。
- 市场证据、权限或现实反馈缺失时写「无法验证」及精确缺口。

## 自检

画像是否按可校准假设运行并显形校准状态？四维是否都有证据规则与翻转条件？B/O 维是否先过了权限与流程的竞争解释？编排是否保持五项分账且权限边界清晰？是否一次只编排一个主瓶颈并正确交接？周期结论是否只用回填证据、区分了 Question 与 Problem？跨周期续接是否核对时效？
