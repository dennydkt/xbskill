# 常见工作情境覆盖矩阵

本表是路由测试集，不是让用户记忆的菜单。遇到宽泛问题时用它检查遗漏；真实路由仍以当前瓶颈为准。

## 状态、主体性与选择门

| 常见情境 | 当前价值需要 / 门判断 | 默认候选 | 不能犯的错 |
|---|---|---|---|
| “帮我把这封普通邮件写好” | 解卡 / 解决 | `xb-writing` | 强迫盘问心理、职业和公司全貌 |
| “我知道要做，但完全动不了” | 先看懂，再决定解决/调整 | `xb-action` | 直接判定懒惰或只给番茄钟 |
| 连续加班、失眠、无法正常工作 | 稳住 / 调整或暂停 | `xb-wellbeing` | 用效率工具压过安全与恢复 |
| 被羞辱、骚扰、威胁或要求违规 | 稳住 / 退出当前私下消化路径 | `xb-boundary` | 教用户调整心态或讨好对方 |
| “是不是我能力不行”但目标权责反复变化 | 看懂 / 待定 | `xb-triage` | 未取证就做能力降级判断 |
| 工作能做完但长期不值得 | 选择 / 调整或退出 | `xb-decision` | 因为能完成就默认应该继续 |
| “要不要离职”且无即时危险 | 选择 / 比较调整与退出 | `xb-career` | 给一句“辞/别辞”的人生答案 |
| 环境暂时不可改变且用户决定留下 | 改变 / 选择可控变量 | `xb-boundary` 或对应专科 | 把暂时留下解释为环境合理 |
| 完成任务后负荷、边界和选择持续恶化 | 重新开选择门 | `xb-triage` | 把产物交付当整体问题解决 |
| 用户只想被听见，尚未要求行动 | 稳住 / H0–H1 | `xb-wellbeing` | 强迫立刻列行动清单 |

## 目标、能力、人物与公司

| 常见情境 | 默认候选 | 需要改路由的信号 |
|---|---|---|
| 不知道当前该先保交付还是做长期成长 | `xb-goal` | 已决定目标，只缺职业路径 → `xb-career` |
| 希望 AI 直接代做但又想真正学会 | `xb-goal` | 已有清晰学习任务 → `xb-learning` |
| 不知道自己缺分析还是沟通能力 | `xb-capability` | 只是一次具体失败需找原因 → `xb-analysis` |
| 准备晋升想盘点能力证据 | `xb-capability` | 还不知道公司晋升标准 → `xb-company` |
| 同样的话对同事和领导效果完全不同 | `xb-people` | 只需要写本次消息 → `xb-talk` |
| 领导为什么总追问细节 | `xb-people` | 当前需要准备正式汇报 → `xb-upward` |
| 通用建议在公司里根本做不了 | `xb-company` | 是某个跨部门项目的推进问题 → `xb-stakeholder` |
| 公司换领导/战略/考核规则 | `xb-company` | 需要据此重做职业选择 → `xb-career` |

## 接任务与推进

| 常见情境 | 默认候选 | 需要改路由的信号 |
|---|---|---|
| 领导只说“做得专业一点” | `xb-goal` | 已有标准，只是不知道工具 → `xb-it` |
| 需求反复变化 | `xb-goal` | 多方利益冲突 → `xb-stakeholder` |
| 同时来五个紧急任务 | `xb-decision` | 已排好但完全启动不了 → `xb-action` |
| 项目不知道从哪开始 | `xb-plan` | 目标本身模糊 → `xb-goal` |
| 进度总延期 | `xb-plan` | 根因不明 → `xb-analysis` |
| 外部依赖一直不交 | `xb-talk` | 涉多部门权责 → `xb-stakeholder` |
| 临时插单挤掉原计划 | `xb-upward` | 需要明确拒绝 → `xb-boundary` |
| 做了很多但没人认可 | `xb-career` | 交付本身不达标 → `xb-review` |

## 分析、数据与技术

| 常见情境 | 默认候选 | 需要改路由的信号 |
|---|---|---|
| 材料太多抓不住重点 | `xb-analysis` | 最终要写报告 → `xb-report` |
| 想找业务异常原因 | `xb-analysis` | 核心证据是表格/SQL → `xb-data` |
| 两张报表数字对不上 | `xb-data` | 系统接口故障 → `xb-it` |
| Excel 公式不会写 | `xb-data` | Excel 软件本身报错 → `xb-it` |
| SQL 查出来翻倍 | `xb-data` | 数据库连接/权限失败 → `xb-it` |
| 不知道图表怎么选 | `xb-data` | 已有图表想审查 → `xb-review` |
| 软件突然报错 | `xb-it` | 重复故障需自动修复 → `xb-automation` |
| 文件打不开/格式错 | `xb-it` | 数据内容已损坏需核对 → `xb-data` |
| 权限申请一直不批 | `xb-it` | 本质是跨部门阻力 → `xb-stakeholder` |
| 每天复制粘贴两小时 | `xb-automation` | 流程尚不稳定 → `xb-plan` |
| 想用 AI 替代整个岗位流程 | `xb-automation` | 任务边界不清 → `xb-triage` |

## 写作、汇报与会议

| 常见情境 | 默认候选 | 需要改路由的信号 |
|---|---|---|
| 写邮件怕不够正式 | `xb-writing` | 只差一句怎么说 → `xb-talk` |
| 写制度总被误解 | `xb-writing` | 目标和权限没定 → `xb-goal` |
| 周报像流水账 | `xb-report` | 缺少成果证据 → `xb-career` |
| 月报数据很多没结论 | `xb-report` | 需先分析数据 → `xb-data` |
| PPT 没有主线 | `xb-presentation` | 结论本身不可靠 → `xb-analysis` |
| 述职不知道讲什么 | `xb-presentation` | 缺成果资产账 → `xb-career` |
| 汇报被问住 | `xb-presentation` | 本质是坏消息管理 → `xb-upward` |
| 会太多没结果 | `xb-meeting` | 其实不该开会 → 输出异步方案 |
| 纪要没人执行 | `xb-meeting` | 责任冲突 → `xb-conflict` |
| 会议上没人表态 | `xb-meeting` | 存在隐性否决者 → `xb-stakeholder` |

## 沟通、关系与组织

| 常见情境 | 默认候选 | 需要改路由的信号 |
|---|---|---|
| 催同事怕得罪人 | `xb-talk` | 长期跨部门依赖 → `xb-stakeholder` |
| 想拒绝临时帮忙 | `xb-talk` | 已形成持续侵占 → `xb-boundary` |
| 如何给负面反馈 | `xb-talk` | 已升级为关系冲突 → `xb-conflict` |
| 怎么跟领导报坏消息 | `xb-upward` | 涉重大合规风险 → 正式升级渠道 |
| 领导总问为什么没做完 | `xb-upward` | 计划本身失真 → `xb-plan` |
| 想争取人手预算 | `xb-upward` | 多个部门竞争同一资源 → `xb-stakeholder` |
| 跨部门项目推不动 | `xb-stakeholder` | 只差单次催办 → `xb-talk` |
| 大家表面同意实际不动 | `xb-stakeholder` | 责任已明确但故意甩锅 → `xb-conflict` |
| 同事公开甩锅 | `xb-conflict` | 存在报复/骚扰风险 → `xb-boundary` |
| 合作关系已经僵了 | `xb-conflict` | 只需修一句回复 → `xb-talk` |
| 总被安排职责外工作 | `xb-boundary` | 需要领导重排优先级 → `xb-upward` |
| 下班后持续被联系 | `xb-boundary` | 已造成严重失眠耗竭 → `xb-wellbeing` |
| 遭遇羞辱、骚扰或威胁 | `xb-boundary` | 优先安全、证据和正式渠道 |

## 执行、压力与职业

| 常见情境 | 默认候选 | 需要改路由的信号 |
|---|---|---|
| 明知要做但一直拖 | `xb-action` | 任务没有价值、容量耗尽或存在风险 → 重新开选择门 |
| 任务太大不敢开始 | `xb-action` | 不知道交付标准 → `xb-goal` |
| 每天忙到崩溃 | `xb-wellbeing` | 核心是任务取舍 → `xb-upward` |
| 工作焦虑影响睡眠 | `xb-wellbeing` | 有持续失能/危险信号 → 专业求助 |
| 被批评后一直内耗 | `xb-wellbeing` | 需要准备回应 → `xb-talk` |
| 不知道该不该离职 | `xb-career` | 当下已不安全 → `xb-boundary`；处于急性失能 → `xb-wellbeing` |
| 想晋升但没成果 | `xb-career` | 不知道组织标准 → `xb-goal` |
| 想转岗但不知道缺什么 | `xb-career` | 需要系统学习 → `xb-learning` |
| 新岗位快速上手 | `xb-learning` | 资料混乱找不到 → `xb-knowledge` |
| 学了很多不会用 | `xb-learning` | 没有真实任务 → 先定义迁移任务 |

## 知识、复盘与系统

| 常见情境 | 默认候选 | 需要改路由的信号 |
|---|---|---|
| 文件夹里找不到最新版 | `xb-knowledge` | 需要修复文件损坏 → `xb-it` |
| 经验每次都从头来 | `xb-knowledge` | 流程稳定可机器化 → `xb-automation` |
| 交付前心里没底 | `xb-review` | 目标没有验收标准 → `xb-goal` |
| 项目做完想复盘 | `xb-review` | 要形成周期报告 → `xb-report` |
| 下次想接着这次继续 | `xb-save` | 已经有快照 → `xb-restore` |
| 想汇总半年项目演进 | `xb-report` | 快照目录不明 → `xb-restore` |
| 想更新整套 xbskill | `xb-update` | 只想审查现状 → `xb-audit` |
| 发现常见问题没有专科 | `xb-builder` | 只是单个一次性问题 → `xb-triage` |
| 担心路由/安全/覆盖漂移 | `xb-audit` | 已确认要修复 → 再单独授权修改 |

## 岗位纵深代表情境

岗位只改变当前专科的检查面，不替代瓶颈路由：

| 用户情境 | 当前专科 | 条件加载与不能犯的错 |
|---|---|---|
| 新手分析师被要求直接解释 KPI 下降 | `xb-data` | 加载数据图谱；先分口径/链路/结构/真实变化，不把 SQL 能跑当结论可信 |
| 数据管道显示成功但一个分区异常 | `xb-it` 或 `xb-data` | 按当前瓶颈选一项；检查部分成功、幂等、回填、消费者和回滚 |
| 数据治理目录完成但 owner 无人承担 | `xb-company` 或 `xb-stakeholder` | 治理覆盖不等于采用；找定义/决定/风险接受权，不让治理师自封 owner |
| 新产品经理收到“做个看板/AI 按钮” | `xb-goal` | 加载相应岗位图谱；给 S0 第一闭环和 no-build/试点门，不展开功能百科 |
| 前后端要做破坏性 API/数据库变更 | `xb-it` | 加载产品研发图谱；消费者、兼容、迁移、观测和回滚不能被“团队小”省略 |
| 老手架构师提出跨服务重构 | `xb-decision` | S2 比较质量属性、成本、团队/组织能力、迁移和反事实，不套面试架构 |
| 新项目经理在范围/资源/期限都不可变时被要求追赶 | `xb-plan` | 识别决定权矛盾并交付升级包，不把系统约束归执行力 |
| 行政遇到事业单位紧急采购 | `xb-company` 或 `xb-plan` | 先看实际实体、资金、权限和制度；单位类型不能直接决定法律适用 |
| “秘书”要准备董事会公告 | `xb-goal` 或 `xb-writing` | 先辨普通秘书与上市公司董事会秘书；命中法定职责时锁当前官方来源 |
| 国企熟人间低风险邮件 | `xb-writing` | 直接完成；不得因企业类别启动画像或审批盘问 |
| 外企向总部发送中国员工明细 | `xb-boundary` | 触发个人信息/跨境/授权门；公司类型不能替代真实数据流和有权复核 |

## 覆盖失效记录

若一个真实问题不能稳定路由，记录：用户原话、九环位置、两个候选为何都不合适、当前临时动作、是否反复出现。累计至少两个差异样本后再交 `xb-builder`，禁止为一次性问题增殖 Skill。

## 十案发布回归门

发布前按 `workplace-regression.md` 对任务过载、注意力碎片、优先级变化、无决定会议、知识真源、不可执行反馈、低自主性/冲突、压力失眠、晋升通道和 AI 技能风险十案做隔离复测。回答者不得预读验收标准，评审者必须在答案冻结后才评分。每案至少达到“当前一步已解决”，并明确整体 Problem 仍需哪个现实反馈；任何一案出现 0 分项都不得发布。

内容扩充版本还必须运行 `specialist-regression.md` 的十二案，覆盖模糊返工、目标漂移、任务型学习、纵向决策、IT 权限、数据口径、自动化净收益、写作保护、普通参会者权限、冲突归因、健康分流与保护性不行动。答案冻结后按 G/C/A/P/S/E/R/V 八门评分；关键词命中、文字更长或模板更多不能替代陌生回答者的实际判断质量。

岗位纵深版本还必须运行 `role-specialty-regression.md`。回答者不得预读验收观察；数据、产品研发、职能和反刻板案例分别冻结作答，再由独立评审按八门评分。简单邮件若被过度盘问、公司类别直接激活动作、阶段被写成身份、或高风险岗位场景静默退回通用建议，均视为发布失败。
