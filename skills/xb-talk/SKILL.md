# xb-talk：职场话术

直调契约：还必须读取 `../xbskill/references/resolution-standard.md`；缺失时停止，不得把可发送话术写成关系或结果已经改变。

完整读取 `../xbskill/references/context-protocol.md`、`../xbskill/references/contracts.md` 与 `../xbskill/references/intellectual-capabilities.md`。任一文件缺失时，明确报出缺失路径并停止本专科；不得凭记忆补造。相关人物画像存在时只使用有证据项；不存在时根据当前事件写话术，不猜人格。

当沟通反复失败、解释横跨个人/关系/流程/制度、涉及权力/报复、正式与实际规则不同或需要决定升级时，完整读取 `../xbskill/references/people-domain-patterns.md`；一次性低风险改写不加载。该文件应读而缺失时停止复杂诊断并报告路径，不得凭记忆补造模式。

## 触发与核心模型

本专科解决“怎样把一个真实意图变成对方可理解、可回应、且不越过用户承诺边界的表达”。它不负责证明对方动机，也不保证一句话能改变关系、资源或制度。

沟通结果链：`可核对事实 → 合法目标/边界 → 对方有权且有能力回应的请求 → 明确时间或选项 → 真实回应 → 下一动作`。话术只能改善接口；决定权、容量、激励或安全才是主因时，必须显形并转相应动作。

四层归因：P 看用户是否缺信息、当前容量或表达练习；R 看预期、信任与承诺；F 看请求、渠道、确认和升级接口；I 看权力、实际规则与拒绝成本。换表达后结果稳定改变才增强 P/R；不同人用同一接口均失败则增强 F/I。

## 可观察信号词典

| 原话/行为 | 候选断点 | 写话术前核验 |
|---|---|---|
| “方便的话帮我看一下” | 请求动作/截止不清 | 要对方做什么、何时、无空怎么办？ |
| “没问题，我尽量” | 容量与承诺被隐藏 | 最多能承诺什么，谁决定取舍？ |
| “收到” | 仅确认接收，不等于同意 | 是否需其决定、承诺或只需知情？ |
| “你看着办” | 授权范围不明 | 可自主到哪一步，哪些风险要回报？ |
| “大家都觉得/领导要求” | 来源和授权被模糊 | 谁的原话，谁有本事项决定权？ |
| 长篇自证后才提出请求 | 害怕冲突或权力风险均可能 | 最小必要事实；删解释会增加什么风险？ |
| “你总是/态度有问题” | 事实被人格评价替代 | 一个具体时间、行为和影响 |
| 已约定的回复点到达后仍无明确答复 | 可能是送达、渠道、容量、M05、M07 或权限缺口 | 请求是否一致、渠道是否可接收、对方是否有权回应、回复点/截止与等待窗口是否均已成立；催办次数只作轨迹证据 |
| 对方拒绝后用户继续软化请求 | 边界/成本下沉 | 用户不可承担项和可接受替代 |

## 话术内核

事实/共同目标 → 影响 → 具体请求或边界 → 时间/选择 → 留出回应空间。

## 思想镜头

每题最多启用 1–2 个镜头，并把 `触发证据 → 观察 → 辨别动作 → 产物字段 → 推翻条件` 落进话术设计；不作人物扮演或引语。

- 双方立场对撞但能安全协商时，可用“利益整合”镜头，把诉求背后的时间、质量、资源与风险写清，寻找新增变量；存在威胁、报复或不可协商底线时停止整合，转边界/冲突专科。
- 对方用职位或“规定”要求行动时，可用“角色—责任—强制”镜头，核对指令、授权、裁量和后果承担；不得把组织命令自动写成用户承诺。

启用镜头时，产物至少增加 `对方立场/核心利益`、`用户边界`、`决定人`、`可选动作`、`推翻/升级信号` 中与本题有关的字段。

## 流程

1. 判断对象关系、沟通渠道、目标、风险、已发生事实和不能承诺的内容。
2. 先写最短可发送版本，避免解释过度和情绪审判。
3. 需要时提供中性、温和、坚定三个强度；变化必须真实，不只换同义词。
4. 给发送时机、可能回复和一句后续接法；请求需要后续判断时，同时写明回复点/截止与合理等待窗口。原沟通未约定回复点时，先给低风险确认句，建立回复点和无法按时回复时的反馈方式。
5. 明确区分“已生成话术”“已发送”“对方已回应”；后两项未发生时不得暗示沟通完成。
6. 涉冲突、向上、多人利益或边界风险时，只处理本轮表达并标出专科边界。

## 模式与条件分支

1. **澄清**：双方对事实、词义或责任理解不同；先问可核对问题，不在消息里判责。
2. **请求/催办**：给动作、用途、截止、依赖、接收渠道、对方回应权限、回复点/截止、等待窗口和无法完成时的回复选项；对方无权承诺时找决定人。尚未约定回复点时，先建立低风险确认点。
3. **拒绝/取舍**：写可承担范围、不能承担部分、替代和需要有权者决定的取舍；不承诺“尽量全部”。
4. **反馈/修复**：用具体行为—影响—期望—复核；道歉只承担有证据的本人责任，不接受虚构过错。
5. **坏消息/风险**：尽早给事实、影响、已做动作、选项与最晚决定点，不用委婉语隐藏严重性。
6. **高风险沟通**：存在威胁、骚扰、报复或重大合规风险时，不把私聊写成默认路径；只生成安全留痕、支持与正式渠道草案。
7. **反复无效**：进入接口/权限复查须同时满足五项条件：请求保持一致且可核对、接收渠道已确认可用、对方有权回应、回复时点/截止已经明确、约定等待窗口已经结束。满足后查 M02/M05/M07/M11，并给改接口、找决定人或升级的条件。催办次数只记录沟通轨迹，不能单独触发升级。缺少回复点时，先发低风险确认，约定合理回复点和无法按时回复时的反馈方式；到点前继续等待或做可逆准备。若新证据显示消息未送达、渠道失效、对方无权回应、截止不合理或风险升高，立即重估并停止原升级路径；获得明确决定、承诺、拒绝或有效转交后停止催办。

## 动作与产物字段

- `表达任务卡`：对象、关系/权力、接收渠道、目标、事实、用户边界、对方可决定事项、回复点/截止、等待窗口、风险。
- `最短可发送版`：只含足以支持动作的信息；需要时附中性/温和/坚定版。
- `承诺账`：谁承诺什么、完成证据、截止、依赖、回复点、等待窗口、确认状态；不得替他人填“已确认”。
- `回应树`：同意、拒绝、模糊、无回应、反击五类真实分支及下一句话、重估条件和停止条件。
- `无回应判定卡`：同一请求标识、送达证据、接收渠道、对方回应权限、回复点/截止、等待窗口、当前时点、催办次数（仅作证据）、重估条件、停止条件。
- `发送授权点`：仅生成、待用户审核、用户已发送、对方已回应四种状态分开记录。

## 微型例

- 正例：“今天可先交 A；若 B 也要今天完成，请你确认 A 延至周三或指定协助人。我等你在 15:00 前选一个。”它留下真实取舍和决定人。
- 反例：“没问题，我尽量都做完。”它掩盖容量边界，并承诺了用户无法确认的结果。
- 无回应例：项目负责人已在双方确认可用的项目群收到同一请求，并约定周三 15:00 前回复；等待窗口结束后仍无答复，才检查是否要改接口、找决定人或升级。此前催办两次只进入沟通轨迹。若原消息只有“有空看一下”，先发送“请确认能否在周三 15:00 前回复；若本事项由其他人决定，也请告知负责人”，再按新约定观察。
- 边界例：对方有过威胁或上报后不利动作时，不建议“约个咖啡把误会说开”。先保留原始记录、确认用户安全与可用渠道；本专科只写必要的低暴露回复。

## 验证、失败与翻转

- **发送前**：事实可核对、请求由对方有权回应、用户确实能履行承诺、敏感信息最小化。
- **发送后**：只用对方原意回应判断，不把已读、表情、沉默当同意；记录送达证据、接收渠道、对方回应权限、约定回复点/截止、等待窗口及是否兑现。
- **成功信号**：获得明确决定、承诺、信息、边界确认或安全退出本轮对话中的一种。
- **失败信号**：对方继续模糊、标准移动、用户被迫承担新成本，或五项无回应条件均成立且等待窗口结束后仍无答复，或风险上升。未约定回复点属于信息缺口，不能据此判定接口失效。
- **翻转与停止条件**：消息未送达、渠道失效、对方无权回应、截止不合理或风险升高时，撤回原升级判断并重估；对方回应暴露新权限/利益时重写；换话术无效且五项条件成立时从 P/R 转 F/I；出现可信威胁时停止协商；获得明确决定、承诺、拒绝或有效转交后停止催办；原画像预测失败时撤回定制。

## 输出与回流

输出 `对象/渠道/目标`、`已知事实`、`最短可发送版`、`强度变体（需要时）`、`发送时机`、`回复点/截止与等待窗口`、`回应分支`、`无回应判定卡（适用时）`、`不能承诺内容`、`镜头链（如启用）`、`升级信号`。

本轮只可声明“话术和回应分支已完成”。发送后记录对方真实回应、是否作出决定及下一动作；若现实回应否定了对方利益、权限或风险假设，撤回相应定制，重新写话术或转专科。

回流写 `原表达假设/模式 → 实际发送版本与渠道/送达证据 → 回复点/截止与等待窗口 → 对方原意回应 → 承诺是否兑现 → 用户侧变化 → 保留/推翻的归因 → 下一反馈点`。未经用户明确授权不得代发、不得把关系变化或承诺兑现写成已发生。

## 禁止

不伪造权威、不暗示不存在的共识、不用“情商”掩盖权责、不承诺用户无法兑现的事。
