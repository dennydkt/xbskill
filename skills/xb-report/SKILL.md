# xb-report：工作报告

直调时先读取 `../xbskill/references/contracts.md` 与 `../xbskill/references/resolution-standard.md`；任何文件缺失时报告精确路径并停止，不得凭记忆补造。报告结论依赖外部专科材料时，再读取 `../xbskill/references/knowledge-source-protocol.md`。

报告合并数据、技术、演示或多人材料，或涉及冲突来源、敏感信息、并发编辑和重复周期时，读取 `../xbskill/references/task-domain-patterns.md`；单次个人简短总结不加载。

## 任务定义

报告是“某一时点、对某一受众、可追溯的工作状态与决定接口”。它不是聊天摘要，也不是活动清单。报告至少要让受众分清：

```text
目标是什么 → 现实结果到哪 → 证据是什么 → 偏差和风险是什么
→ 已作出什么决定 → 需要谁做什么 → 下一次何时更新
```

生成一份忠实报告的 Question 可以本轮解决；项目进展、风险控制和管理决定仍取决于现实行动。

## 核心判断模型：目标—结果—证据—决定

| 层 | 必答问题 | 禁止替代 |
|---|---|---|
| 目标 | 本周期承诺了什么结果，口径和范围是什么？ | 用长期愿景代替周期承诺 |
| 结果 | 现实中已完成、采用或改变了什么？ | 用投入、会议、稿件或计划代替 |
| 证据 | 哪个来源、日期、版本和坐标支持？ | 用“已推进”“基本完成”代替 |
| 偏差 | 与目标差多少，原因置信度和影响是什么？ | 只报百分比不报基线 |
| 决定 | 已批准/拒绝/调整什么，谁有权？ | 把建议写成决定 |
| 请求 | 受众需要决定、执行或知情什么？ | “请领导指导” |
| 反馈 | 什么事件更新状态或推翻结论？ | 报告发布后状态永久不变 |

报告强度不能超过最弱证据。新材料不会自动覆盖旧结论；必须说明修正、替代或并存关系。

## 来源与证据账

优先读取用户指定材料；若用户要求汇总 xbskill 历史，则读取项目 `memory/xbskill/` 中与当前范围匹配的快照。路径不存在或没有适用材料时，报告精确缺口并停止依赖部分，不跨目录猜私人文件、不从聊天记忆补进展。

每条重要内容标记：

- `事实`：材料可定位；
- `用户确认`：用户本轮明确提供；
- `推断`：给依据与置信度；
- `决定`：给决定人、日期和适用范围；
- `计划`：未来动作，不进入已完成；
- `待确认/已失效`：说明缺口或被什么替代。

材料冲突按共用冲突账处理。面向领导/团队的报告默认排除个人心理支持、健康、边界冲突和去留考虑；只有用户明确指定受众与披露内容后才写入，且仍最小必要披露。

## 信号词典

| 材料说法 | 必须还原 | 常见误写 |
|---|---|---|
| “完成/上线” | 完成了文件、部署、验收还是实际采用 | 统一写“已完成” |
| “完成 80%” | 分母、权重、剩余关键路径 | 把主观进度当客观测量 |
| “持续推进” | 本期新增的可观察变化 | 用动词掩盖无结果 |
| “风险可控” | 概率、影响、控制、责任人和触发阈值 | 没出事就叫可控 |
| “领导认可” | 谁、何时、认可事实/方向/预算哪一项 | 把口头兴趣写成批准 |
| “按计划” | 哪个版本计划、里程碑和证据 | 计划已变但沿用绿灯 |
| “同比增长” | 基线、口径、可比范围和原因 | 从增长直接推成功机制 |
| “下周完成” | 依赖、容量、决定权和验收者 | 把意愿写成承诺 |

## 报告模式

### A. 周报/月报

结构：`本期结论 → 目标与结果 → 偏差/风险 → 已作决定 → 下期动作 → 需要支持`。只列改变状态的事项；重复例行活动可汇总为运行指标。

### B. 项目状态报告

结构：`范围/里程碑 → 当前状态及证据 → 关键路径 → 依赖 → 风险/问题 → 变更与决定 → 请求`。状态颜色必须绑定明确阈值，不凭汇报者情绪。

### C. 管理层更新

先写一句结论和 1–3 个需要知情/决定项；细节进入证据表或附录。说清成本由谁承担、延迟影响和不做选项，不用信息量压迫批准。

### D. 事故/异常报告

结构：`影响与当前状态 → 时间线 → 已知/未知 → 临时控制 → 暂定原因 → 恢复/验证 → 防复发`。取证未完时不写确定根因，不为“有结论”提前归责。

### E. 专题分析报告

结构：`问题与决定用途 → 范围/方法 → 发现 → 证据与限制 → 选项 → 建议 → 验证`。分析方法服务问题，不把图表数量当报告深度。

### F. 个人复盘报告

结构：`目标 → 结果 → 预期/实际差异 → 机制 → 能力/负荷/边界变化 → 下一不可绕过动作`。只在用户本人使用的版本保留敏感体验，不自动复制到组织版。

## 执行流程

1. 明确受众、用途、周期、截止、格式、保密范围和必须回答的问题。
2. 列出允许读取的来源、版本与缺口；读取一手材料，不从摘要记忆回填。
3. 建证据账：目标及 G 层级、H 能级、Question/Problem、产物、现实变化、量化证据、SourceLock/claim、人物/公司变化、偏差、决定、风险、动作和请求。
4. 统一对象、口径和状态词；活动与结果、建议与决定、产物与采用分列。
5. 按报告模式组织；同一事实只保留一次主位置，其他章节用引用而非复制改写。
6. 处理演进：保留旧结论及“已修正/已替代/仍并存”，不要只留下最新叙事。
7. 最小披露：按受众删除不必要的个人与公司敏感信息；删除本身不能掩盖重大决策风险。
8. 为每个重要主张挂路径/日期/条件；为请求写决定人、截止与无决定影响。
9. 输出成稿、来源索引、未解决项和 1–3 个用户复核点；外发仍需独立授权。

## 产物字段

```text
报告类型、受众、用途、周期与版本：
一句结论：
目标/承诺及口径：
现实结果及证据：
活动（仅解释结果时）：
偏差、原因置信度与影响：
已作决定：决定人 / 日期 / 范围
风险：触发 / 概率或置信度 / 影响 / 控制 / 负责人
下一动作：主体 / 截止 / 验收 / 依赖
需要受众知情或决定：
结论演进与已失效项：
未解决 / 待确认：
来源索引与适用的锁：
敏感披露边界：
下一更新事件：
用户复核点：
```

## 案例校准

**正例**：周报写“本周完成接口联调并通过 18/20 个验收样本；2 个跨月样本因旧口径未通过，当前不能进入正式发布。口径负责人需在周三前确认方案 A/B，否则上线延后一周。”产物、验证、缺口、决定人和影响都可见。

**反例**：“本周围绕重点任务开展多轮沟通，持续推进方案优化，整体进度 80%，风险总体可控。”没有分母、证据、结果、责任和触发阈值，读者不能据此行动。

**边界例**：项目只有一次保存快照。可以忠实生成单次状态卡；若用户要“趋势报告”，必须说明没有第二时点，不能从一份材料虚构演进。

## 验证、失败与翻转

- 任何“完成/通过/批准”找不到证据和适用范围：降级状态或列待确认。
- 报告总量与明细、不同章节或前后版本矛盾：先修冲突，不靠措辞模糊。
- 受众读后不能说出需要自己做什么：报告的决定接口失败。
- 新材料推翻旧结论：保留演进并更新影响，不能静默覆盖历史。
- 报告成稿但关键来源缺失：可交付非依赖部分，整体标“部分/无法验证”。
- 报告已生成但尚未外发或现实决定未发生：只判报告产物完成。

## 结果回流

报告发布后记录实际追问、决定、误解、被采用动作和未被使用章节；下一周期核对承诺是否兑现、风险是否触发、旧结论是否仍有效。反复追问的缺口进入默认字段，长期无人使用的章节退出。报告净收益看决定速度、返工、风险暴露和用户维护负荷，不以页数和“看起来完整”衡量。
