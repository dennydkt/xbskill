# xb-people：工作人格系统

直调契约：还必须读取 `../xbskill/references/contracts.md` 与 `../xbskill/references/resolution-standard.md`；缺失时停止，不得把画像假设写成人格事实。

读取 `../xbskill/references/agency-model.md`、`../xbskill/references/context-protocol.md`、`../xbskill/references/intellectual-capabilities.md` 与 [references/people-profile-template.md](references/people-profile-template.md)。任一文件缺失时报告精确路径并停止本专科，不得凭记忆补造理论镜头。

完整读取 `../xbskill/references/people-domain-patterns.md`，用原子事件、四层归因和权力账防止把流程/制度表现固化成人格；文件缺失时报告路径并停止本专科，不得凭记忆补造模式。简单任务不应为了建立画像而触发本专科。

## 定义

工作人格是**人在特定组织情境中的稳定行为倾向**，不是当前情绪/精力状态、MBTI 标签、临床诊断或道德评价。画像必须能被新行为推翻。

## 触发与核心因果模型

画像只在“同一人物未来的可观察行为会改变协作动作”时有价值。行为暂定模型：

`行为 = 当前状态 P + 与特定对象的关系 R + 工作接口/流程 F + 权力激励/实际规则 I + 尚未知因素`

因此“某人喜欢细节”必须写成“在何类任务、对谁、何时、基于几次事件”；换情境后不能外推。画像优先预测最有效输入、决定方式、边界和失败信号，不解释一个人的本质或动机。

| 归因层 | 画像中的含义 | 可翻转证据 |
|---|---|---|
| 个人 P | 相对稳定的工作偏好/技能，或当下容量状态 | 休息、训练、换任务后行为改变 |
| 关系 R | 只在特定互赖/信任关系出现 | 换协作者或修复承诺后改变 |
| 流程 F | 接口、信息、验收迫使行为如此 | 换流程后多人同时改变 |
| 制度 I | 权力、评价、激励和实际规则塑造行为 | 规则/领导/奖惩改变后模式改变 |

## 三类画像

- **自己**：优势、盲区、压力反应、能量规律、偏好、承诺边界。
- **同事**：交付可靠性、协作偏好、利益与顾虑、冲突方式、最佳接口。
- **领导**：注意力、决策标准、风险敏感点、授权方式、评价逻辑、汇报偏好。

## 七个观察轴

信息（摘要↔细节）、决策（速度↔证据）、控制（授权↔跟进）、风险（试验↔稳妥）、沟通（直接↔铺垫）、冲突（面对↔回避）、驱动（结果/专业/影响/稳定/认可）。轴不是二选一；记录情境变化。

## 可观察信号词典

| 信号 | 可生成的暂定假设 | 必须同时记录 |
|---|---|---|
| 多次先问结论，再决定是否看附件 | 特定场景偏摘要输入 | 任务类型、时间压力、例外事件 |
| 同类决定总要原始数据/案例 | 证据门槛较高 | 决策风险、谁提供数据、等待成本 |
| 口头授权后频繁追问细节 | 控制偏好或授权不清均可能 | 授权范围、出错史、制度要求 |
| 在会上沉默、会后一对一提出异议 | 渠道安全/沟通偏好候选 | 权力关系、其他对象、真实后果 |
| 承诺在有书面 owner/日期时更稳定 | 接口假设增强 | 无书面时对照、重复次数 |
| 压力期突然变得急促/回避 | 当前状态信号 | 基线行为、持续时间；不写成长期人格 |
| 对上与对下标准明显不同 | 权力/激励候选 | 具体对照、角色、规则与成本 |
| “他就是控制型/我就是拖延” | 标签无证据 | 原子事件、条件、结果、反例 |
| 领导评价偏好与实际晋升案例一致/冲突 | 人物偏好或制度候选 | 决定链、样本日期；规则交 `xb-company` |

## 流程

1. 确认对象、关系、要解决的真实协作任务和可使用材料。
2. 先建事件账：原话/行为、情境、当时状态、权力关系、结果、重复次数；把解释与事实分开。
3. 在七轴上只填写有证据项；每项标“观察/推断/待验证”和置信度。
4. 分角色补充：自己看触发器与盲区；同事看接口与互赖；领导看决策与评价。
5. 生成 1–3 个可验证假设和低风险试探，不根据单次行为定型。
6. 输出协作策略：信息颗粒度、沟通时机、请求方式、留痕、边界、失败信号。
7. 用户授权后才保存到项目 `memory/xbskill/context/people/{self|colleague|leader}-<slug>.md`；默认最小化敏感信息。

## 模式与条件分支

1. **自己画像**：分开稳定偏好、当前状态、能力证据和外部约束；疲惫/焦虑不自动写入长期档案。
2. **同事画像**：聚焦交付接口、互赖、承诺与边界；不推断私人生活、病理或道德。
3. **领导画像**：聚焦注意、决定、授权、评价、风险和实际权力；偏好不能升级成公司规则。
4. **首次建档**：少于两个可对照事件时只建“假设卡”，不填满七轴；明确最小试探和过期日。
5. **反复协作失败**：用 P/R/F/I 并列，不默认通过更懂对方来适配；M02/M07/M10/M11 出现时转边界/公司/冲突。
6. **更新/推翻**：新事件与画像预测不符时先降置信度、记录情境差异；连续反证则撤销而非解释成“隐藏人格”。
7. **安全边界**：明确威胁、骚扰、报复或强制违规不作为画像实验；直接进入保护路径。

## 动作与产物字段

- `事件账`：日期/情境、原话/动作、当时状态、角色权力、规则、结果、重复、来源。
- `四层解释`：P/R/F/I 的支持、反证、未知、置信度。
- `七轴假设`：观察轴、场景范围、证据、反例、预测、有效期、推翻信号。
- `角色专属接口`：有效输入、时机/渠道、请求、留痕、边界、不得适配项。
- `低风险试探`：只改一个变量、预测、窗口、现实结果、回滚/停止。
- `保存授权`：不保存/待确认/已授权；对象使用代号，去掉无关敏感信息。

## 人物归因闸

缺少具体冲突、原话/行为或报复证据时，不先倾向“对方性格”“用户沟通差”或“组织压制”。先取得一个最小事件账：`原话/行为 + 情境 + 当时状态 + 角色与权力 + 可用规则/渠道 + 结果 + 重复次数`，再保留可相互推翻的分支。

- **沟通假设**：同一请求换信息颗粒度、时机或确认方式后，结果稳定改善。
- **边界/权力假设**：请求已清楚，但责任、资源或拒绝成本持续单向落在低权力方。
- **环境假设**：同类模式跨人物、跨周期出现，并受正式/实际规则或激励维持。

单一事件通常只能生成假设；明确威胁、骚扰或违法要求可直接触发安全边界，不等待重复。

## 理论镜头落地

每题最多选择 1–2 个镜头。

| 理论镜头 | 具体动作 | 写入产物字段 | 失败信号 |
|---|---|---|---|
| 玛丽·帕克·福列特：power-over / power-with 与整合冲突 | 分开各方立场、利益、控制资源与承担风险；辨认当前是支配、平均妥协还是共同解决，设计一个不牺牲基本边界的低风险整合试探。 | 参与方、权力/资源、表面立场、核心利益、共同问题、支配风险、整合选项、剩余损失、升级条件 | 低权力方无法安全表达仍要求共创；所谓整合仍单向转嫁成本；把骚扰包装成双方矛盾 |
| 阿伦特：角色—责任—强制 | 拆开提出、决定、授权、执行、复核和承担后果的角色，核对当事人的知情、裁量与真实强制；为每人只归入有证据的责任。 | 角色、指令、授权来源、知情范围、实际裁量、可预见影响、责任归属、异议/升级渠道、强制证据 | “只是执行”被当成免责证据；忽略实际报复风险；用职位或人格标签替代责任链事实 |

晋升相关画像只记录该人物在提名、评价、决定、复核链中的可证实角色，不把其偏好自动升级为公司晋升规则；规则判断回到 `xb-company`。

**微型正例**：一次冲突中，同事要求用户当晚补数据。事件账显示同事负责汇总但无权改截止，领导掌握优先级，双方都缺同一上游口径。先把共同问题定义为“口径决定缺位”，请领导确认口径和优先级；若确认后冲突消失，支持接口假设而非人格定型。

**微型反例**：用户只说“同事难沟通”，就给同事贴控制型标签；或用户说“不敢提问题”，就断言领导会报复。没有行为、情境、权力和结果证据时，画像尚未成立。

**边界例**：领导一次当众羞辱用户。即使样本只有一次，也不要求用户通过反复试探来确认“领导风格”；先记录事实和安全/报复风险。是否写入画像及是否升级由用户决定，法律或临床性质不由本专科认定。

## 验证、失败与翻转

- **画像成立**：至少有跨时间的同类事件与一个对照/反例，且假设能预测一次低风险协作结果；否则仅为待验证。
- **有效验证**：按画像调整一个接口后，目标行为在约定窗口稳定改变；一次碰巧成功只降低不确定性。
- **失败信号**：画像解释任何结果、反证被合理化、用户需要持续牺牲边界、流程/制度换后人物“性格”集体变化。
- **翻转条件**：新行为与预测冲突；状态恢复后行为不同；换关系/流程/规则后改变；真实权力链推翻原角色假设。
- **停止条件**：画像不会改变下一动作、需要侵犯隐私、或适配将增加安全/尊严风险时，不建或删除无用字段。

## 禁止

不诊断人格障碍；不把一次压力反应、职级、性别、年龄当人格证据；不记录无关隐私；不利用画像操控或欺骗；不把“领导喜欢”冒充公司正式规则；不因适配某人而降低安全、尊严和用户选择。

## 输出

协作目标、事实事件、条件分支、行为画像、置信度、角色—责任—强制链、有效接口、禁区、试探方案、失败信号、何时推翻画像。

空画像模板、事件问题清单和试探话术只算脚手架；没有事件证据时不得声称人物模式已确认，没有现实试探结果时不得声称协作问题已解决。

每次现实互动后回流 `原假设/场景/置信度 → 实际输入与对方行为 → 结果 → P/R/F/I 更新 → 保留/降级/推翻 → 下次接口`。只有用户明确授权才落盘；更新必须保留旧判断与新证据，不静默覆写历史。
