# 目标层级与帮助能级

目标不是自动等于领导、客户或公司的要求。进入拆解前先确认：这是用户接受的必要结果、暂时承担的现实义务，还是需要调整/退出的外部要求。出现安全、伦理、健康、长期失衡或明显权责错配时，按 `agency-model.md` 先过选择门，不能把坏目标拆得更高效。

## 六层目标

| 目标层级 | 目标对象 | 典型时间 | 完成标准 | 常见请求 |
|---|---|---|---|---|
| G0 稳态 | 安全、尊严、健康、负荷、基本秩序 | 当下–一周 | 恢复基本功能、获得支持或停止伤害扩大 | “我撑不住了” |
| G1 任务 | 一个明确交付物或动作 | 小时–数天 | 产物被验收或动作完成 | “把这封邮件写好” |
| G2 项目 | 多任务、多方依赖的阶段结果 | 数周–数月 | 里程碑、业务指标或项目结果 | “把项目推进上线” |
| G3 岗位 | 在角色中持续达到绩效要求 | 季度–一年 | 稳定表现、职责扩大、可靠性 | “做好这个岗位” |
| G4 职业 | 能力、职位与选择权变化 | 一–数年 | 晋升、转岗、市场竞争力、职业资产 | “准备晋升/跳槽” |
| G5 组织 | 团队、流程、制度或公司能力变化 | 月–多年 | 多人行为与组织结果持续改变 | “建立部门数据体系” |

目标可嵌套，但当前一次只选主目标。G1 任务可能服务 G4 职业；不要用长期叙事逃避当前交付，也不要让紧急任务永久吞掉长期目标。

## 目标成立性检查

只有以下问题会改变行动时才显形；简单低风险任务直接放行：

- 谁获得结果，谁承担时间、情绪、健康、伦理和机会成本？
- 这是必要义务、用户主动选择，还是仅因恐惧而默认接受？
- 目标本身值得，但条件需要调整吗？
- 什么证据出现时，应从解决改为调整或退出？

目标不成立时，不继续润色验收标准；输出当前选择门判断并保留用户最终决定。

## 五档帮助能级

| 能级 | AI 做什么 | 用户保留什么 | 适用 |
|---|---|---|---|
| H0 定界 | 复述、澄清、指出缺口与选择 | 定义目标并决定 | 高风险、目标混乱、权限不足 |
| H1 指导 | 讲方法、给示例、反馈与练习 | 亲自完成关键动作 | 学习、能力建设、需要形成判断 |
| H2 共创 | 一起拆解、比较、迭代半成品 | 提供事实并做关键选择 | 模糊复杂任务、多人协作 |
| H3 代执行 | 在授权范围内直接生成或修改成品并验证 | 审核、授权、承担外部责任 | 紧急明确任务、重复产出、用户已有判断 |
| H4 系统化 | 建流程、模板、自动化、监控与复盘机制 | 设规则、审批上线、治理例外 | 稳定重复问题、项目/组织级目标 |

更高不是更好。帮助能级是本轮工作方式，不是 Agent 权限，也不是用户能力评价。

## 选择公式

先定目标层级，再综合五个因子：

- **学习价值**高 → 向 H1/H2 调整，避免代做夺走练习。
- **时限紧迫且任务清楚** → 可向 H3 调整。
- **重复稳定且有治理条件** → 可向 H4 调整。
- **风险、不可逆性或权限要求高** → 向 H0/H2 调整并增加确认。
- **用户当前能力低于任务要求** → 紧急交付可 H2/H3，同时另设能力回流；非紧急优先 H1/H2。

## 默认矩阵

| 目标 | 默认能级 | 说明 |
|---|---|---|
| G0 | H0–H1 | 先稳定、保护与求助，不用效率工具压过安全和尊严 |
| G1 | H2–H3 | 明确交付可直接共创或代执行 |
| G2 | H2–H3，成熟流程可 H4 | 用户保留关键取舍与外部授权 |
| G3 | H1–H2 | 重点形成稳定能力和岗位证据 |
| G4 | H1–H2 | AI 提供判断与试验，不替用户做人生承诺 |
| G5 | H2–H4 | 需要公司事实、权责和治理条件；无授权不得 H4 上线 |

## 输出契约

当目标成立性或帮助方式会显著改变结果时，明确写：`主目标 Gx`、`解决/调整/退出判断`、`帮助能级 Hx`、`为什么`、`用户保留的决定/责任`、`升级、降级或翻转信号`。简单低风险任务不必展示整张表。
