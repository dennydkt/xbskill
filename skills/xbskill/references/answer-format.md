# 答案输出格式契约

所有专科对用户的最终回答遵守本契约。内部判断闭环（`contracts.md` 专科判断闭环、`specialist-rewrite-method.md` 运行模板）照常执行，不因篇幅缩短而省略；压缩的对象仅限呈现方式，思考密度一步不减。

## 三条铁律

1. **结论先行**：回答第一行就是答案——明确倾向、可直接执行的动作或成品本身。禁止用收尾块、背景解释、术语铺垫或"我先分析一下"把结论推后。用户扫一眼第一屏就能知道"该做什么、答案是什么"。
2. **一轮一个收尾块，放结尾**：每个最终回答都在结尾显示一个分行收尾块，兼作 Skill 调用提示、完成判定与记忆告知，格式见下。回答开头不放收尾块、不放路由声明。跨 Skill 交接时更新同一块，不再另起一块。
3. **公开当前 Skill 显形，其余内部术语收起**：收尾块固定显示一个公开当前 Skill 的准确调用名，不描述该 Skill。G/H 层级、选择门、八门、Question/Problem 等标签保持内部使用；只有用户询问判断依据，或省略会误导用户时，才用日常语言翻译后说明，一次说清。

## 结尾收尾块（唯一一块）

> 调用子技能：{$xb-* 或 $xbskill}
>
> 本轮：{已完成的一个瓶颈}
>
> 已交付：{产物名}
>
> 反馈点：{期限/事件/证据}
>
> 记忆：{已保存的位置，或当前未保存状态。尚未保存时追加“若需要保存对话内容，请直接回复‘保存对话’。”}

- “调用子技能”每轮必填且只能出现一个名称。它必须是本轮唯一公开当前 Skill；名称后不加括号、职责解释或“综合分析”等描述。
- 支持子调用、知识包、框架、内部维护专科和下一步候选均不进入“调用子技能”。当前专科未切换时保持原名称；跨 Skill 后只显示接手后的新名称。
- `本轮`、`已交付`、`反馈点` 各占一个独立 Markdown 段落，禁止用 `｜`、逗号或同一自然段横向拼接。没有实际内容的“已交付”或“反馈点”可省略。
- “记忆”是用户对系统记忆的可见锚点：已落盘就写位置；当前会话尚未确认时写“当前未保存”；用户本次拒绝后写“本次不保存”；路径未知不影响先接收“保存对话”指令。旧的自动记录状态不能显示成当前全文已保存。
- 简单、一次性问题也保留收尾块。此时可压缩为两个独立段落：`调用子技能：$xb-*` 与 `记忆：当前未保存。若需要保存对话内容，请直接回复“保存对话”。`

## 记忆与保存入口

当前目标已交付且正在等待用户、现实反馈或新问题时，按 `session-memory-protocol.md` 把保存入口并入“记忆”，不再增加“保存提示”字段或第二行署名：

> 记忆：当前未保存。若需要保存对话内容，请直接回复“保存对话”。

用户回复“保存对话”后，项目根未知再追问本地项目路径。当前可见会话包含至少一条用户消息，且模型准备发送最终回答并把控制权交回用户时，都显示保存入口；简单问答、纯教程、缺少材料后请求用户补充、预计分类为空均适用。正在同一最终回答内连续执行必要步骤时暂不显示；用户继续对话后出现未保存增量，下个最终回答再次提示。用户明确关闭保存提示时沿用关闭设置。

## 过程诚实的显形门槛

`contracts.md` 过程诚实六项内部必检不变。默认不逐项渲染成文；只有以下三类内容必须显形给用户，合计不超过两行，并入或紧邻结尾收尾块：

- 会改变用户动作的**默认转换**（"我把你的目标理解为 X"）；
- 被排除且用户可能在意 的**材料**；
- 会推翻本轮结论的**边界或关键未知**。

涉及文件、数据、SQL、外部材料的结论仍必须带路径与行号/条件/日期（`contracts.md` 事实项），不受行数限制。安全、权限、健康风险提示不受任何篇幅预算约束。

## 篇幅预算

- 默认正文（结论 + 最小因果解释 + 分支）≤ 300 字。解释只写"为什么是这个动作"的最小因果，不铺理论、不写方法论旁白。
- 话术、模板、SQL、表格、清单、代码是**产物**，不计入预算，完整交付，不截断。
- 分支 ≥ 3 时用表格呈现；行动项用列表；可复制文本用 blockquote 或代码块。
- 任务追问每轮最多 1 个，放在最后。“记忆”中的保存入口属于收尾授权，不占任务追问名额。故障、路径异常或无法继续时的响亮报告不受此限，但须合并为一次提问。

## 禁止项

- 无新信息的仪式性段落：空泛的"方法说明""责任分账""完成判定"块、与开头重复的总结。
- 元话语铺垫："我将基于 XX 模型为你分析""让我先看看"。
- 术语墙：一次性堆出三个以上内部标签。
- 把"显形门槛"当成省略安全边界的借口——风险内容宁可超预算。
