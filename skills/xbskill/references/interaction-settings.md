# 调用、保存提示与主入口介绍

本协议优先于旧版自然语言触发、常驻回流和无条件保存提示。所有公开入口先过本协议，再读取具体任务材料或执行专科。配置入口为 `../../xb-config/SKILL.md`；缺失时报出精确路径并停止依赖它的初始化。

规则优先次序：明确拒绝 → 即时安全支持 → 用户主动保存 → 普通配置与业务调用。联合模式以 `coexistence-protocol.md` 为准；下文初始化限制仅约束普通业务，安全支持与本次主动保存可先执行。

## 配置与作用域

调用强度 `call_intensity` 必须由用户选择 `high / medium / low`；保存提示 `save_prompt` 必须由用户选择 `high / low`。两项均无默认值、无预选值。只有两项都有用户明确选择，初始化才完成。用户只选一项时保留已选项，仅补问另一项；沉默、继续发任务、安装成功与“随便”均不能补作选择。

持久配置位于明确项目根下的 `.xbskill/config.json`，由 `xb-config` 的配置工具校验与写入。配置独立于 `memory/xbskill/`；保存配置只写两项偏好及其验证所需信息，不保存会话或用户画像。项目根无法确定时只在当前会话保留明确选择，并告知“本次选择仅在当前会话生效”；用户要求跨会话生效时再确定项目路径。禁止在工具私有目录、模型环境变量或公开套件中写个人配置。

“保存低怎么选”“调用中是什么意思”等疑问只触发解释与答疑入口；档位名本身不能作为已选或写入授权。用户明确选择后才暂存或持久化。

无配置表示 `unconfigured`。旧的 `session_save_prompt`、`auto_checkpoint`、档案存在或已安装旧版均不能推定新偏好。配置损坏、版本不支持、权限不足必须报错，禁止回退高档或新建空配置。用户选择配置模式后显示绝对路径并落盘回读；实际写入失败时明确当前生效范围。

## 调用门：依序判定

1. 用户明确拒绝/退出 XB，或只在引文、代码、文件内容中提到 XB：返回 `bypass`，不插入配置、收尾或保存提示。仅点名外部 Skill（如 `/code-review`）且未同时明确要求 XB 参与时也返回 `bypass`。明确联合调用、控制指令与后续续接先按 [联合调用协议](coexistence-protocol.md) 判断；用户主动“保存对话”独立进入 `xb-save`，不受保存提示档位与业务初始化限制。指定的外部技能不可用时报出缺口，禁止用相似 XB 技能补位。
2. 用户明确请求配置 XB：进入 `xb-config`，配置技能自身不受“尚未配置”的循环阻塞。
3. 用户明确调用 XB 主入口或子技能而尚未完成配置：保留任务与点名的子技能，先进入 `../../xb-config/references/spirit-sync.md` 的三阶段逐轮问答，结束或跳过后展示原介绍、基于回答的建议并让用户自行选择两项；完成后回到原任务。未配置且仅被宿主自然语言匹配到时退出业务调用，等待用户明确开启 XB，不抢占普通任务。
4. 已配置，用户明确调用 XB 或在当前已授权 XB 任务内自然续问：按该任务继续。明确调用已经表达使用意图，中档无需再次确认同一调用。明确点名的子技能优先于相似词匹配，主入口才按瓶颈选择子技能。
5. 新任务仅由自然语言匹配：`high` 高强度识别相关工作任务并直接执行；`medium` 使用相同识别范围，只提出一次具体调用建议，收到本任务明确同意前禁止专科求解、读取任务文件或产生副作用；`low` 返回 `bypass`，用户明确开启前禁止业务调用和主动邀请。
6. 中档确认绑定当前任务与拟调用子技能。新任务、换专科、拒绝、撤销或切换其他工具使确认失效；用户只修改同一任务的参数可继续。反复推荐、以沉默视为同意、先做后问均禁止。

初始化完成时，若已有因缺配置暂停的明确 XB 任务，立即恢复已保留的任务和材料，不要求用户再调用一次。单独进入配置且无原任务时只交付配置结果。初始化和中档等待确认阶段只显示当前必需选择或确认句，尚未进入业务专科时不声称已调用该专科；初始化未完成无保存提示，中档确认回复仅按已选保存档位显示一次提示。

自然语言“高强度”只扩大相关任务的识别范围；无关闲聊与简单常识不自动套入职场流程。高档和中档均保留安全、外发、删除及其他实质动作的授权边界。

这是 Skill 运行协议，需由宿主 Agent 在加载与派发阶段遵守；它不控制宿主在模型选择前展示哪些描述，也不构成宿主级强制沙箱。验证时分开记录描述被发现、技能被读取与实际专科执行。不能用配置工具的单元测试通过宣称 Codex/Claude 的实际派发已通过。

## 首次安装与精神同步协调

首次安装完成后的交互回调，或首次明确开启且尚无配置时，进入 `$xb-config` 的 `../../xb-config/references/spirit-sync.md`。先做思维、沟通与信息同步三阶段，每阶段约十轮，一轮一个问题；结束后才展示下方原介绍和两项配置。首次状态未知时只启动一次并允许跳过，不依据记忆目录猜测已学完。已有配置者不自动重学，主动说“精神同步协调”可进入任一阶段。主动保存、即时安全支持、急事与用户直接配置优先。

三阶段问答时长由回答决定，450 字符上限仅约束下方最终配置介绍与选项，不能据此压缩为一次三十题。

## 原有主入口介绍：同步后露出

三阶段同步完成或跳过后，或已配置用户每次明确调用 `xbskill` 主入口时，展示以下四项常规介绍，首次同步第三阶段可选评估，跳过同步时可保留该评估行。自然语言续问、专科内部回流和支持调用不重复展示。已有任务时先简短展示，再推进任务；只有未完成的必选配置会暂停普通求解；即时安全支持先按 `work-state-intake.md` 进行。直接进入 `xb-config` 的首次初始化也展示这份介绍，一轮只展示一次。

<!-- intro-start -->
> **xbskill 是主入口**。
>
> **问法举例：**“$xbskill 工作卡住了”。
>
> **xb-save：**“保存对话”可建本体记忆。换对话、Kimi、DeepSeek 时提供可读记忆文件。
>
> **子 Skill 说明书：**“查看说明书”。
>
> **可选评估：**回复“评估工作状态”，可跳过。

记忆价值与衔接条件按 `memory-portability.md` 执行：拟人化记忆指有来源、时间和关系的结构化记忆；未来调用按任务读取相关历史。首次只展示上述短版，用户问保存、恢复或换产品时再展开步骤。未授权不写会话；提示低档保留完整保存能力。记忆文件未提供、不可读或仅提供部分时显式说明缺口，禁止承诺跨产品自动同步。

展示后等待用户反馈。只有用户明确索要说明书/完整菜单，才读取 `user-guide.md` 的专科速查及所请求技能的 `SKILL.md`，说明用途、输入、产物和边界。用户回复配置档位或直接发任务，不算同意查看说明书；禁止默认展开目录、子技能说明或逐个介绍。介绍中的示例问法不得作为用户实际任务执行。

初始化接在四项常规介绍及首次可选评估之后：必须读取 `../../xb-config/references/configuration-guide.md`，只展示默认短版；介绍各一句，五个档位各一句解释行为，完整初始化含收尾不超过 450 字符（实际路径除外）。详细案例、适用偏好和边界等用户追问再展开，禁止把完整指南倾倒给用户；本轮已有偏好证据时可按 `spirit-sync.md` 给配置建议，但所有选项均无预选；指南缺失时报精确路径，停止初始化展示。

请用户分别选择两项，不预选；建议依据本轮回答并与最终选择分开；可给填写格式“调用强度：__；保存提示：__”。两项选择与当前配置值仍为 high / medium / low 和 high / low；补充解释不改变档位行为。已配置用户显式调用主入口仍展示四项介绍，随后继续任务，不重复初始化。用户只想查看说明书时可以先交付说明，业务求解仍等两项选齐。

无交互复制、克隆或第三方安装器未提供对话回调时，文件安装本身无法展示上述对话；README 明确要求安装后调用主入口完成首次介绍与必选配置。禁止声称尚未发生的对话已经完成。

## 保存提示门

- 只有已经进入 XB 的最终回复适用保存提示。`save_prompt=high` 时每次最终回复显示一次保存入口，含简单问答、澄清、教程和配置完成回复；工具进度不重复显示。
- `save_prompt=low` 时不主动询问、不展示“当前未保存”或保存邀请；用户主动要求保存后才进入 `xb-save`。
- 未完成两项选择时不推定任何保存提示档位；初始化问题不追加保存提示。
- 高档只授权提示频率。当前会话保存、敏感长期检索、联网、外发和 Git 仍分别按原协议取得授权。旧记忆的相关读取规则保持原契约。
- 真实保存成功或失败时，无论档位都报告结果；当轮不重复保存邀请，不把提示写成自动保存承诺。
- 用户说“以后别问保存”明确对应低档，“每次都提醒我保存”明确对应高档；由 `xb-config` 更新当前项目的这项，保留已有调用强度。未初始化时仍补问缺项。
- 当轮已经主动要求保存时，无论档位都只报告结果或待补缺项，禁止重复邀请“保存对话”；等待路径、接受部分保存或修复失败时也适用。即时安全支持暂停主动保存邀请，优先于高档每轮提醒。

## 验证与翻转

正常样本：调用中、保存低的用户接受对本任务使用 `xb-review` 的建议后开始审查，同任务修订继续，无保存邀请。反例：调用高、保存高的用户输入 `/code-review` 时 XB 退出，不出现 XB 标记或保存提示。边界：只回复“调用低”时仅问保存提示；配置 JSON 损坏时明确报错，不启动求解。

验收记录必须区分六种组合、未配置、损坏配置、外部技能、拒绝/撤销、自然续问、查看说明书的明确反馈和保存实际回执。任一越权调用或主动低档保存提示发生，本轮调用/提示门视为失败，保留原始回答后修改对应分支再复测。

## 首次沟通的可选评估

介绍中的评估邀请只在首次同步的第三阶段或跳过同步后的短介绍中展示一次，后续显式主入口介绍省去该行；首次状态未知也只邀请一次，不推断安装日期。用户选择“评估工作状态 / 工作状态评估 / 状态评估”后读取 `work-state-intake.md`，保留待恢复任务，逐轮单问。跳过、拒绝、沉默或直接发任务均不启动问卷，不影响配置与业务能力。可先接收选择，普通评估在两项配置选齐后开始；出现安全或严重失能信号时先支持，配置延后。评估记录只在当前会话暂存，不新增配置字段。该文件缺失时报精确路径并停止评估；当下安全支持仍可继续。

## 所有阶段的使用疑问

每轮按 `community-support.md` 识别疑惑、报错或不理解的语义。未配置阶段也可先答疑并提供官网社群版入口；尊重拒绝并对同一疑问去重，不把购买作为继续条件。
