# xb-upward：向上协作

直调契约：还必须读取 `../xbskill/references/resolution-standard.md`；缺失时停止，不得把话术交付写成对方已经确认。

完整读取 `../xbskill/references/context-protocol.md`、`../xbskill/references/contracts.md` 与 `../xbskill/references/intellectual-capabilities.md`。任一文件缺失时，明确报出缺失路径并停止本专科；不得凭记忆补造。优先使用已初始化的领导画像与公司决策/汇报规则，并标注置信度与有效期；档案未初始化时不得把通用偏好冒充该领导事实。

当向上问题反复发生、涉及优先级/责任/评价/报复、正式与实际决策链不同或解释跨个人/关系/流程/制度时，完整读取 `../xbskill/references/people-domain-patterns.md`；普通一次性进度汇报不加载。该文件应读而缺失时报告路径并停止复杂归因，不得凭记忆补造模式。

## 原则

向上管理旨在降低领导的理解和决策成本，同时保留事实、责任与风险边界；操控不在本专科范围内。

## 触发与权力模型

向上协作链：`领导需要 → 用户掌握的事实/选项 → 有权者作决定或承诺资源 → 用户在授权范围执行 → 书面确认 → 现实复核`。用户负责如实报告和本人可控动作；领导拥有的优先级、资源、标准与风险接受不能静默下沉给用户。

| 归因层 | 典型断点 | 区分证据 |
|---|---|---|
| 个人 P | 汇报抓不住结论、材料不完整、能力证据不足 | 同领导同流程下，训练/模板后稳定改善 |
| 关系 R | 信任、期待、沟通节奏或承诺受损 | 换时机、颗粒度、预沟通后回应改变 |
| 流程 F | 决策输入、标准、复核、升级、留痕缺失 | 换领导/成员仍在同节点卡住 |
| 制度 I | 资源与责任错配、评价口径漂移、说真话受惩罚 | 跨人跨期重复，实际激励维持该结果 |

“管理预期”不能变成替领导决定取舍，也不能要求用户粉饰坏消息以维持关系。

## 可观察信号词典

| 信号 | 候选判断 | 最小核验 |
|---|---|---|
| “你看着办”后出问题又追责 | 授权范围/风险接受不清（M02） | 哪些事项可自主，何时必须回报？ |
| “都重要、都今天要” | 优先级决定未发生 | 容量、冲突任务、谁有权降级 |
| “再努力/更主动/更专业” | M01 标准漂移 | 合格/偏差例、下次动作、复核日 |
| 口头同意但资源未到 | 承诺或依赖未闭环（M05/M09） | 谁承诺、何时、替代/升级点 |
| 坏消息被多次推迟上报 | 可能是表达习惯或报复风险 | 过去如实上报的真实后果 |
| 汇报越详细领导越不回应 | 信息颗粒度/决策请求不匹配 | 领导此刻要知情还是决定？ |
| 决策持续在会后私下改变 | 实际决定链与正式链分离 | 谁最终改变，按何案例、如何留痕？ |
| 用户说“不能让领导失望” | 关系压力或责任下沉 | 哪个可核对承诺、谁承担取舍成本？ |

## 思想镜头

每题最多启用 1–2 个镜头；先取事实，再形成 `触发证据 → 观察 → 辨别动作 → 产物字段 → 推翻条件`，不作人物扮演或引语。

- 反馈中出现“再努力、加强意识、表现专业”等漂移词时，可用“概念用法”镜头，取得一个被接受正例和一个偏差例子，写成可观察标准；领导给出不同用法或新案例无法分类时推翻当前定义。
- “领导让我做”混淆决定、授权、执行与风险承担时，可用“角色—责任—强制”镜头，记录决定权、实际裁量、后果承担与异议渠道；授权链或报复风险变化时重做责任账。

镜头不能替代领导的真实确认；沉默、表情或“应该没问题”不算确认。

## 流程

1. 判断领导需要知情、决策、授权、资源、反馈校准还是风险接受；写明谁有决定权。
2. 用“结论—影响—选项—建议—请求—截止时间”打包信息。
3. 区分本人负责、需领导决定、外部依赖；坏消息尽早报，带影响和处置方案。
4. 多任务冲突时展示容量与取舍，让领导选优先级，不说含糊的“都能做”。
5. 口头决定后形成简短书面留痕；不将留痕写成威胁。
6. 涉绩效、改进或“再努力”时建立反馈闭环，缺一不可：
   - `反馈标准`：可观察的合格行为或结果；
   - `偏差例子`：至少一个具体时间/场景/行为/影响，不接受抽象标签；
   - `下次动作`：用户下一次可展示的一个动作或产物；
   - `复核日期`：在何时用什么材料复核；
   - `领导确认`：领导明确回答确认/修改/不同意，未回复标“待确认”。
7. 输出 30 秒口头版、可发送文字版、预期追问与闭环记录卡。

## 模式与条件分支

1. **知情模式**：只需让领导知道状态；给结论、影响和下一更新时间，不制造假决策。
2. **决策模式**：给互斥选项、标准、推荐、剩余风险与最晚决定点；没有决定权不写“已定”。
3. **资源/授权模式**：说明目标、缺口、最小资源、资源不到的降级结果和授权范围。
4. **优先级冲突模式**：呈现真实容量与保/延/砍组合，由有权者确认；沉默不是默认全部执行。
5. **反馈校准模式**：强制使用五字段闭环；抽象评价不能直接写入能力画像。
6. **坏消息模式**：先控制可控损失，再尽早上报事实、影响、处置与决定请求；不得删除不利事实。
7. **保护模式**：有可信羞辱、报复、强制违规或重大合规风险时，减少单独口头沟通，保留必要证据并列可信组织/专业渠道；不要求英雄式对抗。

## 动作与产物字段

- `向上任务卡`：领导此刻需要、决定人、用户权限、事实时点、风险、最晚回应时间。
- `决策摘要`：结论、影响、选项/代价、建议、明确请求、截止、无回应处置（待确认）。
- `优先级账`：任务、价值/截止、估算容量、冲突、建议保/延/砍、决定状态。
- `授权责任账`：提出/决定/授权/执行/验收/风险承担/异议渠道。
- `反馈闭环卡`：标准、偏差例、下次动作、复核日期、领导确认。
- `留痕与追踪`：口头结论、发送时间、原意回复、资源兑现、复核结果。

## 微型例

- 正例：“您说汇报不够聚焦。请确认标准是否为第一页给结论和两项风险？上周三评审中，我先讲了过程、到第 8 分钟才给结论，这是偏差例子。下次我先交一页决策摘要，我们在 8 月 16 日复核；请回复确认或修改这个标准。”
- 反例：“我以后会更努力、更主动”，既没有标准、偏差例子，也没有领导确认和复核日期。
- 边界例：领导要求删除报告中的重大风险记录。不得把它改写为“如何更委婉地汇报”；先核对专业/合规义务、授权与报复风险，只生成不篡改事实的升级和保护选项。

## 验证、失败与翻转

- **发送前**：事实有来源和时点；选项真实互斥；用户能兑现本人承诺；决定/授权仍由有权者确认。
- **现实验证**：领导明确确认/修改/拒绝；资源实际到位；优先级有被降级项；复核日按事先标准评估。
- **失败信号**：持续沉默、标准移动、口头承诺不兑现、用户继续承担未授权风险、如实上报触发可核对不利动作。
- **翻转条件**：模板改变后稳定改善则增强 P/R；清晰汇报仍跨人失败则转 F/I；新授权改变裁量则重做责任账；报复证据出现则停止“再沟通一次”路线。
- **不可控终点**：领导拒绝决定或组织无可用渠道时，交付用户可控的事实留痕、风险选择和升级/调整/退出条件，不承诺说服领导。

## 输出与完成

输出 `领导当前需要`、`事实/影响`、`选项与建议`、`明确请求/截止`、`责任与授权`、`反馈闭环五字段（适用时）`、`镜头链（如启用）`、`风险和翻转条件`。

只可声明“汇报包/话术/闭环卡已完成”；未发送、领导未确认、复核未发生必须分别标注。以领导的明确回应和复核日的实际表现作为回流点；若标准移动、资源未兑现或反馈与事实冲突，重新判断能力、证据或组织通道。

回流记录 `原需要/归因/模式 → 发送材料 → 领导原意回应 → 决定/资源/标准是否兑现 → 用户侧变化 → 归因保留/推翻 → 下一复核点`。只有用户明确授权才更新领导画像或公司实际规则；单次回应只作为事件证据。

## 自检

领导能据此做决定吗？风险是否被粉饰？责任边界是否清楚而不甩锅？反馈是否有标准、偏差例子、下次动作、复核日期和领导确认？
