# 反甩锅回复包

生成现场回复、书面确认或正式复核材料时读取。所有模板都要用本轮事实替换方括号；未知保持未知，禁止补造姓名、标准、权限和组织程序。

## 零、上下文命中说明

```text
上下文状态：matched / no_match / not_initialized / not_checked
实际读取的本地坐标、日期与有效期：
与本轮材料的冲突：
它改变的观察、动作或产物字段：
明确排除的旧材料及原因：
```

`no_match`、`not_initialized` 或 `not_checked` 时，用一行告知用户当前回复只使用其本轮材料和 xbskill 公开规则，随后直接交付当前可用内容。不得要求用户先初始化记忆或补齐人物、公司档案。`matched` 时只注入能改变当前动作的最小片段，并保留来源、日期和冲突。

## 一、归责主张卡

```text
归责原话：
证据形态：原始记录 / 用户转述 / 他人转述
说话者、渠道、受众、时间：
当前要求：解释 / 认错 / 签字 / 补救 / 接受评价或处分 / 其他
主张涉及的任务、结果和时间范围：
对方给出的证据与适用标准：
用户当前状态：同意部分 / 有争议 / 无法验证
最晚回应时间与不回应后果：
```

## 二、事实—证据—控制账

| 时间 | 原子事件 | 角色动作 | 来源 | 证据状态 | 用户当时知道什么 | 用户实际能做什么 | 异议或缺口 |
|---|---|---|---|---|---|---|---|

证据状态只使用：`原始记录`、`当事人陈述`、`合理推断`、`有争议`、`缺证`、`被拒绝访问`。一条材料可以支持某项事实，仍不足以自动推出责任结论。

### 材料覆盖对照

多人链路、材料主要集中在最近经手人或单一系统、关键记录分散或访问受限时填写：

```text
统一比较的责任主张、时间范围与适用标准：
当前可访问材料覆盖的角色、环节与时段：
各角色材料位置与记录密度：
缺失时段、分散位置与被拒绝访问记录：
可见性偏差候选及其依据：
按相同时间范围、相同标准请求的对照材料：
补齐前的状态：待核
```

材料集中只能说明当前看见了什么，不能自动推出最近经手人责任更大，也不能推给材料较少的角色。对照材料应覆盖提出、决定、授权、执行、采用、验收和复核；无法安全取得时记录缺口、请求人和复核者。

## 三、责任分区

| 分区 | 写入规则 | 典型句式 |
|---|---|---|
| 本人确认承担 | 有记录、有职责、有当时控制，用户确认事实 | “我确认 [具体动作/遗漏] 属于我负责的部分，我将于 [时间] 完成 [补救]。” |
| 当前有争议 | 双方对事实、因果、标准或控制有不同材料 | “关于 [具体主张]，我目前有异议，依据是 [坐标]；请把 [对方依据] 一并列入复核。” |
| 材料不足 | 关键记录、权限或时间段缺失 | “现有材料还缺 [记录]，当前只能标记待核，无法据此确认 [具体责任结论]。” |
| 有权者确认 | 取舍、验收、处分或制度判断超出用户权限 | “请由 [角色/程序] 依据 [标准] 在 [时间] 前确认，并保留异议与采用理由。” |

## 四、三级回复

### L0：现场短句

> 我愿意对我实际负责的部分逐项说明。关于“[归责原话]”，请先把具体事实、依据和适用标准写清；我会按时间线补充本人当时掌握的信息、能够控制的动作和已经做过的处理，再请有权者确认。

### L1：群聊、邮件或会议纪要确认

> 为避免后续记录出现偏差，我把目前能确认的内容列清：
>
> 1. 我确认承担的部分是：[事实＋来源＋补救]。
> 2. 对“[具体归责主张]”我暂不确认，现有记录显示：[事实坐标]。
> 3. 当前还缺：[材料／权限／时间段]；我已于 [时间] 向 [角色] 提出补证请求。
> 4. 请依据 [适用标准]，由 [有权角色] 在 [时间] 前逐项确认。我的异议和后续补充请保留在同一记录中。

### L2：正式复核包摘要

```text
提交目的：核对事实、责任主张与适用标准
本人确认承担：
争议主张及对方依据：
事件时间线与证据坐标：
当时信息、实际控制与已做动作：
缺失／被拒绝访问材料：
事实或标准异议：
已完成补救：
请求复核事项：
复核者、程序与时限：
版本、附件和保密范围：
```

正式材料保留机器辅助生成说明。用户逐项核对前维持“草案”；收到、知悉、事实确认和责任承认分别表述。

## 五、回应树

| 对方回应 | 下一动作 |
|---|---|
| 给出具体证据和稳定标准 | 逐项核对，更新本人承担、争议和补救 |
| 继续说“反正就是你负责” | 请其明确具体动作、因果依据、适用标准和决定权限；宽泛结论保持未确认 |
| 要求立刻认错或签字 | 先确认事实和文字范围；高风险后果下暂停签署并寻求适当支持 |
| 改用新的标准或时间范围 | 把原标准、新标准、生效时间和变更者分开记录 |
| 只引用最近经手人或单一系统的记录 | 要求在同一时间范围、同一标准下补齐决定、授权、采用、验收和复核材料；补齐前维持待核 |
| 拒绝记录用户异议 | 另发简短书面确认，保留送达证据，并判断复核或保护路径 |
| 同意交给复核者 | 确认材料范围、复核标准、时限、回避和结果记录方式 |
| 出现威胁、羞辱或可核对不利动作 | 停止普通辩论，最小化暴露，保留证据并转保护路径 |

## 六、发送前检查

- 原话、事实、时间、来源和转述状态准确；
- 用户只承担有证据支持且本人确认的部分；
- 其他角色只描述动作、权限和记录，没有替其定责；
- 未知、争议和被拒绝访问材料保持可见；
- 多人链路已经检查材料覆盖；可见性偏差仅标候选，并提出同一时段、同一标准的最小对照请求；
- 请求交给有权回应的人，时限真实；
- 内容不包含威胁、羞辱、造假、无授权材料或无依据法律结论；
- 当前状态标明“草案／待用户审核／已发送／已回应”。
- 产物状态与现实状态已经分账；草案已交付不能写成回复已发送、签署已暂停、异议已送达或组织已受理；
- 首次回答缺少现实反馈时，现实状态只填写“未执行”或“未验证”。

## 七、状态分账

```text
产物状态：已起草 / 已交付用户 / 已由用户核对
现实状态：未执行 / 未验证 / 用户已确认 / 原始记录已确认
允许升级现实状态的反馈或证据：
仍然没有发生或没有验证的动作：
```

只有用户反馈或原始记录可以升级现实状态。建议、草案、模拟回复和待办清单都属于产物，不能单独证明现实动作已经发生。

## 八、现实反馈卡

```text
发送或提交时间、渠道与版本：
送达证据：
对方原意回应：
新增材料：
共同记录是否保留异议：
适用标准与复核者是否确认：
本人承担／争议／缺证的变化：
是否出现标准移动、强迫签署或风险升级：
用户侧变化：
下一反馈点或停止条件：
```

### 高风险首次回答回归断言

用户尚未反馈现实动作时，首次回答不得声称签署已经暂停、异议已经发送或固定、组织已经受理、记录已经更正。此时可声明“已准备暂停签署所需的低暴露书面异议草案”，并把签署状态、送达状态和受理状态分别标为“未执行”或“未验证”。
