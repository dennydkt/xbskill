# xb-meeting：让会议产生决定

直调契约：还必须读取 `../xbskill/references/resolution-standard.md`；缺失时停止，不得把会议设计完成写成会议已经产生决定。

完整读取 `../xbskill/references/contracts.md` 与 `../xbskill/references/intellectual-capabilities.md`。任一文件缺失时，明确报出缺失路径并停止本专科；不得凭记忆补造规则。

当会议反复无结论、原因横跨个人/关系/流程/制度、涉及多方权力或需要决定升级时，完整读取 `../xbskill/references/people-domain-patterns.md`，使用其中原子事件、四层归因、权力账与模式编号；简单的一次性议程或纪要不加载。该文件应读而缺失时报告精确路径并停止复杂诊断，不得凭记忆补造。

## 触发与核心模型

本专科处理“是否需要同步交互，以及如何让同步交互产生有权确认的结果”。纯粹润色会前通知转 `xb-talk`；长文汇报转 `xb-report`；会议里已暴露的冲突可先留事实，再转 `xb-conflict`。

会议价值链：`值得同步的问题 → 必要信息到场 → 有权者作决定/形成明确学习 → 有容量者确认行动 → 现实追踪`。任一环断裂，增加会议时长通常无效。

| 归因层 | 会议中的断点 | 判别证据 |
|---|---|---|
| 个人 P | 未预读、表达或主持能力不足 | 同一流程下差异稳定，给预读/练习后结果改变 |
| 关系 R | 不信任、承诺破裂、权力差使人无法表达 | 换对象/一对一预沟通后分歧质量改变 |
| 流程 F | 目的、材料、决定方式、owner 或追踪缺失 | 换人仍在相同会议节点失败 |
| 制度 I | 决策者不在场、授权与责任错配、激励鼓励拖延 | 跨会议重复，且只能由更高权力或规则改变 |

不要用“参会者不积极”吸收 F/I 断点；也不要因一次冷场就断言组织压制。

## 可观察信号词典

| 信号 | 候选判断 | 最小核验 |
|---|---|---|
| “先聊聊、同步一下”但无预期输出 | 目的未定，可能可异步 | 结束时必须新增什么信息、决定或承诺？ |
| “大家一致同意”但无逐人确认 | 沉默被冒充共识 | 谁明确说了什么，反对意见如何记录？ |
| 决策者缺席或“回头请示” | 决策会没有决定权 | 谁最终决定，能否会前授权或改为信息会？ |
| 多人负责、无人确认 | M04 所有权扩散 | 唯一 owner、验收者、截止与容量 |
| 相同议题连续进入下次会议 | 决定方式/依赖/激励断裂 | 上次卡在哪个字段，谁有权解除？ |
| 行动项只有姓名和日期 | 验收或依赖缺失 | 完成证据、输入、确认状态、升级点 |
| 低权力方不发言 | 信息不足或安全问题均可能 | 私下是否能表达、是否有报复/羞辱证据？ |

“没人负责”不能直接贴 M04。先按顺序保留四个竞争解释：`决定尚未形成`、`行动项不可原子化/验收不清`、`关键依赖或容量未到位`、`方向已定但所有权扩散`。只有方向和动作已经可认领、输入基本就绪，仍无人本人确认时，才把 M04 列为当前较强候选；否则产物应先补决定、拆行动或补依赖，而不是催人认领一个尚不存在的任务。

## 权限先分路

先确认用户是：

- **组织者/主持人**：可设计议程、邀请决策者、控制节奏、确认决定并发送纪要；若其中某项没有授权，单独标出。
- **普通参会者**：只能准备材料、提出议题/选项、询问谁决定、确认自己的承诺并保留记录；不得替主持人定议程、替决策者宣布结论或替他人分配任务。需要会务动作时，输出一段发给组织者的请求。

权限不明且会改变动作时，只问“你是本次组织者/主持人，还是普通参会者？”

## 思想镜头

每题最多启用 1–2 个镜头，且只在事实与权限确认后使用：

- 立场对撞但仍有安全协作空间时，用“利益整合”镜头：记录 `各方立场/利益`、`权力/资源`、`共同问题`、`整合方案`、`剩余损失`、`同意/升级条件`。一方可惩罚另一方、核心权利冲突或成本继续单向转嫁时推翻整合路线，不强迫共识。
- “领导要求”“大家同意”掩盖决定权时，用“角色—责任—强制”镜头：记录 `提出/决定/授权/执行/复核人`、`实际裁量`、`异议渠道`、`强制证据`。授权链或报复风险变化时重做分工。

不得人物扮演、伪造引语或用人物名替代证据。启用镜头时写明 `触发证据 → 观察 → 辨别动作 → 产物字段 → 推翻条件`。

## 流程

1. 先判断会议目的：通知、收集、讨论、决策或协作；能异步完成就给异步替代，并写明什么反馈会重新需要开会。
2. 会前写清预期输出、决策者、必须参会者、预读、议题时限和不讨论项。
3. 组织者/主持人按“事实同步—分歧—选项—决定—行动”编排议程，每项标负责人、时间盒和决定方式；普通参会者按同一结构准备自己的发言卡，并把议程建议交给组织者确认。
4. 会中分开记录事实、观点、反对意见、决定依据、未决问题和停车场；沉默、未发言或未反对都不等于同意。
5. 会后纪要首先列决定和行动项：唯一负责人、截止时间、完成标准、依赖、本人确认状态。普通参会者只确认自己承担的事项，并将其他记录标为“待负责人/主持人确认”。
6. 对未决定事项写决定人、升级人和最晚决定日；约定一次现实追踪点，记录决定是否执行及实际阻碍。

## 模式与条件分支

1. **通知/收集模式**：不需要同步澄清或权衡时，改为异步；产物是信息页、反馈字段、截止与重新开会条件。
2. **决策模式**：选项、标准和有权者齐全时开会；产物是决策包、反对意见、决定依据与决定账。
3. **探索模式**：信息不足但同步探索有价值时，明确只产出假设、待验证项和下一取证动作，不伪装成决策会。
4. **承诺模式**：方向已定但执行卡住时，核对容量、依赖、唯一 owner 与验收；无权替他人确认。
5. **高权力差模式**：可信报复、骚扰或强制风险出现时，不要求公开发言换取“充分讨论”；保存必要事实并设计安全的私下/正式渠道。
6. **普通参会者模式**：只生成发言卡、确认本人承诺、请求有权者补齐字段；不越权主持或宣布结论。

普通参会者遇到“聊完没人负责”时，发言卡先问三件事：`是否已经作出可执行决定`、`行动是否能由一个人认领并验收`、`依赖/容量是否允许现在承诺`；之后才请求主持人确认 owner。当前归因及替代解释要随纪要回流，不把一次字段缺失固化为所有权模式。

选中共用模式时，在产物标明如 `M01/M02/M04/M05` 及支持/反证；没有满足成立信号时不得贴模式名。

## 动作与产物字段

- **会议必要性卡**：问题、需要同步的原因、异步替代、重开条件。
- **决策包**：事实、选项、标准、推荐、剩余分歧、决定人、最晚决定日。
- **议程**：议题、目的、负责人、时间盒、所需材料、决定方式、不讨论项。
- **决定账**：决定、依据、反对意见、决定者、授权范围、有效期/重审触发。
- **行动账**：唯一 owner、完成证据、截止、依赖、容量确认、升级人、确认状态。
- **追踪卡**：计划状态、现实结果、阻碍层级、是否重开决定。

## 微型例

- 组织者正例：“由王经理在会上决定 A/B；李负责数据，周五前提交，验收为三项指标齐全。”
- 普通参会者正例：“我建议把 A/B 选择放入议程；请确认谁有最终决定权。我只确认自己周五提交数据。”
- 反例：普通参会者在纪要中写“大家一致同意”，并给未确认的人分配任务。
- 边界例：项目复盘会上低权力成员担心指出安全隐患会被报复。不得用“让每个人轮流发言”处理；先提供可保密的事实入口、核对正式渠道，并把会议目标限制为不暴露个人的风险处置。

## 验证、失败与翻转

- **会前验证**：必要材料已到、决定人/授权已确认、普通参会者的权限边界清楚；缺一项就降级会议类型或标未知。
- **会后验证**：决定者明确确认；行动 owner 逐项确认；追踪日出现完成证据、真实阻碍或重新决定。
- **失败信号**：议题反复回流、行动无人认领、标准继续移动、决定者持续回避、用户被要求吸收新增成本。
- **翻转条件**：异步出现新分歧则重开同步；owner 已明确但仍卡住则转 M05/容量/权限；决定执行后结果相反则重开选项与标准；可信报复证据出现则停止共识路线。
- **停止条件**：用户无权限且组织者拒绝补齐关键字段时，只交付参会者可控动作和升级选项，不伪称会议可被用户单方面修复。

## 输出与完成

输出 `用户角色/权限`、`会议目的与必要性`、`议程或参会发言卡`、`决定权账`、`分歧/剩余损失`、`决定与行动项`、`确认状态`、`追踪日期`、`镜头链（如启用）`。

只可声明“议程/发言卡/纪要草稿已完成”或“已根据会议记录整理决定”；会议尚未举行、负责人尚未确认或行动尚未验证时必须明写。最终以决策者确认、负责人确认和追踪日的现实进展回流，不以文档写完代表会议产生了结果。

回流至少记录 `原断点层级/模式 → 实际会议类型 → 决定者与 owner 的真实确认 → 追踪结果 → 保留/推翻的归因 → 下一动作`。未经用户授权，不把敏感发言或健康/去留信息写进长期档案。

## 自检

会议结束后，没参会的人能否知道决定了什么、为什么、谁有权决定、谁确认承担、何时用现实结果复核？
