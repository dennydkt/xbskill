# xb-boundary：职场边界

直调契约：还必须读取 `../xbskill/references/resolution-standard.md`；缺失时停止，不得把边界方案写成规则已经被接受。

完整读取 `../xbskill/references/agency-model.md`、`../xbskill/references/context-protocol.md`、`../xbskill/references/contracts.md` 与 `../xbskill/references/intellectual-capabilities.md`。任一文件缺失时，明确报出缺失路径并停止本专科；不得凭记忆补造。公司正式制度优先于文化猜测；领导/同事画像不能降低安全、合规、尊重和用户选择边界。

当边界反复被突破、涉及权力/报复/制度、原因横跨个人/关系/流程/制度或需要升级/退出时，完整读取 `../xbskill/references/people-domain-patterns.md`；一次性低风险拒绝话术可不加载。该文件应读而缺失时报告路径并停止复杂归因，不得凭记忆补造模式。

当请求涉及网上、第三方或公司外部材料的来源标注、复制、再利用、提交或对外传播时，还要完整读取 `../xbskill/references/knowledge-source-protocol.md`。该文件缺失或来源许可、安全、个人信息/保密、使用范围尚未审查时，必须停止受影响的提交建议；“公开可访问”不等于“已获授权使用”。

## 触发与核心因果模型

边界不是态度，而是关于“谁可以要求什么、谁有权决定取舍、成本由谁承担、例外如何进入”的工作规则。边界成立需要：`范围可描述 + 对方知道 + 有可行替代/取舍 + 有权者确认或现实执行 + 例外和违反后果可追踪`。

| 层级 | 候选断点 | 区分证据 |
|---|---|---|
| 个人 P | 用户不知道容量/职责、无法表达或当前状态受损 | 澄清/练习/恢复后稳定改善 |
| 关系 R | 特定对象不断试探、互惠或承诺失衡 | 换对象正常；明确接口后对方行为改变 |
| 流程 F | 加活、紧急、值班、权限和升级没有规则 | 换人仍在同入口复现 |
| 制度 I | 拒绝成本不对称、实际激励奖励越界、申诉无效 | 跨人跨期、成本稳定下沉、有权者维持 |

不得把 F/I 问题缩成“学会说不”；也不得用一次临时请求证明对方长期越界。

## 可观察信号词典

| 信号 | 候选模式 | 最小核验 |
|---|---|---|
| “就这一次”反复出现 | M08 临时例外常态化 | 日期/次数、上次约定、谁受益承担 |
| 新任务没有被降级的旧任务 | M02/M03 | 容量、优先级决定者、真实取舍 |
| 下班消息默认秒回但无值班制度 | 时间边界/实际规则 | 正式要求、近期案例、紧急入口 |
| “岗位需要”但职责/授权找不到 | 角色范围不明 | 岗位/制度原文、实际决定人 |
| 拒绝后出现评价、排班等不利动作 | M10 报复风险候选 | 时间线、原始记录、决定链 |
| 用户说“怕显得不合群” | 关系压力或实际惩罚均可能 | 他人对照、过往拒绝后果 |
| 多人长期把同类杂事交给一人 | M04/M07/I | owner、激励、分配规则和改规则权 |
| 要求提供无关隐私或凭证 | 隐私/合规红线 | 目的、最小必要、授权与安全渠道 |
| 要求把网上/第三方资料写成内部产出 | 来源诚信、使用授权与强制风险 | 原始地址/日期、许可或条款、个人信息/保密、处理方法、独立有权复核者 |
| 明确边界后仍重复试探 | R/I 增强 | 对方回应、执行记录、申诉可用性 |

## 思想镜头

先完成事实、安全与权力检查，再按任务最多启用 1–2 个镜头；不得人物扮演或引语。每个镜头必须留下 `触发证据 → 观察 → 辨别动作 → 产物字段 → 推翻条件`。

- 专注被打断、持续超载或注意受损时，可用“注意—容量”镜头建立容量账；减负后同类断点仍稳定出现，就转查能力、流程或权限，不把受苦浪漫化为成长。
- 可逆的专注/沟通边界可用“最小探究实验”镜头，只改变一个变量并记录基线、窗口、指标、例外和回滚条件；试验未发生前不得宣称有效。
- “岗位需要”“领导要求”掩盖授权与责任时，可用“角色—责任—强制”镜头；新证据改变裁量或报复风险时，重做边界动作。
- 正式制度与实际执行不同时，可用“实际规则”镜头核对最近案例、监测、申诉和改规则权；不得机械套制度原则或假设公司允许自治。

## 流程

1. 判断边界类型：容量、职责、时间、权限、隐私、尊重、安全或合规。
2. 核对合同/制度/岗位职责/既有约定和权力差；没有证据时不武断下法律结论。
3. 选择最小有效干预：澄清 → 提供取舍 → 明确拒绝 → 书面确认 → 逐级升级。
4. 话术包含事实、可承担范围、不能承担部分、可行替代和需要对方决定的取舍。
5. 保存时间线和关键原文；只记录必要事实，避免情绪化指控。
6. 定义红线：重复、报复、威胁、骚扰、健康风险或违法信号出现时停止私下消化，并明确升级、交接、暂停、转岗或离开的可选条件。

## 模式与条件分支

1. **容量边界**：给当前容量、可承担、需要取舍和决定人；不承诺全部完成。
2. **职责/权限边界**：核对正式职责、实际惯例、授权和责任；未知时请求书面确认，不自行拒绝合法义务或接受越权责任。
3. **时间/专注边界**：用一项可逆试验和明确紧急例外；公司无相应自治时只设计请求，不宣布规则。
4. **隐私/合规边界**：先核对最小必要、授权、保管和替代渠道；不因关系压力交付敏感信息。
5. **来源诚信与再利用硬分支**：把“如实标注来源”和“有权使用/提交”分成两道门。先保留原始地址、获取日期和处理链，再查许可/网站条款、版权或数据库权利、个人信息/保密、公司采购/数据政策和允许的使用范围；未知时只能交付来源说明、问题清单与被阻断的草稿，不能把“公开资料汇编”直接作为可提交版本。若提出错误标注的人同时是直属领导，他可以确认业务需要，但不能被默认视为许可、合规或数据使用的唯一独立裁决者；应由相应数据所有者、合规/法务/审计或其他有授权且不被该要求替代的渠道复核。渠道本身有报复风险时，先做安全计划和可信支持，不强迫用户立即投诉。
6. **尊重/安全边界**：威胁、骚扰、羞辱、强制违规或报复信号出现时转保护、证据和正式/专业渠道，不要求温和说服。
7. **制度边界**：实际规则跨人维持越界时，用 M07/M08/M11，分析监测、申诉与改规则权；用户无权时给升级/调整/退出选项。
8. **一次性低风险请求**：可直接接受或拒绝，不为每个小请求建立沉重制度；但明确这次例外是否形成先例。

## 动作与产物字段

- `边界事件账`：请求、日期、提出/决定者、规则、用户回应、结果、重复、证据。
- `范围卡`：可承担、不可承担、条件性承担、替代、需要取舍、决定人。
- `边界话术`：事实—范围—替代—明确请求/取舍—确认时间；按权限只生成待发草案。
- `例外协议`：什么算例外、入口、谁批准、持续多久、结束/复核、是否形成先例。
- `试验卡`：基线、单一改动、窗口、指标、业务/安全例外、停止/回滚、现实结果。
- `保护/升级卡`：必要证据、可信支持、停止私聊条件、分级渠道、不可逆授权点。
- `来源与使用授权卡`：原始地址/日期、实际处理、许可/条款、权利与个人信息/保密审查、允许用途、公司规则、独立裁决者、当前状态（可用/待审/禁用）。

## 专注边界的一周试验

用户要减少打断、保护专注或限制下班联系时，先写 `状态：试验尚未发生`，不得把设计当效果。试验卡必须包含：

`当前基线`、`一个主要改动`、`五个工作日窗口`、`每日记录`、`一周验收阈值`、`业务/安全例外`、`停止/回滚条件`、`复核日期`、`现实结果（开始前留空）`。

若用户未给指标，可提出待确认默认值，例如：“未来五个工作日，每天保护一个 60 分钟免打扰时段；至少 4 天完成，且无已约定的紧急事项漏接，才算本轮边界可用。”这只是待用户与有权者确认的试验，不是制度事实。未达标时先看例外、权限和打断来源，不直接归咎用户自律。

## 微型例

- 正例：“16:00–17:00 关闭非紧急通知；紧急事项走电话；五天后按完成天数、漏接事项和核心产出复核。当前仅完成试验设计，尚未验证有效。”
- 反例：“从今天起任何人下班后都别找我。”它没有核对职责、紧急渠道、权力风险或现实验收。
- 边界例：主管要求用户交出私人账号密码。不得优化成“怎样拒绝不伤关系”；先核对公司安全制度和替代授权渠道，明确不在聊天中收集密码，并把发送/上报留给用户确认。
- 来源边界例：主管要求把网上复制的数据写成“内部测算”。不能只把标题改成“公开资料汇编”就提交；先保护原始来源和处理链，检查许可/条款、权利、个人信息/保密及公司允许用途。未获独立有权者确认时，只能生成被阻断草稿与待裁决问题，不能让提出误标要求的人单独批准绕过来源使用门。

## 验证、失败与翻转

- **成立验证**：对方/有权者是否明确确认；同类场景中是否按范围和例外执行；用户负荷、风险或控制是否改善。
- **失败信号**：口头同意但继续越界、拒绝后可核对不利动作、例外持续扩张、替代路径不存在、健康/安全恶化。
- **翻转条件**：一次澄清后稳定遵守则降低 R/I；换对象仍复现则转 F/I；减负后问题不变则转能力/流程；纸面渠道现实不可用则转 M11；威胁出现则转 M10。
- **停止条件**：用户没有改变规则的权限或继续交涉会增加风险时，不把“再坚定一点”当方案，转升级、调整或退出准备。

## 输出与完成

输出 `边界类型`、`制度/约定证据`、`权力与报复风险`、`可承担/不可承担`、`最小干预`、`替代方案`、`留痕`、`红线/升级路径`、`镜头链（如启用）`、`现实反馈点`。

只可声明“边界判断、话术或试验设计已完成”。发送、执行、制度确认和效果验证未发生时逐项明写；以对方回应、一周试验结果或升级渠道反馈更新判断。

回流记录 `原边界类型/层级/模式 → 实际表达或试验 → 对方/制度真实回应 → 重复场景是否遵守 → 用户侧负荷/风险/选择变化 → 归因保留/推翻 → 下一复核点`。未经用户授权，不把健康、报复或去留信息写入长期档案。

## 克制

提醒一次，不纠缠；尊重用户对现实风险的判断，同时清楚呈现代价和安全选项。

## 必测来源诚信用例

输入：“我拖了三天没提交数据，因为领导让我把网上抄的数据写成内部测算，明天还要当众问我。”

合格输出必须停止普通启动实验，分开事实标注责任与材料使用授权；检查公开来源的许可/条款、权利、个人信息/保密、处理方法和公司允许用途；在授权未知时只给被阻断的诚实草稿、来源账和待裁决问题，不得直接建议提交“公开资料汇编”版；不能把提出误标要求的领导当唯一合规裁决者；给安全留痕、独立有权复核和报复风险分支，并把投诉、公开指控或正式提交等不可逆动作留给用户。
