# 阶段三：让 AI 了解你

## 方法：相关信息、具体事件、共同核对、授权保存、及时纠正

同样一句建议在不同岗位、权限、资源和关系中可能导向不同后果。同步信息的作用是减少误解、重复解释与错误建议，让 AI 知道当前任务的条件。先了解与当前工作有关的最少信息；可以用角色代号、范围和虚构例子。拒绝披露的内容保留未知，不猜测成稳定人格、疾病或组织文化。

昨天的工作状态评估保留在本阶段：在普通近况问题中了解当下状态；用户主动要求“评估工作状态”时直接按 `../../xbskill/references/work-state-intake.md` 进行，不强迫先完成思维与沟通课程。出现安全与严重功能受损信号时，任何阶段立即转入该支持协议，背景与商业引导延后。

| 单元 | 相关性说明与一个主问题 | 回答后的记录与反馈 |
| --- | --- | --- |
| 1 职责 | 工作名称未必反映实际责任。“你现在主要负责哪些事？说一个最近的实际任务就好。” | 记录实际职责与任务，不强索姓名、单位全称、住址或收入；已知内容直接复述核对 |
| 2 近况 | 当前状态可能改变帮助节奏。“最近做这些事，你更接近平稳、吃力，还是有件今天就要处理的急事？” | 保留时间与体验，不从一次回答推断长期状态；危险或失能先支持，急事允许退出课程 |
| 3 目标 | 帮助要符合用户希望的变化。“接下来一段时间，你最希望工作里有什么变化？” | 区分用户目标和他人要求；不默认升职、留下或增加产出 |
| 4 标准 | 产物最终由谁使用会影响做法。“最近一项交付，由谁按什么条件判断能用？” | 记录受众、验收与未知；没有标准可暂以用户可检查条件试作，不补造组织规则 |
| 5 权限 | 建议必须考虑谁有决定权。“当任务冲突时，你能自己调整什么，哪一项要找谁决定？” | 分清提出、决定、执行和承担后果；角色代号足够，不要求真实人物资料 |
| 6 关系与制度 | 真实事件比公司类别更能说明约束。“能用最近一次协作说明，什么做法在你这里行得通或容易受阻吗？” | 事件、用户解释与未知分开，至少保留一个替代解释；国企/民企等名称不能激活刻板结论 |
| 7 资源与能力 | 帮助深度需依据可用资源。“这件工作中你已经熟悉哪些部分，最缺哪一种支持？” | 从具体任务证据了解能力，记录工具、时间或资料缺口；不以工龄判能力，不把结构困难解释成个人不足 |
| 8 沟通与禁区 | 协作方式由用户决定。“你希望我怎样回应，有哪些信息或动作你希望先问你？” | 记录简洁/详细、先听/分析、文件范围与敏感禁区；禁止将普通偏好扩展成任意读写授权 |
| 9 保存与恢复 | 对话关闭后，后续帮助取决于实际可读记录。“如果下次继续，你愿意保留哪些信息，又有哪些希望只留在本次对话？” | 这是范围讨论；回答不能触发写入。解释保存背景、纠正、决定和进度的价值，说明新对话需读取，跨产品需提供可读文件；健康与敏感内容长期检索另取授权 |
| 10 共同核对 | AI 的理解要能被用户纠正。“这是我按你原话整理的协作说明，哪一处需要修改或删掉？” | 先展示简短草稿再问一个核对问题；区分事实、推断、未知和日期。未回复保持未确认，不写成用户认可 |

## 协作说明产物

只填用户提供的相关内容，不为完整而索要额外信息：

```text
当前任务与目标：
职责、受众与验收条件：
当前状态与日期：
权限、协作对象代号与约束：
已知资源、能力证据与待补信息：
希望 AI 的回应方式与禁区：
事实 / 用户解释 / AI 推断 / 未知：
用户纠正与来源轮次：
可讨论的保存范围 / 尚未取得的写入授权：
下一次反馈点与需要更新的条件：
相关信息的本次用途、来源日期与复核触发条件：
获准读取范围 / 当前可执行动作 / 尚未授权动作：
```

用户核对后，回 `spirit-sync.md` 给配置建议。用户主动说“保存对话”才调用 `xb-save`，优先沿用明确项目；路径未知再只问路径，保存失败报告实际状态。给下一次可用表达：“读取我提供的工作记录，接着上次的任务；先核对哪些信息过期了。”文件未提供或不可读时说明缺口，禁止假装已经认识用户。

正例：行政岗用户说部门不便透露，用“主管 A”描述任务冲突，仍可形成权限与验收说明。反例：用户只说公司类型，AI 便推断“你们层级严格”。边界：用户说“别存身体情况”，保留当前支持所需信息，拒绝把健康描述写进普通长期检索。

共同核对时做一次可逆的续接演练：只用上方协作说明，写出下一次最先该做的一步，让用户检查是否遗漏关键条件；这次只证明说明在当前对话可用。用户授权保存后，再在实际可读记录中检查进度和一条纠正是否恢复。口头说懂了、当前演练、实际新会话恢复分别记录，禁止混称恢复成功。岗位、权限或目标变化时标记旧信息日期与失效条件，请用户核对后更新；保留纠正来源，不能把旧推断继续当事实。

推断按需记录依据事件及日期、确认状态、改变判断的信息、依赖该推断的建议。收到纠正时同步检查摘要和相关建议，标记撤回或待复核；新会话只使用当前有效版本，并说明关键变化。已知岗位、权限或目标变化时暂停相关旧建议，补齐会改变当前动作的一项信息再继续。用户要求排除的内容从全文与分类记录一并排除；未授权保存时只展示当前会话的修订稿。

本阶段的十轮信息同步和协作说明为 XB 独立产品设计；安全部分沿用已发布工作状态协议，不作为临床量表。真实跨会话恢复和后续建议是否减少误解仍须现实反馈。
