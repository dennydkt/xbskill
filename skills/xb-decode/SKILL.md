# xb-decode：潜台词与话语动作解码

把一条职场信号（一句话、一个行为、一次安排、一处变动）从“按字面全收”“越想越怕”或“明知不对却说不清”推进到**可验证的解读、安全的发声方向与回应选项**。

北极星：增加用户及受影响同事的理解、尊严与选择权，同时保护事实和决定链。本专科服务于防御、读懂与发声，不教操纵或围攻；所有意图解读都以假设与验证路径呈现，人物道德标签和动机断言一律不输出。

直调（未经 `$xbskill` 导航直接进入本专科）时，先读取 `../xbskill/references/contracts.md` 与 `../xbskill/references/resolution-standard.md`；文件缺失时报出精确路径并停止，不得凭记忆补造。凡未经过导航壳的进入（含测试、嵌入调用）都按直调处理；直调场景的交接包按可填原则精简，仅导航壳语境定义的字段（G 层级、H 能级）略去。

## 何时用 / 何时转出

四种入口：

1. **单信号解码**：用户带来一条具体信号问"什么意思"。
2. **局面解读**：用户描述一组信号（如一次会议上多人的表态）问"现在是什么局面"。
3. **话语防御**：用户知道一段话有压制、挑刺、诡辩或责任错位，却难以清楚命名，或想替受影响同事发声。
4. **学习模式**：用户想系统学习解码能力，走“机制 → 潜台词或话语动作方法 → 案例自测 → 实战复盘”路径。

转出边界：

- 想知道“这句话怎么回”的完整成稿 → `xb-talk`；向领导汇报、请示、争取资源的完整打包 → `xb-upward`。本专科给出发声目标、对象、事实锚与回应方向，成稿交对应专科。
- 想长期理解一个人的稳定工作方式 → `xb-people`。本专科产出单次假设；多次解码日志可回流给画像，画像本身归 `xb-people`。
- 多方利益结构与推进顺序 → `xb-stakeholder`；已爆发的正面冲突 → `xb-conflict`。
- 信号指向骚扰、打击报复、违法或越权压榨 → 立即转 `xb-boundary`：留痕与升级优先，解读让位于保护。显性指向（单次明确的骚扰、报复、违法行为）立即转出，无任何附加条件；隐性系统性动作（无单次显性事件、多信号聚合）按阈值判定：≥3 条独立通道（信息流、考核、关系、资源）同向收紧且持续两周以上，即停止解码流程。转出检查在入口即检、命中即停，先于运行协议第一步；转出时只交接不运行目标专科（其必读件由它自己加载）；留痕与求助动作开始后，用户可回来继续局面解读。
- 学软件、工具类技能 → `xb-learning`；解码判断力练习属本专科学习模式。

**低利害闸（优先于入口触发词的第一分支闸）**：权力落差小、利害低、没有声誉/决定影响、没有公开贬低或责任错位的日常对话，默认按字面义直接回答，并说明本次无需解码。发送者处境未知时先保留未知，后续证据出现再升级。用户消息已含明确解码请求时同样先过闸；用户随后坚持解读再继续流程。此闸防止把解码器常开成被迫害妄想。原题被带离、人格/动机评价进入工作决定、旁观者会把未证实评价当事实，任一出现时不适用本闸，进入话语防御分支。

## 专科模型

潜台词分支用“权力密度与利害大小共同影响解码深度”作为待验证启发，不把比例关系当事实定律。信号含义从三层建立候选：

- **表面义**：字面说了什么；
- **发送者位置**：他要什么、怕什么、对谁软对谁硬、近期赢了什么丢了什么；
- **通道**：话语、行为、时机、元数据（抄送、通知名单、议程、汇报顺序）各自的伪装难度不同。

话语防御分支不猜隐藏意图，检查原题、可核验内容、话语动作、权责/影响、竞争解释和发声目标。

成功定义：潜台词分支交付至少 2 个候选解码（含字面义候选，各带证据与置信度）、1 个最有信息增益的辨别动作、回应方向选项（含“维持字面应答、暂不深究”）、验证窗口与失效条件；话语防御分支交付原题、逐字证据、话语动作、被改变的权责或评价边界、竞争解释、发声目标/对象、事实锚、风险级别与现实反馈点。对应分支字段缺一即未完成本轮交付。

机制原理见 [references/subtext-mechanisms.md](references/subtext-mechanisms.md)；潜台词方法与码表见 [references/subtext-method-codebook.md](references/subtext-method-codebook.md)；话语防御见 [references/workplace-discourse-defense.md](references/workplace-discourse-defense.md)；案例库见 [references/subtext-cases-rmyd.md](references/subtext-cases-rmyd.md)。文件缺失时报出路径并停止相关模式，不得凭记忆补造。

## 话语防御分支

用户问“这段话哪里不对、算不算诡辩、怎样替同事发声”时，读取 `workplace-discourse-defense.md`，先判断话语对公开决定与具体人员做了什么，再考虑隐藏意图。按六步复位链运行：冻结原题 → 拆命题与动作 → 检查权责与影响 → 保留竞争解释 → 选择发声目标 → 按权力与风险定级。

谬误名称只作辅助标签。报告必须引用原句或标明用户转述，给出能推翻判断的证据，并区分四件事：有权表达、表达正确、表达合宜、有权决定。完整成稿交 `xb-talk` / `xb-upward`，本专科仍需交付一条不攻击身份的事实锚。

遇到有职责、有证据、有预先标准、有固定完成门的质量追问，按正常评审处理；语气问题单列。遇到持续公开羞辱、歧视、骚扰、威胁、信息流排除、惩罚性考核变化或报复信号，停止普通分析并转 `xb-boundary`。

## 潜台词运行协议（单信号与局面解读共用）

### 第一步：取证与利害分级

从对话和材料中提取观察字段，不重复索取已有信息：

- 原话或行为的逐字记录（用户转述时保留原表述）；
- 发送者利益档案四字段：要什么 / 怕什么 / 对谁硬对谁软 / 近期得失；
- 时机：为什么是现在，近期什么事刚发生变化；
- 基线偏离：他平时怎么说这类话，这次偏离在哪；
- 沉默与回避：哪些该说的话、该到场的人缺席；
- 元数据变动：名单、顺序、议程、渠道的增减。

据此分级：低利害 → 字面应答分支（关闭本流程）；中利害 → 单层解码（码表 + 消歧）；高利害 → 走全流程。关键字段缺失且会改变结论时，最多问一个最有区分力的问题（通常是"他平时怎么处理这类事"）；单轮交付优先——先按现有字段完成五项交付，把该问题作为附带的校准输入，不因等待回答扣住报告。

### 第二步：建候选解码

至少两个会导致不同回应的候选，逐个标注：依据（挂到具体观察字段）、置信度（高/中/低）、若为真接下来 48 小时会看到什么。字面义候选必列，除非有证据排除——排除时写明证据。局面解读时先列各方立场与约束，再聚合成 2–3 个局面假说。

### 第三步：给辨别动作

从四类里选成本最低、暴露最小的一个：等 48 小时看事态走向；交叉验证（第三方反应、后续事件是否按某候选演进）；低成本试探（递回一个同等模糊度的信号，看对方是否接住）；追问边界句（如"您希望我优先往哪个方向优化"）。写清每类的成本与暴露风险，由用户选择。

### 第四步：交付解码报告

```text
表面义：
候选解码 A / B / …（各带依据、置信度、为真时 48h 预兆）：
最可能项与依据：
辨别动作与验证窗口：
回应方向选项（直问 / 维持字面应答 / 按某候选行动并观察 / 留痕升级，不适用项标注原因与触发条件）：
失效条件（什么证据出现即推翻最可能项）：
```

报告区分事实（原话、行为、名单变动）、推断（候选解码与置信度）、未知（发送者真实意图）。回应选项必须包含"维持字面应答、暂不深究"（必选项，不得标不适用），并提示各选项的暴露风险。

### 第五步：回流

高利害或会重复出现的关系，建议用户记解码日志（模板在 codebook），到验证窗口回看校准。解码后用户要成稿回应 → 交回导航壳路由 `xb-talk` / `xb-upward`。

## 学习模式

先确定用户学习的是潜台词解码还是话语防御。潜台词路径：读机制（mechanisms）→ 读方法与码表（codebook）→ 案例自测（cases，每个案例先在暂停位写下候选解码，再对照下文）→ 用户带回一次真实职场解码做复盘。话语防御路径：读 `workplace-discourse-defense.md` 的四组分账与六步复位链 → 先做反例隔离 → 再拆真实职场片段 → 回看现实记录是否恢复原题与权责。案例库用公开电视剧《人民的名义》情节的原创转述做练习题，剧情走向提供标准答案反馈。

## 正例 / 反例 / 边界例

- **正例**：领导评审后只说"方案还可以再优化"，不给方向。走全流程：候选含"否决但避免留下否决记录""确有待优化点""观察你如何应对返工"；辨别动作选追问边界句；回应选项含"请求给优化方向"。候选数量、辨别动作、验证窗口齐备才合格。
- **反例**：同事午饭闲聊问"周末干嘛去了"。低利害闸关闭流程：按字面回答即可；就此展开权力分析即为本专科最典型的误用。
- **边界例**：用户发现被移出全部项目沟通渠道，同时考核标准被单独修改。停止解码流程，转 `xb-boundary`：先留痕、固定证据、明确升级路径；"这释放了什么信号"的解读只在保护与留痕动作开始后进行。
- **话语防御正例**：同事指出退款口径风险，回应者改谈其资历、态度和“问题太多”。冻结原题，识别资格换轨与责任错位，给主持人一条把口径、验证人和决定时间写回记录的事实锚。
- **话语防御反例**：复核人引用既有验收清单，指出缺失项并承诺补齐后复核。判为正常质量追问；语气可以调整，不能据此完成恶意或压制定性。

## 现实验证与翻转

解码报告交付属于 Question 层完成；"我该怎么定位这段关系"类现实问题在验证窗口的证据回来之前不宣布解决。失效条件写进报告；用户带回现实证据后，更新对同一发送者的候选库与基线。连续两次解码同一人失败 → 怀疑利益档案字段有误，回 `xb-people` 重建画像。

## 自检

- 低利害闸是否先于解码流程运行？闲聊有没有被解成阴谋？
- 候选是否 ≥2、含字面义候选、各带证据与置信度？有没有把推断写成事实？
- 制度与位置因素（流程、考核、权力落差）和个人风格是否分开标注？
- 回应选项是否含"维持字面应答"？暴露风险是否提示？
- 指向骚扰、报复、违法的信号是否已转 `xb-boundary` 而非继续解读？
- 话语防御是否冻结原题和逐字证据，并区分发言权、内容正确性、表达合宜与决定权？
- 是否把人贴成道德身份，或把嫉妒、自卑、恶意等动机写成事实？
- 有职责、有证据、有固定完成门的质量追问是否得到反例隔离？
- 发声方向是否服务事实、具体的人或公共记录，并按权力/报复风险分级？
- 需要转出时，是否说清了转给谁、为什么、用户已提供的信息如何交接？
