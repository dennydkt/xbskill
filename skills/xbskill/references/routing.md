# xbskill 完整路由表

先过安全闸和选择门，再按瓶颈路由，最后参考关键词。多个问题并存时，选择最先阻塞用户净收益与可验证结果的一项。

## 岗位纵深是条件层，不是菜单

先按当前瓶颈选择下表中的一个 `xb-*` 专科，再判断岗位差异是否会改变观察项、责任接口、动作或验收：

- 数据分析师、数据工程师、数据治理师、数据产品经理：按需读取 `role-context-model.md` 与 `data-work-specialties.md`。
- 产品经理、UX 设计师、前端工程师、后端工程师、架构师：按需读取 `role-context-model.md` 与 `product-rd-specialties.md`。
- 项目管理、行政、秘书、综合/机关办公室：按需读取 `role-context-model.md` 与 `function-work-specialties.md`。
- 金融分析师、投资研究员、权益研究员、投委会支持：按当前瓶颈选择一个现有专科，再按需读取 `role-context-model.md` 与 `finance-marketing-specialties.md` 的金融切片；活动岗位知识无匹配时显式 `no_match`。
- 营销经理、产品营销、增长营销、营销分析师：按当前瓶颈选择一个现有专科，再按需读取 `role-context-model.md` 与 `finance-marketing-specialties.md` 的营销切片；活动岗位知识无匹配时显式 `no_match`。
- 企业类型、人文环境、正式/实际权责会改变路径：再读取 `organization-strategy-genome.md`；类别只排序补问，不能直接激活动作。
- 当前专科已经确定，但岗位专业知识会改变观察、竞争解释、动作、产物或验收：由当前专科隐藏支持调用 `xb-role-knowledge`，取得最小包后继续原专科；它不是第二个当前 Skill。

同一任务横跨多个角色时只标当前责任帽子，仍然一次推进一个瓶颈。简单任务不加载岗位全景，不因用户职业名改变明确答案。

## 路由前置：价值阶梯与选择门

| 当前最需要的变化 | 首要判断 | 常见候选 |
|---|---|---|
| 稳住 | 是否存在安全、功能、健康、骚扰、报复或严重负荷信号 | `xb-wellbeing`、`xb-boundary` |
| 解卡 | 目标是否必要且成本可接受；卡点在哪一环 | 对应任务专科、`xb-action` |
| 看懂 | 症状来自任务、状态、能力、人物/权力还是公司 | `xb-triage`、`xb-analysis`、`xb-people`、`xb-company`、`xb-decode` |
| 改变 | 哪个条件可调整，谁有权决定 | `xb-goal`、`xb-plan`、`xb-upward`、`xb-stakeholder`、`xb-boundary` |
| 选择 | 继续、试验、暂停、转岗或退出的条件是什么 | `xb-decision`、`xb-career` |

简单、明确、低风险且成本可接受的任务默认进入“解决”，直接路由任务专科；不要为了展示模型强迫用户做心理盘问。出现反复做不动、成本失控、价值/伦理冲突、结构性伤害或去留疑问时，必须按 `agency-model.md` 显式判断解决、调整或退出。

## 易混淆边界

- `xb-analysis` 判断“为什么”；`xb-data` 处理数据证据和口径。
- 模糊评价与目标不清同时出现时：用户只问“怎样把标准说清”可进 `xb-goal`；一旦追问“是不是我能力/性格有问题”或要求归因，必须先进 `xb-analysis`，显形词义/目标、真实质量、人物/权力、流程接口候选及置信度，再把校准动作交给 `xb-goal`。不得用目标校准跳过人物/权力归因。
- `xb-triage` 在问题混杂时找当前瓶颈；`xb-analysis` 在已有分析任务时建立现象、竞争解释和验证；长期人物/公司结论仍由对应档案专科维护。
- `xb-talk` 解决单次表达；`xb-upward` 处理上下级权责与预期；`xb-stakeholder` 处理多人利益结构。
- `xb-decode` 解读单条信号的多层含义，也识别公开话语动作怎样改变原题、举证、评价边界和责任；`xb-people` 维护长期工作画像；解码后要完整成稿或汇报包交 `xb-talk`/`xb-upward`。信号已经进入骚扰、报复、越权或持续边界侵蚀时，`xb-boundary` 保持唯一当前专科，并可隐藏复用话语防御 reference 先做体验承接与逻辑复位，再进入保护或话术。严格评审若有职责、证据、既有标准和固定完成门，留在正常质量讨论，不能因语气生硬直接定性。
- `xb-action` 处理启动与执行阻力；`xb-wellbeing` 处理身心负荷和安全边界。
- `xb-action` 不能把所有不行动都改造成执行；价值冲突、容量耗尽或现实风险先回选择门。
- `xb-decision` 处理当前工作/任务取舍；`xb-career` 处理岗位、转岗、跳槽与离职等职业路径。二者都保留用户最终决定。
- `xb-decision` 只有在用户明确要求保存/回填时建立项目内决策事件；普通选择不强迫持久化，`xb-save` 只引用事件而不复制第二真源。
- `xb-writing` 写成稿；`xb-report` 汇总一段时间的状态与结论；`xb-review` 审查已有产物。
- `xb-plan` 设计工作；`xb-automation` 把稳定重复流程机器化。
- `xb-capability` 判断“能稳定做到什么”；`xb-people` 判断“在特定情境下怎样工作”；两者不能互相替代。
- `xb-learning` 通过真实任务生成新能力证据；`xb-capability` 汇总和判级。课程、AI 成品或一次练习不能直接升级等级。
- `xb-ai-native` 编排多周期发展（画像校准、四维证据、周期验收）；单技能训练环归 `xb-learning`，判级归 `xb-capability`，单次取舍归 `xb-decision`，流程机器化归 `xb-automation`。它消费上述专科的产出，不重复其工作；用户只求单点时先路由对应专科。
- `xb-company` 提供组织事实与约束；`xb-stakeholder` 针对当前项目设计多方推进。
- `xb-goal` 同时确定目标层级与帮助能级；目标清楚时入口可轻量判定，不强制进入专科。
- `xb-wellbeing` 提供工作相关支持，不做临床诊断；结构性伤害不能被路由成“调整心态”。
- 专科为当前结论读取已存在的 `KnowledgePacket` 时仍留在原专科；只有用户的主结果是发现、建包、校验、更新或回滚知识来源时才路由 `xb-knowledge`，不得新增“来源管理”菜单项。
- `xb-knowledge` 治理来源、许可、锁和证据；`xb-role-knowledge` 把已治理主张翻译为岗位任务的观察、分支、产物和验证。普通岗位任务只支持调用后者，不切换当前专科；只有用户明确要补充/治理岗位单元时才直达它。
- 任务跨 IT/数据/文档/汇报/审查时仍只路由当前瓶颈专科；共享 `task-domain-patterns.md` 是按需契约，不是新菜单或默认长链。
