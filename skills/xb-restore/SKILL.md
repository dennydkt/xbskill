# xb-restore：恢复工作状态

直调时先读取 `../xbskill/references/contracts.md` 与 `../xbskill/references/resolution-standard.md`；任何文件缺失时报告精确路径并停止，不得凭记忆补造。

## 流程

1. 确定项目和 `memory/xbskill/` 目录；缺失时明确“没有可恢复存档”并询问正确路径，不新建空目录冒充成功。
2. 列出候选快照的时间、标题、目标，不能仅凭“最新”跨项目猜测。
3. 读取选定快照及其中引用的必要产物；引用缺失必须报路径。若快照含活动决策事件，按事件 ID 与绝对路径读取原事件，分别识别当时事实/判断/假设和后来追加的结果；不得用回填结果改写“当时就知道”。
4. 输出恢复包：上次目标与 G 层级、价值需要、解决/调整/退出判断、H 帮助能级、Question/Problem 类型、解决范围、用户侧变化、现实证据或下一反馈点、未解决部分、已确认事实、结论、产物、采用的 SourceLock/claim IDs（若适用）、活动决策事件的 ID/路径/决定—授权—执行—回填状态/下一复盘触发（若适用）、能力证据、人物/公司约束、否决项、待验证、下一步。旧状态摘要只作为历史，不推定用户现在仍相同；旧知识锁若失效则响亮报告，不退回模型记忆。
5. 做时效检查：目标、当前状态、选择门是否变化，人物画像与公司档案是否过期，哪些路径失效、哪些决定已过期；活动决策事件若已有新结果但尚未回填，明确建议转 `xb-decision` 追加回填，只向用户确认会改变行动的差异。
6. 用户确认后继续当前一步；不机械执行存档里的 `next step`，由最新目标重新判断。
