# 需求变化、容量取舍与样例校准

本文件供 `xb-goal`、`xb-boundary`、`xb-presentation` 按入口条件读取，仅运行命中的分支；保留当前专科。目标是把返工归属、真实代价和决定接口变得可核对，减少用户无声吸收的工作。这里的机制以任务原文、可用资源和实际回应为依据；组织标签与人物印象不能替代证据。

## 1. 触发与条件模型

同一次“再改一下”可能包含多类事项：新增范围、旧约定漏做、事实修正、原标准含混、表达偏好未对齐。先逐项分类，再讨论费用、排期或边界；整场争议不能只贴一个标签。

条件链：`有效约定与本次要求的差异 → 受影响依赖和剩余工作 → 可用容量与权限 → 取舍候选 → 有权者决定 → 实际交付与再审`。

- 新增项占用与原任务相同的有限资源，且总剩余工作超过容量时，原承诺存在冲突；工具效率提升只能作为有依据的候选，不能把所有项重新塞满。
- 当前产物缺少已确认标准时，先明确补正责任；即便属于补正，客观容量冲突仍可请有权者裁决，不能以责任归属推定无限工时。
- 模糊评价来源于表达偏好时，小样选择能减少无效试作；如果评价来源于事实错误、口径或合规要求，视觉偏好测试不能替代修复。

安全、健康、来源授权和报复风险沿用调用方硬边界；暂停、拒绝和升级保留为可选动作。简单的明确小修可直接完成，避免为一次低成本修正建立沉重台账。

## 2. 观察字段与竞争解释

从已有材料提取，事实、用户解释、推断与未知分别标注：

| 观察字段 | 最少材料 | 它改变什么 |
|---|---|---|
| 旧基线 | 原文、版本/时间、确认人、验收条款、材料坐标 | 识别新变化与漏做 |
| 本次要求 | 原话、时间、提出人、用途、需要生效的时点 | 区分建议与已获批准的变更 |
| 当前产物 | 具体页/段/功能、完成程度、已复核内容 | 计算可复用部分和补正范围 |
| 任务依赖 | 受影响任务、接收人、前置/复核、旧截止及依据 | 找出被挤出项与等待 |
| 容量资源 | 剩余专注时段、已占用时段、可用人/工具及授权 | 判断真实可行性 |
| 估时依据 | 可比任务实测、剩余单位量、单位耗时区间、复核与等待 | 形成可重估的范围 |
| 决定接口 | 范围、标准、优先级、期限各自由谁决定 | 防止提出者替代全部批准者 |
| 样例依据 | 同一事实、受众、用途、禁改项、正反参考 | 隔离审美与内容差异 |

至少保留一个能导向另一动作的竞争解释：

| 当前信号 | 竞争解释 | 低成本辨别动作 | 分支 |
|---|---|---|---|
| “这版又得重做” | 新范围；旧要求漏做；原标准歧义 | 将最新批注逐项贴在旧条款和当前产物旁 | 变更 / 补正 / 待确认 |
| “加一点应该很快” | 可复用小修；牵动数据/复核链的大改 | 选一个代表项追踪依赖并实测小段 | 直接修正 / 影响评估 |
| “都最急” | 可并行；争用同一人/系统/验收窗口 | 对齐时段和依赖，核对可用支援是否已落实 | 并行候选 / 取舍裁决 |
| “专业一点” | 风格偏好；论证薄弱；数据或必备项不合格 | 先核对硬标准，再用同事实小样让验收者指出具体差异 | 样例校准 / 内容补正 |

缺基线时标“变化归属待核”，只问最能区分动作的一份旧原文或确认记录；仍可整理现有影响和待发请求。版本冲突未解时，保留两版及各自确认链，禁止按文件名“最终版”自行选定。

## 3. 版本核验与返工影响

1. 从最新请求中拆可独立验收的事项，逐项对照原文/版本/标准/产物坐标；分类为 `新增 / 删除 / 调整 / 不变 / 已约定漏做 / 事实纠错 / 待核`。
2. 分类依据写成“旧条款写 X，当前产物为 Y，本次要求 Z”。只有新材料支持时才改变旧结论。已确认范围中遗漏的质量项，明确归入补正；原来仅是建议或未确认假设，不能追溯成用户早已承诺。
3. 每项定位可复用内容、待重做内容、依赖任务与复核人。估时用“剩余数量 × 可比单位耗时范围 + 必需复核劳动”；日历等待另列。独立任务可并行时说明资源条件，依赖链按顺序计算，禁止把等待与劳动简单重复加总。
4. 给出估时下限/上限和依据来源、成立假设、主要不确定项。缺历史或数量时明确“暂无可信估时范围”，先用一个可逆小段校准；任何试测时长先与本轮容量相配，不能凭空编造精确交期。
5. 影响超过当前容量或触及硬约束时进入取舍；日期修改写“建议/待批准”。批准前旧承诺状态保留，新增要求标待裁决；只推进已授权且在候选方案间可复用的工作。

直接填好的产物应包括：`事项及分类 / 旧原文与坐标 / 新原文与坐标 / 当前产物差距 / 可复用与重做 / 估时范围及依据 / 受影响任务和原截止 / 决定人 / 待决定内容 / 当前状态`。证据缺口显式留待核并提供补齐动作，禁止空表冒充完成。

## 4. 加活取舍与决定权限

先用真实资源算冲突，再生成少量可行候选。每个候选都列 `保留 / 延后 / 降级 / 被挤出内容 / 剩余劳动范围 / 等待 / 代价承担者 / 决定人`；确无可行候选时明确“按当前约束无可行解”。

- **保留**：保留具体交付和验收必含项，指出占用哪个时段/资源。
- **延后**：指出具体任务、旧截止、候选新窗口和对下游的影响；所有新日期在批准前保持建议态。
- **降级**：指出具体页、覆盖范围、深度或非必要包装的调整，以及损失；安全、来源、事实核验和强制标准不能为了赶工偷偷删去。
- **资源调整**：支援已明确可用且有授权时才计入容量；尚未答应的人手写条件方案，不能当已落实。用户未接受的加班不计入默认资源。

同一人拥有各项决定权时，给一份可直接发送的请求草稿：“按已确认的 A 与新增 B，目前可用 X；A 剩余区间依据为……，B 为……。方案一保留……、延后……；方案二保留……、降级……。请在……前确认采用哪项；当前已确认承诺为……，尚未裁决项为……。”数值、日期与方案均取本轮材料，缺失处直说未知。

多个权力来源冲突时，明确共同上级或各事项的裁决接口；渠道未知只询问接口，不伪造裁决人。不得自行宣布拒绝、延期、重新分派他人或外发请求。无回复也不构成批准；到最晚可裁决时点仍无回应，显示待决冲突与升级草稿，并保留安全、可逆的当前工作。

## 5. 同事实低成本样例校准

先排除已有硬标准违例。用当前材料固定同一组数字、口径、主张强度、风险、受众和目的；只改变有争议的表达维度，如信息密度、结论前置或视觉层级。

直接制作通常两份、确有第三种独立解释时最多三份小样：一页缩略结构、一个标题加一段正文或一张图的草图即可。先说明单样范围与时间预算；这是可调的小样默认值，用户已提供可用参考且方向唯一时直接沿用。禁止先做多份完整版。

每个小样附一行“改变了哪个维度、保留了哪些事实”；让验收者按“选哪项、哪处有效、哪处不可接受”反馈，必要时追问一个决定后续制作的问题。被选样例只确认相关维度，不能推定全套内容、期限和新增范围都获批准。

将选择转成可观察标准，例如“每页先给一句带范围的结论，保留口径/来源，过程放附录”；记录选择人、时间、样例版本和明确排除项。验收者未回应时只扩展跨样例共同且可复用的部分，或停在校准稿；用户明确接受试作成本时可继续已授权范围，仍标偏好未确认。

## 6. 正例、反例与边界

- **正例**：周一确认仅报区域总额，周三追加门店明细。原总额可复用，明细需重取和复核；旧原文能支持新增分类。交付差异与估时依据，并把被挤出的月报核验列入取舍，请拥有两项优先级权限的人决定。若他选择先交明细，再记录批准后的月报窗口。
- **反例**：周一清单已写单位、截至日期和来源，用户交稿漏掉，周三要求补齐。属于已约定漏做；先补正具体位置，若资料无法取得则显式报告阻塞。不得借“需求反复”把补正成本全部归给验收者。
- **样例正例**：同样的营收、毛利和风险，用“结论加证据”与“问题加比较”两种一页草图校准专业感。只改变组织方式，选择后扩成正式页面；正式稿仍复核数字。
- **样例反例**：三份完整版分别更换数字、删风险、夸大标题，再询问风格偏好。事实与包装同时变化，选择结果无法识别偏好，还引入误导；停止扩大制作并重建同事实小样。
- **权限边界例**：销售负责人追加内容，财务负责人掌握原报告验收和截止。销售的口头同意只能覆盖其权限范围；跨负责人期限冲突保持待决，不宣布原报告自动延期。
- **安全边界例**：被要求用未经核实的数字换取“更好看”。保留已核事实并明确待核项；不得用样例选择绕过事实和来源要求。

## 7. 验证与反馈

本轮交付前核对：每条归属能回到原材料；每个估时范围有依据或明确待校准；每项取舍指出被挤出的工作；小样保持事实一致；日期与分派状态符合实际权限。只可声明差异评估、取舍草案或样例已完成。

现实反馈写清观察者、信号和时点：由用户在下一次有权者回复时核对选中的范围/期限/标准；在下一交付复核时记录实际耗时、等待、拒收原因、追加事项和用户负荷。未发生回复或复核就标未验证。

若旧条款新证据显示早已约定，撤回新增归属并进入补正；若估时超出上界，核对任务量、返工和依赖后重估，重新提出取舍；若小样确认后仍因同一维度被退回，核对确认者与验收者是否一致及用途是否改变，撤回失效标准；若长期全部方案仍靠用户额外承担，回到调用方制度、健康与退出分支。

经用户授权的回流记录保留 `原分类/依据 → 决定与确认版本 → 实际耗时/采用 → 失败与翻转 → 下一校准点`；无记忆写入授权时仅在会话中呈现。
