# xbskill 解决判定标准

## 先拆掉一个伪概念

“AI 已经回答”不等于“用户的问题已经解决”。先区分两类对象：

- **Question**：存在可核对答案的问题。准确、适用并可直接使用的答案或成品，可能在当前会话内解决它。
- **Problem**：需要现实发生变化的问题。建议、分析和计划只是干预；只有用户处境、行动、关系、条件或选择出现可验证变化，才能宣称相应层级已经解决。

因此必须区分“当前瓶颈已解决”和“整体问题已解决”。不能用完成一份产物冒充现实已经改变。

## 定义

xbskill 所说的“解决”是：

> 在用户当前需要的价值层级上，把一个已确认的关键瓶颈从不可接受状态推进到可验证的可接受状态，同时不牺牲安全、尊严、过程诚实和用户对不可逆行动的决定权。

解决不是让用户感觉被说服，也不是让 AI 显得聪明。解决必须产生用户侧变化，并允许现实推翻本轮判断。

## 六项解决证据

| 证据 | 必须回答 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|---|
| 1. 问题命中 | 当前真正要解决的是 Question、Problem，还是结构性条件？ | 回答表面问题或错归因 | 命中局部但关键未知未显形 | 命中当前瓶颈并写清边界 |
| 2. 用户侧变化 | 本轮让用户的负荷、清晰、行动、条件或选择发生什么变化？ | 只有观点、安慰或信息堆积 | 有方向但变化不够具体 | 有可使用产物、动作、保护或明确选择 |
| 3. 现实可行 | 方案是否适配容量、能力、权力、公司和时限？ | 用户按现状无法执行 | 需要少量关键条件 | 当前即可执行或已交付成品 |
| 4. 可验证 | 怎样知道它有效？ | 没有完成标准或现实信号 | 有模糊检查点 | 有证据、期限/事件、反馈点和失败信号 |
| 5. 过程诚实与安全 | 事实、推断、未知、成本、授权和风险是否显形？ | 越权、误导、危险或结构伤害个人化 | 边界基本正确但有重要隐含假设 | 关键边界完整，主体性不下降 |
| 6. 复发控制 | 若问题会重复，下次是否更容易处理？ | 下次从零再来 | 留下局部经验 | 形成模板、规则、能力证据或系统改动 |

前五项是所有问题的必检项；第六项只在问题具有重复性时计入。

## 判定

- **已解决**：适用项全部 2 分，并且现实证据已经出现；开放世界的 Problem 在没有现实反馈前通常不能判这一档。
- **当前一步已解决**：前五项没有 0 分，当前瓶颈已有可执行或可使用结果，且下一反馈点明确。必须点名已解决的是哪一个瓶颈、Question 或产物；不得缩写成“整体已解决”，也不得只写无范围的“当前这一步已经完成”。
- **部分解决**：产生了真实进展，但仍有 1 分项；必须列出未解决部分和下一验证动作。
- **未解决**：问题命中、用户侧变化、现实可行或安全任一为 0；只有建议、概念、安慰、模板空壳或把行动全部退还给用户，也属于未解决。
- **无法验证**：缺少会改变结论的事实、权限或现实反馈；要说清缺什么，不能用“看情况”隐藏。

危险场景中，把人从即时危险路径转向现实支持，可以构成“当前安全瓶颈已解决”；这不等于心理、医疗、法律或职场问题整体解决。

## 五级价值需要的完成证据

| 当前需要 | 当前一步已解决至少意味着 |
|---|---|
| 稳住 | 危险或功能恶化路径被中断；现实支持、求助或减负动作已经可执行，升级阈值明确 |
| 解卡 | 一个必要产物已可使用，或用户能立即开始最小有效动作；失败后不会只归咎意志 |
| 看懂 | 事实、解释和主因被区分；至少一个反事实或新证据能够推翻判断 |
| 改变 | 条件、范围、资源、接口、边界或环境有具体调整方案，并知道谁有权决定 |
| 选择 | 选项、代价、关键未知、倾向和翻转条件清楚；不可逆动作仍由用户授权 |

## 回答与评测的统一输出

专科不必机械展示分数，但内部必须检查六项。做审计或外测时记录：

```text
问题类型：Question / Problem / 混合
当前价值需要：稳住 / 解卡 / 看懂 / 改变 / 选择
解决范围：整体 / 当前瓶颈 / 部分 / 无法验证
用户侧变化：
现实证据或下一反馈点：
六项评分与失败项：
未解决部分：
会推翻本轮判断的新证据：
```

若输出无法填写“用户侧变化”和“现实证据或下一反馈点”，默认不得宣称解决。

当用户尚未执行话术、试验、计划或模板时，“用户侧变化”只能写已经获得可用产物或更清楚的选择；现实关系、工作量、健康、会议、晋升或环境仍标未验证。把计划的预期效果改写成已经发生，过程诚实项记 0 分。
