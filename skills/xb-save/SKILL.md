# xb-save：工作状态快照

直调时先读取 `../xbskill/references/contracts.md` 与 `../xbskill/references/resolution-standard.md`；任何文件缺失时报告精确路径并停止，不得凭记忆补造。

## 路径硬约定

优先写入当前项目的 `memory/xbskill/`；若无法确定项目根目录或项目没有明确 memory 位置，先问用户指定。禁止写入 AI 工具私有目录，禁止静默创建另一个“记忆系统”。

## 流程

1. 解析项目 slug 与目标目录；显示将写入的绝对路径。
2. 从对话提取而非重问：用户原始目标、G 层级、当前价值需要、解决/调整/退出判断、H 帮助能级、Question/Problem 类型、解决范围、用户侧变化、现实证据或下一反馈点、未解决部分、已确认事实、关键结论、产物路径、采用的 SourceLock/claim IDs（若适用）、已否决方向、待验证假设、相关能力证据、人物/公司约束、风险、当前下一步。若 `xb-decision` 已在用户授权下建立长期事件，只保存事件 ID、绝对路径、决定/授权/执行/回填状态、下一复盘触发，不复制整份事件；未立案时不得为了快照静默新建。状态与主体性只保存行动相关摘要，并再次确认用户确实要落盘。
3. 区分用户原话、材料事实、AI 推断和用户决定；不把建议写成已确认结论。
4. 文件命名 `YYYY-MM-DD-HHMM-<slug>.md`，写完不改；后续状态新建快照。
5. 写入后重读，核对路径、完整性和敏感信息；报告快照位置。

## 快照模板

标题；时间/项目/来源；用户目标与 G 层级；当前价值需要；选择门；H 帮助能级；问题类型与解决范围；用户侧变化；现实证据/下一反馈点；未解决部分；行动相关状态与主体性摘要（可选、含日期/有效期）；已确认事实；当前结论；产物；知识锁与主张（若适用）；活动决策事件（ID/绝对路径/状态/待授权项/下一复盘触发，若适用）；能力证据；人物/公司约束；否决项；待验证；风险；下一步；恢复提示。

禁止默认保存诊断式心理标签、无关健康细节或去留想法；这些信息不因“方便恢复”自动获得长期保存授权。
