# 人与组织领域共用判断模式

本文件为 `xb-meeting`、`xb-talk`、`xb-upward`、`xb-stakeholder`、`xb-conflict`、`xb-boundary`、`xb-people`、`xb-company`、`xb-wellbeing`、`xb-career` 的按需参考。它把协作问题拆成可观察事件、四层原因、权力链、模式和现实验证，不替代各专科流程。

简单、一次性、低风险且原因明确的任务不读取本文件。出现以下任一情况时完整读取：同一问题反复发生；解释横跨两层以上；涉及多人权力或正式/实际规则；用户要求诊断原因；需要决定解决、调整、升级或退出；需要用共用模式编号形成回流记录。文件缺失时报告精确路径；不得用模型记忆补造模式。

## 1. 原子事件与四层归因

### 1.1 原子事件

把“他不尊重我”“公司很乱”“会议没用”还原为：

```text
时间/场景：
参与者与角色：
待完成对象：
当时目标与验收：
原话/动作/记录：
谁掌握决定、资源与惩罚：
正式规则与实际做法：
直接结果与成本承担者：
已尝试动作及对方回应：
重复范围（人/次数/周期）：
```

不知道的字段写“未知”。原子事件用于生成假设，不自动证明动机、人格、文化或违法性质。明确的威胁、骚扰、自伤/伤人风险、严重健康症状和重大合规风险不等待完整事件账，先走安全边界。

### 1.2 四层原因

| 层级 | 核心问题 | 可观察证据 | 典型干预 | 不能据此下的结论 |
|---|---|---|---|---|
| P 个人 | 当事人的容量、知识、技能、判断或当前状态是否构成断点？ | 同流程、同资源下差异稳定；训练或恢复后结果改变 | 补信息、练习、减负、支持、调整任务 | 一次失误不等于能力差；疲惫不等于人格 |
| R 关系 | 两人或小群体的预期、信任、沟通接口、承诺是否错位？ | 换对象正常；换表达、时机或确认方式后结果改变 | 澄清接口、修复承诺、谈边界、引入见证 | 不把权力压制称为“双方沟通问题” |
| F 流程 | 输入、验收、责任、依赖、信息、节奏或反馈机制是否断裂？ | 换人仍复现；断点固定在同一交接或节点 | 补 owner、验收、真源、依赖、升级和复盘 | 有流程不等于流程在实际运行 |
| I 制度 | 权力、激励、资源分配、正式/实际规则和申诉是否制造同类结果？ | 跨人跨期重复；成本稳定下沉；规则与奖励维持行为 | 改规则/资源/治理、正式升级、转岗或退出 | 单一事件不等于文化定性；描述规则不等于认可规则 |

不得先选一层再搜证据。至少保留两个可竞争解释，并写出什么新证据会让判断从一层翻到另一层。

### 1.3 跨层检验顺序

1. 先控即时安全与不可逆风险。
2. 明确当前要恢复的最小结果，而不是先判断谁好谁坏。
3. 收集一个原子事件；重复问题再取一个对照事件。
4. 对 P/R/F/I 分别写“支持证据、反证、未知”。
5. 优先选择能区分解释、可逆且不把成本继续压给低权力方的动作。
6. 用现实回应更新归因；不因第一次解释顺口就固化。

## 2. 权力—责任—成本账

任何涉及承诺、分工、评价、冲突、边界、晋升或离职的问题，拆开以下角色：

| 字段 | 要问什么 |
|---|---|
| 提出者 | 谁提出目标、请求或指令？ |
| 决定者 | 谁能在选项之间作最终取舍？ |
| 授权者 | 谁允许使用资源、时间、预算或系统权限？ |
| 执行者 | 谁实际完成动作？ |
| 验收者 | 谁按什么证据判断完成？ |
| 复核/申诉者 | 争议由谁复核，渠道现实可用吗？ |
| 后果承担者 | 延期、错误、健康、关系和合规成本落到谁？ |
| 裁量与强制 | 当事人有哪些真实选择，拒绝成本和报复证据是什么？ |

责任不等于服从。没有决定权的人不能被默认要求吸收全部结果风险；有职位的人也不自动拥有某事项的合法授权。若用户无权替别人承诺、外发、升级、辞职、签署、投诉或改规则，只能生成草案、选项与确认点。

## 3. 共用信号词典

信号只触发追问或候选模式，不直接等于诊断。

| 可观察信号 | 首要候选 | 下一项最小核验 | 禁止跳到 |
|---|---|---|---|
| “尽快、做好、专业一点、再努力” | 验收词漂移（F/R） | 一个被接受正例、一个被拒绝例、决定人 | “用户能力差” |
| “大家都知道/大家都同意” | 共识或信息来源不明（F/I） | 谁明确确认、何时、原始记录 | 把沉默写成同意 |
| “先做了再说/反正你负责” | 决定权与责任错配（F/I） | 谁决定取舍、谁接受风险 | 用服从替代授权 |
| “我都可以/没问题/我尽量” | 容量或边界被隐藏（P/R） | 可用容量、不可承诺项、取舍人 | 认定真心同意 |
| “他总是/公司从来不” | 概括超出样本 | 一个具体事件和一个对照事件 | 人格/文化定性 |
| 同一任务多人都“负责” | 所有权扩散（F） | 唯一 owner、验收者、依赖 | 归因个人不主动 |
| 截止/优先级反复变化且无新确认 | 决策漂移（F/I） | 变化者、变更依据、被降级事项 | 要求个人加速吸收 |
| 信息散在群聊、私聊、文档且互相冲突 | 真源缺失（F/I） | 哪个来源有权覆盖、版本时间 | 让用户自行猜最新版 |
| 纸面有渠道但没人敢用/用了无回应 | 实际规则与正式规则分离（I） | 近期案例、监测、申诉结果 | 把渠道存在写成有效 |
| 同类成本长期落到同一低权力方 | 成本下沉（R/I） | 谁获益、谁决定、能否拒绝、是否跨期 | “不会拒绝”作为主因 |
| 错误随打断、工时或睡眠恶化而增加 | 容量/系统负荷（P/F） | 减负前后同口径结果 | 懒惰、态度或人格 |
| 换人后同一断点仍复现 | 流程/制度候选（F/I） | 共同节点、规则、资源和激励 | 继续培训单个人 |
| 换对象或渠道后问题消失 | 关系接口候选（R） | 哪个变量改变、能否重复 | 直接认定对方恶意 |
| 上报后出现可核对的不利动作 | 报复风险候选（I） | 时间线、原文、决定链、专业渠道 | 自行作法律认定 |
| “我是不是太敏感/不够努力” | 自我归罪信号（P/R/I 均可能） | 任务量、规则、他人对照、功能变化 | 立刻安慰或立刻归结构 |
| “辞了就都好了/只能忍” | 假二选一（多层） | 调整路径、缓冲、退出阈值、不可逆点 | 替用户定辞职日期 |

## 4. 十二个可检验模式

### M01 验收词漂移

- **成立信号**：同一抽象词对应的正反例矛盾；复核时标准移动。
- **动作/产物**：用法对照卡：原词、正例、反例、可观察差异、决定人、有效期。
- **翻转**：有权者给出稳定标准，之后案例可一致分类。

### M02 决定权—责任错配

- **成立信号**：用户承担结果，却不能改范围、资源、期限或优先级。
- **动作/产物**：责任账 + 两个真实取舍 + 书面确认请求。
- **翻转**：用户获得相应裁量，或决定者明确接受风险与取舍。

### M03 容量透支

- **成立信号**：承诺量超过可用工时/注意；错误随负荷变化；没有被降级事项。
- **动作/产物**：容量账、保/砍/延/求助清单、审批点、恢复与复核窗口。
- **翻转**：负荷下降后断点仍稳定存在，转查能力、流程或资源。

### M04 所有权扩散

- **成立信号**：“共同负责”但无人能验收或拍板；行动项没有唯一 owner。
- **动作/产物**：RACI 的最小版：唯一 owner、决定人、验收、依赖、截止、确认状态。
- **翻转**：责任人明确确认并按标准交付；若仍卡住，转依赖或权限。

### M05 依赖孤儿

- **成立信号**：任务依赖外部输入，但依赖没有提供者、承诺时间或升级人。
- **动作/产物**：依赖账：输入、提供者、需要时间、承诺状态、最晚升级点、降级方案。
- **翻转**：输入按期到位；若反复失约，升级为接口、激励或治理问题。

### M06 信息真源缺失

- **成立信号**：多个版本并存；使用错误版本无人负责；访问权与覆盖权不清。
- **动作/产物**：来源地图、候选真源、授权确认、版本/日期、访问与变更规则。
- **翻转**：有权者指定真源且现实使用稳定；普通用户不得自行宣布公司真源。

### M07 激励与目标冲突

- **成立信号**：口头鼓励 A，评价/资源/惩罚持续奖励 B；跨人跨期出现。
- **动作/产物**：宣称—正式—实际奖励对照，受益/成本，能改规则者，验证案例。
- **翻转**：评价、资源或近期决策改变并维持；单次例外只降低置信度。

### M08 边界侵蚀循环

- **成立信号**：临时例外变常态；拒绝成本不对称；每次让步扩大下一次默认范围。
- **动作/产物**：边界事件账、可承担/不可承担、例外入口、替代、红线、升级条件。
- **翻转**：边界获得明确确认并在重复场景中被遵守；一次口头同意不够。

### M09 关系承诺破裂

- **成立信号**：明确承诺未履行，双方对承诺内容或修复方式有不同记录。
- **动作/产物**：事实—影响—承诺—修复请求—复核日期；先恢复最小任务，不强迫和好。
- **翻转**：对方持续履约；若换接口无效且跨人复现，转流程/制度。

### M10 支配或报复风险

- **成立信号**：可信威胁、羞辱、骚扰、强制违规，或上报后出现可核对不利动作。
- **动作/产物**：安全计划、必要证据、可信支持、停止私聊条件、正式/专业渠道选项。
- **翻转**：风险评估与新证据改变；不得自行作医疗、法律或合规定性。

### M11 纸面制度失效

- **成立信号**：制度有入口但无监测、反馈、申诉或改规则权；近期案例不按制度运行。
- **动作/产物**：正式规则—实际规则—案例—决定/监测/申诉图。
- **翻转**：连续案例显示渠道实际可用；描述“大家都这样”不能代替案例。

### M12 选择权收缩

- **成立信号**：用户认为只有忍受或立即退出；健康、收入、家庭、合同或市场事实未知。
- **动作/产物**：解决/调整/退出选项、缓冲、最小可逆试探、退出阈值、不可逆确认点。
- **翻转**：新支持、市场反馈、健康/安全变化或组织回应改变方向；方向不等于授权执行。

## 5. 动作选择与不可逆授权

按“信息价值 ÷ 风险与成本”选择下一动作：

1. **澄清**：缺定义、事实或决定权；产物是问题卡、标准卡或责任账。
2. **低风险试探**：解释竞争且可逆；一次只改一个变量，预先写失败与回滚。
3. **调整接口/流程**：模式稳定且有局部权限；产物含 owner、规则、例外和复核。
4. **正式升级**：低权力方无法安全解决、规则需要更高权力或风险扩大；先留必要证据。
5. **暂停/退出准备**：安全、健康、伦理或长期选择恶化；先区分保护动作、准备和不可逆行动。

外发消息、替他人承诺、投诉、公开指控、修改制度、提交辞呈、签署或放弃权益等动作，执行前必须由用户明确确认目标、范围和影响。AI 可生成草案、比较选项和明确倾向，不能把草案当现实动作。

## 6. 案例校准

### 正例：把“同事不配合”拆成可翻转模式

用户提供两次具体事件：同事均未在约定时间给输入；两次请求都没有写用途和最晚需要时间。先按 R/F 并列，发送含用途、时间和降级后果的新请求。若对方按时交付，支持接口假设；若仍失约且其他团队也受影响，转 M05 或 M07。此时只能说“已完成区分解释的试探设计”，不能说协作已解决。

### 反例：用心理建议吸收制度成本

多人连续加班、优先级由领导频繁改变，建议用户“提高抗压、学会拒绝”。它漏掉 M02/M03/M07，把决定权与激励制造的问题个人化。正确动作是先呈现容量与取舍，由决定者确认，再观察规则是否改变。

### 边界例：单次失误与明确威胁

单次忘记抄送不能支持“对方针对我”，只生成事件账与澄清动作。明确威胁或强制违规即使只发生一次，也足以进入 M10 的保护路径；安全干预不要求用户用第二次伤害换取统计把握。

### 不可逆例：离职方向与提交辞呈

证据可以支持“倾向准备退出”，并设计市场试探、财务与权益核对；这不等于用户已决定离职，更不授权代发辞呈或指定日期。

## 7. 结果回流协议

每次现实动作后追加最小回流记录：

```text
事件/日期：
原判断与模式编号：
执行动作与实际授权者：
对方/制度真实回应：
用户侧变化（负荷/清晰/条件/选择）：
结果证据：
未解决部分：
原判断：保留 / 降级 / 推翻 / 转层
新判断与置信度：
下一反馈点或停止条件：
是否获授权写入人物/公司档案：
```

只有现实证据出现才能把 Problem 相应范围判为已解决。话术、地图、计划、档案模板和试验设计只证明干预已准备。回流优先更新事件、假设和有效期；未经用户授权不落盘，不把健康、情绪或去留信息默认写入长期人物档案。
