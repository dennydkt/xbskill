# 数据结论复核

## 触发与模型

一份排名、报表或评价被用来指责个人或业务时，先复核数值链与结论范围。保留真实差距、不同统计对象、刷新差异、计算错误四类解释。用户感到委屈不提高任何解释的可信度。

## 最小工作流

1. 保存原始文件只读副本、哈希、表名、单元格/查询坐标与数据截至时间；确认访问及处理范围，缺权限时停止相关取数。
2. 写下待检验的具体结论及影响决定，提取日期窗口、对象粒度、单位、分母、状态过滤、去重键、关联键和比较群组。可比口径未确定时给分支结果，不能自行挑选有利口径。
3. 从总数到分组再到明细定位第一处差异。对公式、隐藏筛选、合并与重复关联、迟到数据分别保留样本；至少检查一条正常记录和一条边界记录。公式结果缓存无新鲜度证明时重新计算或标未验证。
4. 在副本或只读查询里复算，保存可重复执行的公式/代码及中间数；运行成功后核验行数、唯一键、分子分母和差额守恒。禁止只修改最终数或按预期排名反推规则。
5. 交付 `原结论｜原口径与坐标｜发现与证据｜重算口径/公式｜原值/新值/差额｜受影响范围｜仍成立的较弱结论｜下一复核者`。口径改变产生的不同答案与原计算错误分开。
6. 报告分支：发现错误则提供更正稿；原值正确则保留结论并讨论真实差距；资料不足则给待核项和最小补证。用户决定是否提交，有权者决定评价或资源调整。

## 正反边界例

- 正例：部门目标100，完成80；一对多关联把完成数重复为160。去重后回到80，记录关联膨胀与影响行，不能称业绩翻倍。
- 反例：A完成80/100，B完成90/150；按完成率A为80%、B为60%，按完成额B较高。两个排序可同时成立，先核对考核指标，禁止挑选对用户有利的排序。
- 边界：只有截图与结论，缺公式和明细。可以指出待核口径，不能声称已复算或已经证明造假。

## 验证

同快照同规则独立重算一致才称计算复核完成；更正被采用与绩效改变需真实反馈。新规则、刷新或抽查反例出现时重开受影响结论。能直接解决的单表计算当轮交付，不能把工作退回为只有一份检查清单。
