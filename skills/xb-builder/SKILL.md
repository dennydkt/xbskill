# xb-builder：专科孵化器

直调时先读取 `../xbskill/references/contracts.md`、`../xbskill/references/resolution-standard.md` 与 `../xbskill/references/specialist-rewrite-method.md`；任何文件缺失时报告精确路径并停止，不得凭记忆补造。候选框架依赖外部资料时，再读取 `../xbskill/references/knowledge-source-protocol.md`。

## 核心原则

先解决问题，再设计 Skill；先拆动作，再找理论；框架必须绑定动作并在真实片段上试跑；低于准入标准不沉淀。DBS 或其他 Skill 只能作为白盒研究样本：程序机制可以保留，领域语义必须重推导，有害先验必须拒绝。

## 流程

1. **问题定形**：冻结用户原话、对象、期望结果、当前卡点、反复出现的通用任务与普通回答为何不够；先交付一个真实样本的当前解。
2. **拆动作槽位**：定义、取证、归类、因果、决策、生成、验证、交付、回流；同时检查问题是否只是目标、状态与主体性、能力、人物/权力或公司对象缺失，写明缺少每项会错在哪。
3. **画候选器官图**：触发/边界、专科模型、观察字段、竞争解释、辨别动作、分支/阈值、产物、正反边界例、现实验证与翻转。
4. **逐字段三分**：对借鉴内容记录 Keep / Re-derive / Reject。只要改变因果、权限、风险或完成定义，就按完整证据闭环重写，不做全局换词。
5. **选择框架**：为动作选 1–3 个候选，写它改变哪项观察和动作、适用条件、失效原因；不得只堆理论名。
6. **试跑差异样本**：至少两个真实或高保真样本，其中一个是反例/边界例，一个由不懂该域的新手按字面执行；记录设计者未提示时的真实卡点。
7. **自我一致性审计**：每个不问、不确认、不验证、不处理、默认转换和有意省略必须显形；检查是否默认用户应该继续做、适应环境或提高雇主产出。
8. **八门评分**：按重写方法的 G/C/A/P/S/E/R/V 各 0–2。任一项为 0 拒绝上线；任一项为 1 留在重写区；八项全 2 才称完整专科。高总分不能抵消硬门缺失。
9. **建设与渐进披露**：准入后才创建/修改 frontmatter、运行流程、references/scripts、路由、UI 元数据、版本和测试。长字典与共享模式进一层 references，个人/公司内容不进入发布包。
10. **冻结答案后独立评审**：回答者不读评分表，评审者不参与设计；失败必须进入字段、流程、示例或自动测试，不能只留“以后注意”。

若候选框架来自思想家，只抽取可观察、可执行、可被反证的判断动作：写触发、观察、动作、产物字段、推翻条件和不适用边界。人物只作来源，不模拟人格、不伪造引语、不以声望代替证据。

若能力服务多个既有专科且用户主结果仍属于原专科，优先建设共享 reference、契约与验证脚本；显式治理任务交给最接近的既有专科。横切能力不得为了“看起来完整”新增菜单项。

## 否决项

一次性问题、依赖不可得事实、没有可验收输出、现有专科或五个系统对象已覆盖、只是横切契约而非独立任务、存在静默有意忽略、领域公理只能靠固定比例或人格归因成立、需要无授权高风险试验，任一成立就不新增。能通过深化现有专科或共享 reference 解决时，不增菜单项。

## 发布前

必须跑干净会话/陌生接收方：发现→安装→首次使用；缺文件必须响亮失败；个人内容与机制分离；按 `resolution-standard.md` 证明当前一步产生用户侧变化和反馈点；用 `xb-audit`、`workplace-regression.md`、专科深度回归与校验脚本验收。回答者与评审者分离，不能把设计者知道的验收标准偷偷补进试跑答案。若来源许可未确认，只发布独立表达的功能重实现，不逐字搬运原 Skill 资产。
