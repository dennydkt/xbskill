# v0.8 岗位知识参与式子 Skill 发布记录

## 1. 发布范围与现实边界

本轮新增 `xb-role-knowledge` 双态子 Skill：用户明确要补充、修订、停用或回测岗位知识时，它可以是唯一当前专科；普通任务中它只给已经选定的 `xb-*` 当前专科返回最小 `RoleKnowledgePacket`，不得成为第二个 current Skill。

首批目录覆盖 3 个岗位族、13 个岗位任务单元和 S0/S1/S2 三种帮助深度。目录激活只证明“来源、结构、匹配、权限、安全、陌生作答和运行轨迹通过本轮发布门”，不证明任何真实组织已经采用，也不证明现实 Problem 已整体解决。真实结果仍需由用户、业务 owner、验证 owner 和有权主体在任务发生后回流。

## 2. 不可缩水的运行契约

- 专业匹配只使用实际岗位族、当前责任、任务/信号和已填写的生命周期；企业类别、职级、工龄、性格不进入 matcher。
- `actual_constraints` 只接受带 `kind/value/evidence_date/evidence_ref` 的范围事实；项目覆盖还要精确命中该范围。
- 项目 `RoleKnowledgeUnit` 绑定同项目 `KnowledgePacket` 的文件 SHA-256、lock ID/digest、全部 claim、source 和 authority scope；知识包由当前账本确定性重建，手改即失败。
- 每个命中单元必须形成 `ApplicationTrace`，固定实际交付物 UTF-8 SHA-256，并把专业 effect、六项权限、全部风险门和本轮阶段适配绑定到交付物内逐字存在的片段；片段还必须逐项包含对应 effect 的原始内容，无关通用段落不能冒充参与。只引用、只列来源、只填未来计划或形式字段报 `E_RK_INERT`。
- 项目替代只有新旧单元同时完整命中角色、任务或信号、生命周期和有证据范围时才生效；`supersedes` 不是自动覆盖。
- 包生成、目录激活或测试通过均不等于现实事项完成。

## 5. 被真实复现并修复的门禁缺口

1. 证据只按 unit ID 找记录，候选内容偷换仍可激活：改为绑定 catalog ID/version/digest 和 `unit_id@version+unit_digest`，激活与运行时都重算。
2. 伪造或手改 `KnowledgePacket` 仍可被项目单元引用：知识管理器现在从 requirement/lock/source/evidence 确定性重建整包并 exact compare；岗位单元再固定 packet SHA-256。
3. 伪包、危险 flags、占位 Trace 和“未改变任何产物”曾可通过：现在先全量校验包，再要求实际 artifact、SHA-256、逐字片段、完整 controls 和结构化验证/反馈。
4. 不匹配任务或生命周期的项目 superseder 曾能压掉 builtin：替代只在新旧单元都完整命中后裁决；多替代冲突响亮失败。
5. `required_unit_ids` 曾可被 `max_units` 截断：请求进入匹配前即拒绝，结束后再核完整覆盖。
6. `xb-does-not-exist` 曾只靠字符串正则通过：现在必须存在同套件兄弟 `SKILL.md` 且声明同名。
7. 组织类别可借自由文本 constraint 或 matcher 进入专业覆盖：constraint 改为证据对象，常见中英文类别及同义词在 constraint 和所有 matcher 字段均被拒绝。
8. Windows junction 可把项目 catalog/knowledge/packet/evidence 指向项目外：所有根、直接子文件和包路径 resolve 后必须仍在 exact project root。
9. project candidate 的 helper 链曾无法完成完整陌生测试：现已支持同一 `--project-root` 下 deterministic(4) → blind(4) → assemble → activate，全链另在干净接收方验证。
10. schema 接受而运行时拒绝、布尔值冒充 schema version、声明式自签等漂移：严格类型、真实日期、目录/单元摘要、证据引用和四类覆盖均进入机械门。

## 7. 用户主动复核点

1. 从 [builtin-role-knowledge.json](../../xb-role-knowledge/references/builtin-role-knowledge.json) 任抽一个单元，核对它的专业问题、至少两个竞争解释、辨别动作、六权、风险门和 S0/S2 是否真的不同但不缩水。
2. 从 [role-knowledge-regression.json](../../xb-role-knowledge/references/role-knowledge-regression.json) 任抽一个 `independent_review`，沿 `answer_record_ids` 回到冻结答案，核对 scenario kind、unit digest、八门分数和 artifact-bound Trace。
3. 用同一专业任务只改变“国企/外企”标签，专业 claims、权限、安全线与验收应不变；只有真实制度或案例证据才能改变沟通、审批、留痕和制品包装。
4. 抽查一个项目覆盖：没有读取/用途授权、当前锁、packet SHA、精确范围或 authority confirmation 时必须失败，不能静默退回模型先验。
