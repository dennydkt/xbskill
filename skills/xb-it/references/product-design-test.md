# 需求、设计与测试契约

三个专业视角共同服务同一个小软件。需求描述用户可观察的结果；设计说明如何实现和处理失败；测试用独立预期证明结果。采用来源见 `method-sources.md`，以下文本为独立实现。

## 产品经理：确定最小可用范围

为核心需求赋稳定 ID（如 R-01），在 `docs/软件方案.md` 的需求章节填写：

- 用户与使用场景：当前步骤、频率、痛点，以及软件完成后用户拿到什么。
- 输入契约：格式、必填列、样例、规模；编码/时区/精度/公式/工作表/宏等仅填写确实相关的约束。
- 输出契约：文件或界面、存放位置、命名、预览、可追溯字段及交接对象。
- 业务规则：数据从输入到输出的转换，重复/缺失/冲突/无法识别时的行为；禁止由 AI 擅自定义业务事实。
- 本版范围：必做、可延后、明确排除，防止一次扩成复杂系统。
- 验收：给定具体样本、操作、可见结果；可复核的计算和数量，不能只写“正常运行”“体验好”。
- 未决事项：谁能决定、影响哪条需求、解决前可以继续哪些工作。

例：R-01“商品编码按文本读入，00123 导出仍为 00123”；R-02“编码相同的两行保留原值并标记待复核”；R-03“缺商品编码列时展示缺列原因并保持原文件”。这些为合成案例，实际规则由用户确认。

需求文档达到可开发条件：每条必做项都有输入、结果、异常行为与验收；重要未知已解决或明确排除。禁止用文档长度作为准入条件。

## 架构师与交互设计：选可维护的实现

先按目标环境排除不满足约束的形式，再提出一个推荐与必要备选。记录选择依据：安装/网络/权限、数据规模、处理能力、分发、学习与维护成本。把技术差异翻译为使用者会遇到的差别。

设计章节至少覆盖：

1. **界面草图**：入口、文件选择/拖放、必要设置、处理按钮、进度、结果预览/导出；按应用实际需求取舍。示例使用真实长度的合成文字，避免仅画空框。
2. **状态与交互**：首次空白、输入就绪、检查失败、运行中、成功、部分失败、重试；每种状态说明用户看到什么、能做什么。关键失败有原因和可行下一步。
3. **数据与模块**：输入解析 → 校验 → 处理 → 预览 → 输出；核心规则独立于 UI，原件/临时文件/正式结果分开。
4. **接口与依赖**：外部 API、端口、库、模板/模型/浏览器等实际前置；可选功能与必需依赖明确区分。缺必需依赖要显式失败，禁止假匹配、空结果或跳过处理后报成功。
5. **运行与分发**：启动入口、配置、相对路径、打包目标、关闭方法、更新与恢复方式；本地服务默认仅监听回环地址。
6. **与需求的对应**：每个模块和关键状态指向需求 ID；功能删改时同步检查受影响的设计与测试。

视觉默认清晰、简洁、少配置：清楚的主动作、可读字体和对比度、对齐与一致间距，颜色配文字说明。已有产品保持一致；用户有参考样式时使用参考。用静态可运行预览或图示确认样式，禁止把无后端预览说成已完成功能。

规模判断使用实际文件行数/体积、样本耗时和内存；无证据的性能数字标为待测试。大型文件需分块、后台任务或另选实现时，写明选择触发条件及测试样本。

## 测试设计：先定义可观察结果，再执行

本流程借鉴 TDD Master 的“测试定义驱动开发”：在编码前确定验收契约。随后由 xb-it 实现必要的自动测试、真实交互测试与交付包测试。测试文档本身只算设计产物。

每个测试使用稳定 ID，记录：关联需求、环境/前置、输入、操作、独立预期、失败信号、测试层、实际结果和证据。状态仅用“未运行 / 通过 / 失败 / 阻塞”，禁止无执行记录直接标通过。

| 测试层 | 小软件的实测重点 |
|---|---|
| 核心规则 | 正常、边界、错误输入；手工可核验的小样本；关键编码、计算、日期、去重与保留原值 |
| 输入与集成 | 缺列、空文件、格式不符、文件占用、无输出权限、外部服务失败；按实际功能选择 |
| 界面任务 | 从真实入口选择输入、完成操作、看进度、取结果；空白/错误/部分成功反馈符合设计 |
| 打包与重跑 | 新目录解压启动、中文空格路径、缺依赖明确提示、连续两次运行、保留原件；按支持平台实测 |
| 变更回归 | 旧样本、旧输出或明确允许的差异；错误修复新增能暴露该错误的用例 |

预期结果来自已确认规则、独立手算或可信基准。禁止调用待测实现生成期望值后再与自身比较。数值工具核对逐格/逐字段结果，UI 能打开不能证明计算正确。

必要的核心回归先看失败是否符合目标错误，再修实现并验证通过；记录实际结果。避免为静态文案或简单可逆调整制造无价值测试。关键业务功能必须覆盖所有必做需求，失败/未运行项保持可见。

用户确认前复核需求、设计、测试三者能否共同描述同一个软件；交付前再核对实际实现与三者一致。需求发生变化时同步更新关联项，保留变更原因与尚未运行的测试。
