# xbskill v0.7 岗位纵深陌生外测记录

## 1. 测试范围与隔离

- 日期：2026-08-11。
- 对象：数据岗位 D1、产品研发岗位 P5、职能岗位 F2；三案分别覆盖 S0、S2 和 S1，并刻意放入国企、外企/总部、事业单位语境。
- 回答者：每案在全新上下文中首次按 `xbskill/SKILL.md` 字面执行，只能读取入口按问题要求加载的共享参考与 `xb-*`；不得读取 `role-specialty-regression.md`、任何测试记录、测试脚本或旧答案，不得改文件。
- 评审者：答案冻结后由未参与作答的独立上下文读取当前八门与岗位参考，逐案按 G/C/A/P/S/E/R/V 各 0–2 分；不得用总分补偿单门缺口，不得由设计者给答案补字。
- 发布门：八门必须全部为 2；任一门为 1 留在重写区，任一门为 0 或边界硬门失败拒绝发布。
- 诚实边界：外测只验证“陌生回答者能形成合格的当前干预”。它不证明领导已经采纳、补券已经有效、CTO 已批准架构变更、采购已获批，或现实 Problem 已整体解决。

## 2. 发布前静态失败被保留

1. 第一轮 `forward_test.py` 在组织类别门失败：测试要求显式硬句“不得直接激活动作”，机制当时只有等价含义。修订为“类别种子不得直接激活动作”并重新执行；这是响亮约定缺失，不用语义相近掩盖。
2. 八门自我一致性审计发现，本记录建设期间曾把 G/C/A/P/S/E/R/V 错写为另一套扩展词义。现已恢复全套件唯一口径：目标适配、因果有效、行动权限、权力/结构、安全边界、证据证伪、现实结果、陌生外测；`forward_test.py` 固定检查八个全名和“全 2 才发布”。
3. Skill Creator 的 `quick_validate.py` 首次在 Windows 默认 GBK 解码下失败；设置 `PYTHONUTF8=1` 后八个被改 skill 均通过。这是验证工具运行环境问题，不记为内容通过，也没有删除失败记录。
4. 在本记录写入前，干净接收方静态测试为 **19/19**；manifest 因尚未发布 v0.7 而明确给出待重建警告。

## 4. 失败如何进入机制

| 失败 | 进入的运行规则 | 自动化锚点 |
|---|---|---|
| D1 C/E/R | `data-work-specialties.md` 增加口径、链路、结构、真实经营四本解释账及各自区分动作；关键主张须用独立查询、源系统总量或抽样回查交叉验证；统计对象/粒度显式核验；结构贡献不得冒充经营原因；补业务 owner 复核、决定采用与有依据观察窗 | `forward_test.py` 固定检查“四本解释账、独立查询、统计对象、业务 owner、不得代写原因” |
| P5 P/E | `role-context-model.md` 规定精确阈值、样本、窗口、角色和语言必须回指事实/制度/基线/决定人；`product-rd-specialties.md` 禁止自创“接下来 N 次”；`organization-strategy-genome.md` 禁止由外企/HQ 激活英语、护栏核对、区域复核或审批 | `forward_test.py` 固定检查阈值校准、知会不得扩写成审核、HQ 不得生成语言/职责/窗口 |
| 八门漂移 | `role-specialty-regression.md` 只保留全套件 canonical 八门和全 2 发布线 | `forward_test.py` 同时检查八门全名与发布硬句 |

这些规则改变观察项、动作和现实反馈，不只修饰措辞。

## 5. 重测隔离与无效样本

- D1 由新的陌生回答者重跑，用户逐轮只补其上一问需要的事实；回答者没有看到观察重点或旧评分。
- P5 第一次修订试跑的最后一条测试提示重复了“不自创阈值/HQ 职责”的验收方向，因此即使答案表现合格，也从发布证据中剔除。
- P5 随后换全新陌生回答者从原始问题重跑；后续只给制度/近三例权责事实和 6 个月技术事实，不给评分提示。
- 最终评审者为新的独立上下文，只收到冻结交互轨迹与最终输出；不得读取本记录、旧评分或测试脚本。
