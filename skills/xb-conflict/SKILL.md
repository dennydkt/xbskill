# xb-conflict：冲突处理

直调契约：还必须读取 `../xbskill/references/resolution-standard.md`；缺失时停止，不得把对话方案写成冲突已经解决。

完整读取 `../xbskill/references/context-protocol.md`、`../xbskill/references/agency-model.md`、`../xbskill/references/contracts.md` 与 `../xbskill/references/intellectual-capabilities.md`。任一文件缺失时，明确报出缺失路径并停止本专科；不得凭记忆补造。人物画像只能帮助形成可验证假设，不得替代事件事实或成为人格指控。

冲突通常包含竞争解释，默认完整读取 `../xbskill/references/people-domain-patterns.md`，使用原子事件、四层归因、权力账与模式编号。文件缺失时报告精确路径并停止本专科，不得凭记忆补造；只有用户明确只要一句不涉及归因的低风险回复时，才可转 `xb-talk` 而不加载。

## 触发与核心因果模型

冲突是“共同任务、预期、资源、责任、价值或权利不能按当前接口同时成立”，不等于双方性格不合。先恢复最小安全/任务结果，再判断是否需要修复关系。

| 层级 | 候选原因 | 区分证据 |
|---|---|---|
| 个人 P | 信息、技能、容量、单次失误 | 澄清/恢复/训练后稳定改变，且不跨人复现 |
| 关系 R | 预期、信任、承诺或沟通接口破裂 | 换对象/时机/确认方式后改变，模式限于特定关系 |
| 流程 F | 目标、owner、交接、验收、升级缺失 | 换人仍在同节点复现 |
| 制度 I | 权力、激励、资源和实际规则维持冲突 | 跨人跨期重复，成本稳定落给低权力方 |

权力差决定干预顺序：能安全表达才讨论整合；可信威胁、骚扰、强制违规或报复风险出现时先保护，不要求私下调解。

## 可观察信号词典

| 信号 | 候选解释 | 最小核验 |
|---|---|---|
| “他针对我/总甩锅” | 责任、关系、权力均可能 | 一次原子事件、原始记录、一次对照 |
| 双方引用不同版本或口径 | M06/F 流程冲突 | 哪个来源有权覆盖、版本时间 |
| 都说对方“没说清楚” | 请求/确认接口断裂 | 原请求、复述、确认状态 |
| 任务完成后才争责任 | M02/M04 | 决定、执行、验收、风险承担链 |
| 首次澄清后行为立即修正 | 误解/特殊事件增强 | 后续是否履约，是否再次出现 |
| 同类冲突跨人跨期出现 | F/I 增强 | 共同节点、规则、资源、激励 |
| 上报后出现排班/评价等不利动作 | M10 报复风险候选 | 时间线、决定人、原始证据、专业渠道 |
| “为了团队和谐你先忍一下” | 成本下沉/支配 | 谁获益、谁承担、可否申诉/拒绝 |
| 对方承认但反复不履约 | M09 或激励问题 | 承诺证据、复核、未履约后果 |

## 事实门

在把“针对、甩锅、报复、结构问题”写成主要归因前，至少取得两类材料：

1. **一次具体冲突**：时间、场景/渠道、各方可核对原话或动作、任务影响、在场人或原始记录。
2. **一次纠正路径回应**：安全时可以是向当事人的具体澄清及其原意回应；不安全、需要判断组织/报复路径时，记录向谁、何时、如何上报、对方原意回应或明确未回应及之后动作。两者都未发生时写 `未发生`，只设计最低风险动作并等待现实回应。

任一类缺失，或没有可核对的报复证据时，只给条件分支并用一个合并问题索取这两项，不先倾向个人或结构根因，也不把“没有回应”自动解释为报复。

“一次上报回应”只是在判断组织/报复路径时需要；普通任务或关系冲突可以先做安全的澄清/接口修复，不强迫用户为了取证而上报。尚未上报不得写成组织已失效。

## 思想镜头

每题最多启用 1–2 个镜头；先过事实门和安全闸，再留下 `触发证据 → 观察 → 辨别动作 → 产物字段 → 推翻条件`，不作人物扮演或引语。

- 双方立场冲突且能安全表达时，可用“利益整合”镜头，记录权力/资源、立场、核心利益、共同问题、整合方案、剩余损失与同意条件；存在可信威胁、报复或核心权利冲突时立即停用，不强迫共识。
- “按角色执行”混淆授权、执行和责任时，可用“角色—责任—强制”镜头，拆出指令、知情、裁量、可预见影响和异议渠道；授权链或报复证据变化时重分责任。

## 流程

1. 先评估安全、权力差与报复风险；有骚扰、歧视、威胁或重大合规风险时优先证据和正式渠道，不要求用户先私下对话。
2. 按目标过事实门，建事件时间线：可观察事实、各方解释、影响、已尝试动作和缺失证据；普通任务冲突不为取得“上报回应”而强迫升级。
3. 区分任务冲突、流程冲突、责任冲突、价值冲突、关系冲突和权力冲突。
4. 明确最低目标：恢复任务、澄清责任、制止行为、修复关系或正式升级。
5. 设计对话：共同目标—具体事实—影响—听取对方—明确请求—确认记录。
6. 给可能回应分支、停止对话条件、书面留痕和逐级升级路径。

## 模式与条件分支

1. **任务/事实冲突**：先统一对象、版本、验收和 owner；关系评价暂不处理。
2. **责任冲突**：建立提出—决定—授权—执行—验收—后果账；不按职位或谁先指责来分责。
3. **关系承诺冲突**：用 M09 记录承诺、破裂、修复动作和复核；修复任务不等于必须恢复亲密。
4. **流程/制度冲突**：跨人复现或规则维持时，用 M04/M05/M07/M11，动作转流程 owner、决定者或正式治理。
5. **权力/安全冲突**：M10 信号出现时停止整合/私聊，先安全、证据、支持和专业/正式渠道选项。
6. **证据不足**：只输出并列解释、最小取证和低风险下一步；不以“中立”为名要求用户再次暴露于伤害。
7. **用户只求一句回复**：可以先交付消息，但标明它仅处理本轮表达，结构归因与现实解决未完成。

## 动作与产物字段

- `事件时间线`：时间、场景、各方原话/动作、记录来源、结果、重复、对照。
- `四层归因表`：P/R/F/I 的支持、反证、未知、置信度与翻转证据。
- `权力责任账`：角色、授权、裁量、资源、后果、异议/复核、强制证据。
- `最低目标`：恢复任务、澄清责任、制止行为、修复承诺、正式升级之一；不能混成“大家和好”。
- `对话/保护卡`：事实、影响、请求、回应分支、停止条件、留痕、升级点。
- `复核卡`：约定动作、现实行为、用户侧变化、归因更新。

## 条件分支与微型例

- 只有笼统判断、没有具体冲突和上报回应：输出“任务误解、责任冲突、关系/权力问题均待验证”，先取一次具体冲突与一次上报回应；上报尚未发生时明确标记，不预演成事实。
- 正例：有具体冲突，但首次澄清后对方给出可核对修正并实际履行；先按任务/流程冲突处理，保留复核点。
- 有具体冲突，且上报后出现可核对的不利动作：先保护证据和安全，列正式渠道与停止私聊条件；仍不直接作法律上的“报复”认定。
- 反例：仅凭“他总针对我”就断言公司存在结构性压迫，并建议立刻投诉或离职。
- 边界例：一次明确骚扰或强制违规不需要等待重复或先和对方“充分沟通”；先转保护路径，同时明确 xbskill 不作法律定性。

## 验证、失败与翻转

- **验证**：对方是否按确认后的版本/责任/行为执行；任务是否恢复；伤害是否停止；正式渠道是否有可核对回应。
- **成功信号**：最低目标在约定范围内出现现实证据，而非只完成一次对话。
- **失败信号**：标准继续移动、承诺再次破裂、报复/羞辱升级、流程 owner 不处理、成本仍单向下沉。
- **翻转条件**：澄清后稳定修正则转特殊事件/R；换人仍复现则转 F/I；流程改变后消失则降低人格解释；新威胁证据出现则立即转 M10。
- **停止条件**：私下沟通会增加风险、用户无权改变根因、或渠道持续失效时，停止优化措辞，给调整/升级/退出准备和用户授权点。

## 输出与完成

输出 `事实门状态`、`事件时间线`、`解释/未知`、`权力与安全`、`冲突类型（置信度）`、`最低目标`、`对话或保护动作`、`回应分支`、`留痕/升级条件`、`镜头链（如启用）`、`复核日期/条件`。

只可声明“事实记录、条件分支、对话或升级方案已完成”；对话、上报、组织处理或关系修复未发生时必须明写。以对方下一次行为和上报渠道的实际回应回流，出现新证据后允许翻转冲突类型与路径。

回流记录 `原事件/归因/模式 → 实际动作与授权 → 对方/组织真实回应 → 最低目标证据 → 风险与用户侧变化 → 归因保留/推翻 → 下一复核点`。未经用户授权不写入人物/公司档案；写入时只存必要事实、日期和有效期。

## 禁止

不诊断人格，不鼓励报复，不把忍耐当成熟，不把正式投诉当第一或唯一方案。
