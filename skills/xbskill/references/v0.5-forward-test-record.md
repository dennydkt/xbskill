## 失败如何进入系统

| 失败组 | 进入的运行规则 |
|---|---|
| X01 | `xb-analysis` 增加模糊评价硬分支、四类竞争解释、逐候选置信度、权力否决/接纳责任与跨版本/人物验证；`xb-goal` 和路由禁止先做自我能力定性 |
| X02 | `xb-goal` 与 `xb-plan` 强制显形新旧版本、上层决定、真实容量、具体被挤出页/深度/核验及取舍决定人 |
| X03 | `xb-learning` 强制交付轨/能力轨分账，补 SQL 真实任务诊断、AI/用户/权限/复核/采用责任链、错误与净节省字段、迁移失败停止分支 |
| X04 | `xb-decision` 增加供应商/采购/合同/试单角色表，分开建议、质量/合规/财务复核、批准与执行 |
| X06 | `xb-data` 增加十分钟冲突数硬分支，覆盖快照、统计对象与粒度、源版本、ETL/同步批次、报表版本和总量到明细定位 |
| X07 | `xb-automation` 增加 AI+敏感数据+直接外发硬分支，以及五日观察窗、关键错误、采用率、复核/维护成本、实测净节省、扩大与停止阈值 |
| X08 | `xb-writing` 增加“硬锁不等于事实授权”，分别维护文字锁与事实授权；未确认承诺只能作为不得发布的草稿 |
| X09 | `xb-meeting` 在所有权扩散前先检验决定未形成、行动不可原子化/验收不清、依赖或容量未到位等解释 |

这些修订同时进入 `suite_manager.py` 深度锚点或 `forward_test.py` 静态门，避免教训只停留在复盘文字。

## 发布结论

v0.5 达到的是**专科协议与陌生首次使用层面的完整性**：12 个案例均能给出目标适配、条件性归因、权限、安全、证伪和现实回流。它没有声称现实 Problem 已整体解决；X06 还明确保留“唯一真值无法验证”。发布历史保留 177 → 189 → 192 三次分数，而不是只展示最后一次。后续真实使用若出现新失败，必须冻结原始提示与答案，按同一八门回流，而不是修改本记录掩盖历史失败。
