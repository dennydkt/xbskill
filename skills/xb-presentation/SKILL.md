# xb-presentation：汇报与演示

直调时先读取 `../xbskill/references/contracts.md` 与 `../xbskill/references/resolution-standard.md`；任何文件缺失时报告精确路径并停止，不得凭记忆补造。内容结论依赖外部专科材料时，再读取 `../xbskill/references/knowledge-source-protocol.md`。

演示依赖数据、多人材料、正式报告，或涉及外发、敏感信息、交付审查和会后自动流转时，读取 `../xbskill/references/task-domain-patterns.md`；简单口头更新不加载。

## 任务定义

演示在有限时间里帮助特定听众完成一种认知或决定；材料压缩只是页面加工环节。先写清本场任务：

- **知情**：听众能复述现状、影响和下一观察点；
- **判断**：听众能比较选项及证据；
- **决定**：有权者明确批准、拒绝、修改或延期；
- **协调**：各方确认依赖、责任和接口；
- **证明能力**：述职/答辩中用证据说明贡献、判断和成长；
- **教学**：听众能在演示后完成目标动作。

同一场可以有次要目的，但只能有一个主动作。用户完成 PPT 的 Question 可以本轮解决；会议是否通过、资源是否获得仍需现实反馈。

## 核心质量模型：决定链与注意预算

```text
听众当前认知 → 必须回答的问题 → 主结论 → 支撑证据
→ 选项与取舍 → 明确请求 → 质疑/边界 → 会后动作
```

每页承担一个“页面合同”：

| 字段 | 要求 |
|---|---|
| 页面问题 | 听众此刻需要回答什么 |
| 结论标题 | 在范围内成立的完整判断，不只是主题词 |
| 最少证据 | 足以支持该判断的图、数字、事实或例子 |
| 限制/反例 | 哪些条件下结论不成立 |
| 过渡 | 该判断自然引出哪个下一问 |

页面数量、图表数量和动画不是质量。信息只有在改变理解、决定、风险判断或后续动作时才进入主线；其余放附录或删除。

## 信号词典

| 信号 | 需要判断 | 常见失败 |
|---|---|---|
| “领导只看一页” | 这一页要知情、决定还是批资源 | 把十页字缩小塞入一页 |
| “材料很多” | 哪些材料改变决定 | 按材料来源而非问题组织 |
| “做得高级/专业” | 可信、简洁、视觉一致还是业务深度 | 装饰替代主张 |
| “多放数据” | 哪个主张需要哪条数据 | 数据堆积且口径不可见 |
| “讲讲过程” | 过程证明什么判断或能力 | 时间流水账 |
| “别暴露问题” | 是控制披露还是隐瞒决策风险 | 把风险藏到被问才说 |
| “要有说服力” | 对方的合法疑虑和决定门槛 | 只强化单方话术 |
| “准备 Q&A” | 哪些质疑会推翻、阻塞或改变方案 | 编造漂亮答案 |

## 模式与叙事分支

### A. 状态/项目汇报

用 `目标 → 当前结果 → 偏差及影响 → 已采取动作 → 下一步 → 需要支持`。活动只在解释结果或负荷时出现；黄/红风险要带责任人与处理时间。

### B. 决策/资源申请

用 `要决定什么 → 为什么现在 → 事实与约束 → 可选方案 → 取舍 → 推荐 → 请求`。至少给“不做/延期”作为真实选项；成本与风险落到谁承担。

### C. 方案提案

用 `现状证据 → 问题边界 → 目标 → 机制 → 方案 → 实施/验收 → 风险`。不能用页面数量填补因果链；机制不确定时把最小试验写清。

### D. 述职/答辩

用 `职责与目标 → 关键结果 → 我的可识别贡献 → 关键判断/取舍 → 证据 → 失败与改进 → 下一阶段`。区分团队成果、个人贡献和外部条件，不抢功也不把所有结果归因个人。

### E. 复盘/事故说明

用 `影响与当前状态 → 时间线 → 已知事实 → 原因置信度 → 控制动作 → 未知与验证 → 防复发`。先控制伤害；不要在证据不足时用单人责任制造确定感。

### F. 教学/演示

用 `完成目标 → 前置条件 → 示范 → 练习/检查 → 常见失败 → 独立完成`。讲完不是学会，必须留下可观察动作。

## 执行流程

1. 建听众卡：角色、权力、已有认知、利益/风险、可能异议、时间和保密范围。
2. 写一句“演示后，由谁基于什么作出什么动作”；没有决定权的人不能被设为批准者。
3. 建主张链：主结论和最多三个一级支撑；每项标证据、范围、反例和数据口径。
4. 选择叙事分支并画页面问题序列；若顺序不能写成连续问题，结构尚未成立。
5. 为每页填写页面合同；标题不能比证据强，材料不足时显式待确认。
6. 设计请求：对象、决定、选项、截止、资源、后果和会后记录；不要让“请指导”隐藏真实需求。
7. 准备讲述：开场主结论、每页一句口播、时间预算、可跳页、附录索引和中断后的恢复点。
8. 准备 Q&A：区分事实型、口径型、取舍型、权限型和攻击型质疑；不知道就说未知、取证责任和回填时间。
9. 验证：无讲者阅读、限时彩排、数字复核、最强质疑和会后动作模拟。

## 页面自检

- 遮住正文，只读标题能否看到完整推理？
- 遮住标题，只看证据能否支持该标题而非更弱结论？
- 删除此页是否改变决定？若不改变，移到附录或删除。
- 图表轴、单位、口径、来源和截至时间是否足够复核？
- 听众若不同意，能否指出是事实、推断、价值取舍还是权限分歧？

## 案例校准

**正例**：申请增加一名项目支持。第一页直接写“若不调整范围，当前人力无法在 9 月同时满足 A/B 两项承诺”，随后给容量基线、两种选项及风险，最后请求领导在周五前选择“加人”或“延期 B”。请求可决定，数据有范围，风险没有藏在附录。

**反例**：述职按一月至十二月列出参加会议、写材料和协助事项，每页标题都是“重点工作回顾”。它展示活动而非结果、个人贡献和判断，听众无法据此评价能力。

**边界例**：领导说只要“一页项目概况”存档，没有会议决定。此时可用状态卡而非强行造选项和请求；仍写数据截至时间、风险和负责人，但不把存档任务包装成决策提案。

## 验证、失败与翻转

- 彩排超时：优先删不改变主动作的页面，不把所有字体缩小。
- 听众需到最后才知道请求：主线失败，提前决定接口。
- 数字或口径未核：对应标题降级为观察/待确认，不能靠附注免责。
- 最强质疑出现就让推荐失效：把质疑和备选带进主线，或降低推荐置信度。
- 会上没有有权决定者：本轮成功信号改为形成建议和升级材料，不称获得决定。
- PPT、讲稿和 Q&A 已交付但会议未发生：只能判演示产物已完成。

## 结果回流

会后记录听众实际提出的问题、决定、未决项、承诺、负责人和日期。比较预期疑虑与真实疑虑，更新听众认知而非固化人格标签；记录哪些页面改变决定、哪些造成误解、哪些未被使用。演示净收益看决定清晰度、返工和会后执行，不以“讲得不错”或视觉好评代替。
