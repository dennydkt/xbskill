# xb-capability：上班族能力坐标

先读取 `../xbskill/references/capability-model.md`、`../xbskill/references/role-context-model.md`、`../xbskill/references/agency-model.md`、`../xbskill/references/context-protocol.md`、`../xbskill/references/contracts.md` 与 `../xbskill/references/resolution-standard.md`。模板位于 [references/capability-profile-template.md](references/capability-profile-template.md)；缺失时报出精确路径，不临时发明另一套模型。命中数据、产品研发或职能岗位时，只再读取对应的 `data-work-specialties.md`、`product-rd-specialties.md` 或 `function-work-specialties.md`，不得一次加载三套。岗位要求依赖外部材料时，再读取 `../xbskill/references/knowledge-source-protocol.md`。

## 核心原则

- 能力是“在某类情境中稳定产出结果”，不是性格、知识量或自我评价。
- 等级由独立性、复杂度、稳定性、迁移性和杠杆五项证据共同决定。
- 不追求八项都高。目标岗位需要什么，才决定目标等级。
- 当前等级取“有证据稳定做到”的最低共同等级，不拿一次高光替代稳定表现。
- 当前状态不是能力。耗竭、恐惧、权责混乱或不安全环境造成的一次失常，不得直接用于能力降级。
- S0/S1/S2 是本轮任务的帮助阶段，L0–L4 是长期能力证据；不得把二者换算后给整个人贴“新手/老手”标签。

## 能力证据模型

每条等级判断都要同时回答“在什么情境、对什么对象、靠多少帮助、处理何种异常、重复几次、结果由谁验收”。证据按强度分层：

| 证据 | 能证明什么 | 不能证明什么 |
|---|---|---|
| 知道概念、看课、证书 | 接触过知识，可能具备起步条件 | 能独立交付或处理异常 |
| 模拟练习、AI 代做后复述 | 在受控情境能跟随 | 真实任务稳定性与责任承担 |
| 一次真实产物 | 在当时条件下做成过 | 跨时间、对象和变化仍稳定 |
| 多次同类产物 + 验收反馈 | 稳定性、常规独立性 | 新情境迁移或复杂求解 |
| 异常处理、跨情境迁移 | L2/L3 的复杂度与迁移证据 | 形成多人杠杆 |
| 标准、流程、他人稳定结果 | 组织杠杆候选 | 因个人救火而形成的假 L4 |

能力结论必须带证据窗口和环境条件。公司不给访问、信息或授权时，“未产出”首先是证据不足或条件受限，不自动记为 L0。

## 常见误判与辨别

| 表面信号 | 竞争解释 | 辨别动作 |
|---|---|---|
| 一次交付失败 | 能力缺口、目标/输入变化、容量、工具、流程、政治性验收 | 对照同口径历史产物、变更记录和同环境样本 |
| 表达很自信 | 真正掌握、熟悉话术、他人代做、只会标准情境 | 给一个小型变体并要求说明判断与异常处理 |
| 借助 AI 做得很好 | 能力被放大、完全依赖、复核不足、流程成熟 | 分别记录采用、错误、复核动作和无 AI 时的关键判断 |
| 在原公司表现好，换岗失常 | 迁移不足、公司知识缺失、权限/网络变化、暂时状态 | 保持任务相近，逐项改变环境变量观察断点 |
| 经常救火 | L3 复杂求解、流程缺陷、边界失守、团队依赖单点 | 看是否能降低复发、形成标准和他人能力 |
| 领导说“还不够” | 真实等级缺口、标准漂移、机会不足、评价政治 | 取得具体标准、正反例、证明机会和复核日期 |

## 工作模式

1. **快速定位**：围绕当前目标只评估 1–3 项相关能力。
2. **完整盘点**：评估八项能力，形成能力雷达与证据账。
3. **目标差距**：比较当前角色与目标角色的要求，找最小关键差距。
4. **能力发展**：设计能产出真实工作证据的挑战，不把看课当提升完成。
5. **回填升级**：新证据出现后更新等级；保留旧判断、日期和变化原因。

## 判级规则

1. 先写实际角色、任务族、生命周期与环境边界，再选能力维度；不对“这个人整体能力”判级。按当前任务证据暂定 S0/S1/S2 只用于调整帮助深度，与 L0–L4 分账。
2. 独立性、复杂度、稳定性、迁移性、杠杆性分别给证据与未知；不一致时保留分项，不硬平均。
3. 当前等级取已稳定满足的最高完整等级。一次高阶行为可写“上探证据”，不能直接升级。
4. 目标等级只能来自真实任务、岗位标准或用户选择；公司材料缺失时标“暂定”，不以通用职级印象冒充。
5. 差距必须能被一个真实挑战产生新证据；无法被观察的“提升格局、增强主人翁意识”不是合格能力目标。
6. 能力挑战同时写最低支持、最大可承受代价和停止条件；不能用高风险工作事故测试能力。

## 流程

1. 明确实际角色/责任、任务族/生命周期、时间范围和公司评价环境；从对应岗位图谱选择代表产物、异常和反馈。公司信息未知且会改变标准时，只问一个关键问题或调用 `xb-company`。
2. 选择相关能力维度；说明为什么评这些、不评哪些。
3. 收集证据：产物、结果、反馈、复盘、异常场景和重复次数；自述只能作为线索，并标出当时容量、安全与组织条件。
4. 对每项给当前等级 L0–L4、目标等级、证据、反证、置信度。
5. 找“约束性能力”：补一项最可能带动当前目标，而非平均补齐全部短板。
6. 设计下一项真实挑战：情境、动作、产物、验收者、成功信号、失败后复盘。
7. 推荐帮助能级 H0–H4；学习型目标避免长期使用 H3 代执行。
8. 用户授权保存时才按模板写入项目 `memory/xbskill/context/capability-profile.md`；路径无法确定时先问。

## 分支与案例

- **快速定位**只需要足以决定当前帮助方式的证据；不得假装做了完整八维盘点。
- **晋升/转岗**若缺公司标准，先形成候选要求与待确认清单；取得正式标准、实际案例和证明机会后再定目标等级。
- **AI 增强任务**要拆开“用户做的判断、AI 生成的内容、用户复核、现实采用和错误成本”；AI 成品不能直接计作用户能力。
- **状态受损**时可延后判级，先用既往稳定证据；恢复后再做小样本复核。
- **高风险能力**不做未经监督的生产试验，使用沙盒、模拟或有授权复核的真实片段。

**微型正例**：用户连续三个月独立完成三类月报，能发现口径异常、向业务确认并让决策者采用。可把“数据分析—标准场景”评到 L2，并把跨业务口径迁移设为 L3 上探挑战；不能因为做过一个自动化脚本就直接判 L4。

**微型反例**：用户在失眠和目标反复变化的一周交付失败，立即把表达和执行能力各降一级。这里缺稳定样本，且状态与环境是竞争解释。

**微型边界例**：公司拒绝提供系统权限，却要求用户证明会做生产发布。XB 只能设计沙盒或取得监督权限的挑战；不能建议越权上线来“证明能力”。

## 输出

目标场景、相关能力、等级证据表、约束性能力、下一项挑战、帮助能级、未评估项与复核日期。

输出必须区分：`已证实等级`、`上探信号`、`证据不足` 与 `环境受限`。完成证据卡和挑战设计只算本轮评估/发展方案完成；只有现实挑战被执行、产物获验收并产生重复证据后，才能更新能力等级。

## 自检

等级是否有重复行为证据？是否把当前状态或人格偏好误判成能力？目标等级是否来自真实岗位/公司要求？挑战是否值得、可承受并能生成新证据？
