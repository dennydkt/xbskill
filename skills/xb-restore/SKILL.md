# xb-restore：恢复工作状态

直调时先读取 `../xbskill/references/contracts.md`、`../xbskill/references/resolution-standard.md` 与 `../xbskill/references/session-memory-protocol.md`；任何文件缺失时报告精确路径并停止，不得凭记忆补造。

## 欢迎回来开场（宾至如归）

供导航壳启动时调用。项目确定且存在 `memory/xbskill/` 时：

1. 先读 `progress.md`（若存在，这是最快入口）；无 progress.md 再列 `sessions/*/session.md` 与旧版完整快照。
2. 开场不超过两行：一行带上次的主目标、当前一步和反馈点（标注“记自 MM-DD”），一行问现状（“接着上次的 X 继续，还是今天有新的事？”）。不倒全部细节，不重复教程。
3. 没有存档的项目不输出任何“欢迎回来”；直接处理当前问题。
4. 记忆空白不得用“我记得”填充；不确定就说不确定，诚实优先于亲切。
5. 开场只负责接住，不机械执行存档里的 next step；是否继续由用户本轮目标重新判断（见流程第 6 步）。

## 流程

1. 确定项目和 `memory/xbskill/` 目录；缺失时明确“没有可恢复存档”并询问正确路径，不新建空目录冒充成功。
2. 列出候选会话/快照的时间、标题、目标和完整性，不能仅凭“最新”跨项目猜测。
3. 读取选定 `session.md`、`classification.md` 及其中引用的必要产物和 `context/` 档案；引用缺失必须报路径。默认不加载 transcript 全文，用户要求核对原话或分类来源时只读取相关轮次，降低敏感内容重复暴露。若会话含活动决策事件，按事件 ID 与绝对路径读取原事件，分别识别当时事实/判断/假设和后来追加的结果；不得用回填结果改写“当时就知道”。
4. 输出恢复包：上次目标与 G 层级、价值需要、解决/调整/退出判断、H 帮助能级、Question/Problem 类型、解决范围、用户侧变化、现实证据或下一反馈点、未解决部分、已确认事实、结论、产物、采用的 SourceLock/claim IDs（若适用）、活动决策事件的 ID/路径/决定—授权—执行—回填状态/下一复盘触发（若适用）、能力证据、人物/公司约束、否决项、待验证、下一步。旧状态摘要只作为历史，不推定用户现在仍相同；旧知识锁若失效则响亮报告，不退回模型记忆。
5. 做时效检查：目标、当前状态、选择门是否变化，人物画像与公司档案是否过期，哪些路径失效、哪些决定已过期；活动决策事件若已有新结果但尚未回填，明确建议转 `xb-decision` 追加回填，只向用户确认会改变行动的差异。
6. 用户确认后继续当前一步；不机械执行存档里的 `next step`，由最新目标重新判断。
