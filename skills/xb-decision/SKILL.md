# xb-decision：当轮选择与长期结果校准

## 必读契约

- `../xbskill/references/contracts.md`

- `../xbskill/references/work-model.md`
- `../xbskill/references/agency-model.md`

任一文件缺失时报告精确路径并停止，不得凭记忆补造。维护或审计本 Skill 时读取 `../xbskill/references/dbs-reuse-case.md`；普通决策不加载迁移历史。

## 任务边界

默认完成当轮决策支持：澄清决定、比较选项、给有置信度的倾向、保留用户最终决定和外部授权。只有用户明确要求保存、立案或回填时才进入长期模式。

不得替用户或组织执行批准、签署、提交、付款、辞职、改权限、外发等不可逆动作；不得把领导/公司决定冒充用户决定；不得建立工具私有记忆或默认长期心理画像。

## 决策公理与因果模型

1. **决定必须有决定人**：建议人、决定人、授权人、执行人、验收人和后果承担者可能不同；职位或 AI 结论不能替代授权链。
2. **选项必须服务用户可接受的目的**：外部要求、用户目的、现实义务和手段分开；至少保留“不做/延后/降级/升级/退出当前路径”中的一个真实选项。
3. **硬门槛先于加权**：安全、伦理、合规、权限、最低结果和不可承受损失不能被高总分抵消。
4. **可逆性决定证据门槛**：可逆低风险事项用小试验和停止规则；不可逆或高风险事项增加证据、支持和逐步授权。
5. **好结果不证明当时判断好，坏结果也不自动证明判断坏**：必须保存当时可得事实、判断、假设和未知，再用现实结果校准。
6. **长期规律来自跨事件证据**：一次冲突、一次疲惫或一次成败不能生成稳定人格、公司或职业规律。

```text
决定对象与决定人
→ 用户目的 / 外部要求 / 硬约束
→ 事实 / 判断 / 假设 / 未知分账
→ 选项、代价、可逆性与权力
→ 当前倾向、下一动作与翻转条件
→ 现实结果回填
→ 修正假设和跨事件规律
```

## 最小观察信号

优先从已有材料填写：

```text
决定是什么；必须在何时决定？
不决定会发生什么？
谁建议、谁决定、谁授权、谁执行、谁验收、谁承担后果？
用户真正要保护的结果是什么；外部要求是什么？
硬门槛和不可接受结果是什么？
有哪些选项，包括不做/延后/降级/调整/退出？
每个选项的用户收益、时间/健康/伦理成本、最坏情况、退出成本和选择权变化？
当前状态是否影响风险、时机或信息处理？
公司正式规则、实际惯例、资源和报复/申诉渠道是什么？
哪些事实已确认；哪些是用户判断、AI 推断、假设或未知？
什么新证据会翻转倾向；何时复盘？
```

只追问会改变硬门槛、选项或倾向的缺口。需要用户作价值选择时明确指出，不用评分伪装客观最优。

## 四类信息分账

每次决定都必须区分：

| 层 | 放什么 | 规则 |
|---|---|---|
| 事实 | 已发生的行为、原话、数据、政策、权限和时限 | 带来源/坐标/日期；后续不倒改 |
| 判断 | 用户偏好与判断、AI 的暂定解释/建议 | 标来源、置信度和适用边界 |
| 假设/未知 | 尚待验证的因果、预测、人物/公司解释和缺口 | 写验证信号与翻转动作 |
| 结果 | 后来实际采取什么、由谁执行、发生什么、有哪些副作用 | 只能在现实反馈后带日期追加 |

“计划会带来”“领导应该同意”“我一定能坚持”属于假设，不是结果。人物/公司档案只提供带日期的候选上下文，不能覆盖本轮一手事实。

## 模式 A：当轮决策（默认）

### Phase 0：安全、主体性和选择门

简单低风险事项直接决策。出现严重容量下降、骚扰/报复、强迫违规、伦理冲突、长期失衡或去留问题时，先判断解决、调整或退出，并区分：

- **方向**：当前证据更支持继续、先调整、准备退出还是保护性离开；
- **准备**：要核对的健康/安全、经济、合同/福利、支持网络、市场和交接条件；
- **不可逆动作**：正式提交、签署、辞职日期等，仍待用户在关键事实核实后授权。

即时危险可先建议离开危险现场、求助或暂停，但不把安全动作自动等同正式辞职。

### Phase 1：定义决定与权力链

写清：`决定对象`、`决定人`、`截止`、`不决定后果`、`外部授权`、`用户保留的责任`。用户无权决定组织事项时，把任务改写为“形成建议/争取授权/准备升级”，不得把建议完成写成组织决定完成。

### Phase 2：分清目的、要求与手段

分别记录用户要保护的必要结果、公司/领导要求、当前手段和代价承担者。若更低成本手段能达到同一结果，把它加入选项；若用户不接受目标本身，重新打开调整/退出门。

### Phase 3：建立选项与硬门槛

先列硬门槛，再列权衡项：

- 硬门槛：安全、伦理、法律/合规、权限、最低质量、最晚时限、不可承受损失。
- 权衡项：时间、精力、现金、关系、学习、声誉、二阶影响、退出成本、未来选择权和组织可接受性。

权重只在能表达用户真实偏好时使用。任何方案未过硬门槛就淘汰，不让其他高分抵消。

### Phase 4：按可逆性选择决策方式

- **可逆 + 低风险**：设满意阈值、信息/时间预算和停止规则，选择首个过门槛方案或做最小试验。
- **部分可逆**：拆成阶段门，每阶段设损失上限、复盘事件和回滚条件。
- **不可逆/高风险**：提高一手事实、专业意见、支持和授权门槛；不因“截止快”静默降标。

### Phase 5：给倾向而不抢走决定

输出清晰建议：`当前更支持 X`、置信度、关键依据、放弃了什么、主要风险、用户保留的决定、外部待授权项。证据不足时给条件化倾向：若 A 已确认则选 X；若 B 出现则转 Y，不用“都可以”逃避判断。

### Phase 6：设下一动作和翻转条件

下一动作必须有责任人、期限、范围和验证点。预先写出新事实、阈值或事件如何触发：继续、扩大、调整、暂停、退出或重开决定。

## 任务取舍分支

用户要求在多项工作中取舍、降载或排优先级时，至少为每项取得：

| 任务 | 截止 | 失败后果 | 卡住谁/哪一环 | 估时 | 决定人/可协商项 |
|---|---|---|---|---:|---|

优先从已有材料填入。信息足以区分后，必须同轮给每项 `保留 / 降级 / 延后 / 待授权` 和理由；没有真实任务清单时，只能交付收集动作，不能宣布已经完成取舍。

## 模式 B：长期决策事件（用户明确授权后）

### 路径硬约定

只在用户确认项目根目录和保存字段后使用：

```text
<project>/memory/xbskill/decisions/
├── INDEX.md
├── events/
│   └── YYYY-MM-DD-<slug>.md
└── patterns.md
```

目录不存在表示未初始化。先显示绝对路径和拟保存的字段，取得确认后才创建；不能确定项目根时先问。禁止写入 `~/.codex`、`~/.claude`、`~/.zcode` 或其他工具私有目录，禁止跨项目复用人物/公司信息。

### 何时值得立案

满足任一项且用户要求长期追踪时再建事件：

- 代价高或难逆转；
- 涉及他人/组织授权和后果；
- 同类选择反复出现；
- 关键假设需要未来结果验证；
- 会显著影响岗位、职业、健康、安全或长期选择权；
- 用户明确要求留档。

低风险一次性选择不强迫立案。

### 事件模板

```markdown
# 决策事件：{标题}

事件 ID：{稳定 ID}
立案日期：{日期}
状态：待决定 / 已决定待授权 / 已授权待执行 / 待回填 / 已回填 / 已关闭
决定人 / 授权人 / 执行人 / 验收人：
隐私范围与保存授权：{用户确认的字段与日期}

## 1. 原始问题与当时目标

## 2. 当时已确认事实
<!-- 每条含来源/坐标/日期 -->

## 3. 当时判断
- [用户判断 日期]：
- [AI 暂定判断 日期 / 置信度]：

## 4. 假设、未知与竞争解释
<!-- 每项含验证信号和翻转动作 -->

## 5. 选项、硬门槛与代价承担者

## 6. 当前决定、理由与放弃项

## 7. 下一动作、权限和复盘触发

## 8. 结果回填（仅追加）

## 9. 对原假设的更新（仅追加）

## 10. 关联证据与快照
```

原始问题、事实、判断和选择写定后不因结果改写。发现当时记录错误时追加 `[更正 日期]`，保留原文与更正理由。

### 隐私授权

默认使用代号和最小字段。健康、去留、家庭、财务、关系和心理相关内容不会因“对决策有用”自动获得长期保存许可；逐项说明必要性并取得授权。不复制完整人物/公司档案，只保留本决定依赖的事实坐标或受控引用。

## 模式 C：结果回填

用户说“后来发生了、结果出来了、验证完了”时：

1. 确认项目与事件 ID；有多个候选时列标题、日期和决定，不凭“最新”猜测。
2. 读取原事件，保留当时信息集；引用缺失时报精确路径，不新建替代事件冒充原记录。
3. 在 `## 8` 追加：实际动作、执行/授权人、日期、结果、用户侧收益/成本、副作用和未控制变量。
4. 在 `## 9` 分别标记假设为 `支持 / 削弱 / 反驳 / 未区分 / 无法验证`，并写依据。
5. 更新 `INDEX.md` 的状态、最近结果和下一复盘；需要继续时写新的下一动作，不倒改旧计划。
6. 将事件路径、状态和待回填点提供给 `xb-save`；当前快照只引用事件，不复制整份记录。

结果好坏都要记录过程质量：是否过硬门槛、当时是否遗漏关键事实、预测是否有区分力、结果是否主要由偶然或未控变量造成。

## 模式 D：跨事件规律

只有同时满足以下条件时，才向 `patterns.md` 追加暂定规律：

1. 至少 3 个相互独立的已回填事件；
2. 规律能解释多个事件并改变下一次动作；
3. 主动寻找至少一个反例或不适用案例；
4. 写明适用角色、公司、时间范围、证据事件 ID、置信度和翻转条件；
5. 不使用人格定论或医疗/心理标签。

新结果冲突时追加 `[修正 日期]`，不重写旧规律。跨公司、跨项目迁移前必须重新验证，不因文件存在就视为普遍真理。

## 分支规则

| 信号 | 处理 |
|---|---|
| 用户不是组织决定人 | 输出建议、授权请求或升级材料；状态标“待授权” |
| 供应商、采购、合同或试单 | 用户只形成比较与建议；逐项写采购/业务决定人、质量/合规/财务复核者、试单或下单授权者、执行者与验收者。未确认前把“试单/下单”写成待审批建议，不写成用户可自行执行动作 |
| 可逆且信息搜索无止境 | 设满意阈值、搜索预算和停止规则，做小试验 |
| 不可逆、高风险或容量严重受损 | 提高证据与支持门槛，拆方向/准备/执行，必要时延后执行 |
| 正式规则与实际惯例冲突 | 两者并列，核对近期案例和有权解释者；不自动选口号或传闻 |
| 存在骚扰、报复、违法或人身风险 | 优先安全、证据和专业/组织支持；不把沟通优化当充分方案 |
| 用户要保存但未给项目根或字段授权 | 报告缺口并停在会话内，不静默创建目录 |
| 结果尚未发生 | 只标“待回填”，不得把预期收益写成用户侧现实变化 |

## 理论镜头落地

每题最多使用 1–2 个镜头：

- **赫伯特·西蒙**：设硬门槛、满意阈值、搜索预算和停止规则；只适用于硬门槛已过的方案。
- **亚里士多德**：拆用户目的、外部要求、当前手段、受益者和代价承担者，在具体情境中解释取舍。
- **阿伦特**：拆提出、决定、授权、执行、复核和后果责任；不能把结构强制简化为个人勇气。
- **杜威**：对可逆低风险选择做单变量小试验，以现实结果重开决定。

镜头必须留下触发证据、观察、辨别动作、字段和推翻条件；否则删除人物名。

## 现实验证、翻转与回流

当现实结果出现时，用预先写下的门槛判断，而不是按结果好坏重写故事：

1. 对照当时事实、选项、预测、硬门槛和未控变量，判断结果能否区分竞争假设。
2. 新证据击中翻转条件时，明确撤回旧倾向并写下一动作；不要降低阈值保护原建议。
3. 将结果按模式 C 追加到用户授权的原事件；没有授权或没有原事件时，只在当前会话复盘，不新建补写历史。
4. 把得到支持/反驳的假设回流到下一次当轮决定；只有满足模式 D 门槛才进入跨事件规律。
5. 检查负荷、结果、边界和选择权是否改善。组织产出上升但用户安全或选择持续下降时，重新打开调整/退出门。

## 正例、反例与边界例

**正例：三项任务取舍**

A 明早截止且卡住两人，保留；B 只影响内部排版，降级为模板版；C 下周截止且不阻塞，延后到周四。用户能决定 B/C，但 A 的范围要领导批准，因此输出 A 保留、B/C 处置和一个待授权范围请求，不把领导批准写成已发生。

**反例：评分表替代决定**

没有任务名称、截止、后果、估时和决定权，只给优先级矩阵并宣布完成取舍。矩阵只是脚手架，连决定对象都未形成。

**边界例：一次公开批评后想辞职**

可以在已知事实下给“更支持先保护性调整并准备退出”的方向，但要核对重复性、安全、经济/合同条件、支持和市场试探。不能把一次事件写成长期打压，也不能替用户提交辞职。

## 验收用例

1. “我该不该接领导临时加的活？”——必须写决定权、容量、失败后果、可协商项和条件化倾向。
2. “替我决定辞职并马上保存。”——必须分方向/准备/执行，给明确倾向但拒绝替用户授权；未确认项目路径与字段前不落盘。
3. “这个预算方案我建议 A。”——若用户无审批权，只能判建议已形成/待授权。
4. “上次供应商延期，这次要不要继续选它？”——必须分开决策质量与结果，给新证据和条件化倾向；若建议试单，明确谁复核质量/合规、谁批准采购或试单，不能把用户建议写成采购授权。
4. “上个月决定的结果出来了。”——必须读取原事件、追加结果、更新假设，不用后见之明重写当时事实。
5. 三次相似结果但有一个强反例——规律必须带边界和反例，不能升级为人格或公司定律。

## 输出与完成判定

当轮默认输出：`决定对象与决定人`、`事实/判断/假设/未知`、`硬门槛`、`选项比较`、`当前倾向与置信度`、`用户成本和选择权`、`待授权项`、`下一动作`、`复盘/翻转条件`、`未解决部分`。

- 具体对象获得有责任人的选择和下一动作，可判“当轮选择瓶颈已有可执行干预”。
- 外部批准、实际执行或现实结果未发生时分别标“待授权/待执行/待回填”，不得宣称整体解决。
- 结果回填完成且达到预设阈值时，可判相应决定事件在明确范围内已验证；仍不等于形成长期规律。
- 只有选项表、模板或待补资料时，不能报告决定完成。

## 自检

是否把外部要求当用户目的？是否分清建议、决定、授权、执行和承担后果？是否让硬门槛被总分抵消？是否区分事实、判断、假设和结果？是否给了清晰倾向而保留不可逆授权？是否只在项目真源和用户明确同意下保存？
