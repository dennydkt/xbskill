### X05

不要把生产 token 贴到任何在线调试网站。这会把一个 403 故障升级成生产凭据泄露。

最快的安全处理顺序是：

1. 记录报错时间、请求方法和路径、响应错误码、`request ID/correlation ID`、最后一次正常时间及最近变更。删除或遮盖 `Authorization`、Cookie、签名和客户数据。
2. 在公司认可的本地或内部工具中检查 token 的元信息：`iss`、`aud`、`exp`、`scope/roles`、租户及调用身份；不要上传或在聊天、工单中粘贴完整 token。
3. 请系统负责人按以下顺序核对：

   - token 与生产端点、资源及环境是否匹配；
   - 当前身份是否具备该资源和动作所需的最小权限；
   - 是否存在资源归属、租户、IP 白名单、网关/WAF 或近期策略变更；
   - 若所有已授权用户都失败，按 `request ID` 查服务端或网关日志。

4. 如果确实缺权限，最快恢复方式是让资源负责人临时授予完成本次交付所需的最小权限，并写明范围、期限和撤销时间；不要借用账号、共享 token 或申请全局管理员权限。

可直接发给运维或系统负责人的信息：

> 【紧急协助】生产环境【系统名】调用【方法 + 路径】于【时间】返回 403，request ID 为【ID】。当前调用身份为【脱敏后的用户/客户端 ID】，token 的 aud 为【值】，scope/roles 为【值】，最后正常时间为【时间】，近期变更为【无/具体变更】。本次交付需要在【截止时间】前完成【资源 + 动作】。请协助核对资源权限及网关策略；如需授权，请仅授予上述动作所需的最小权限，并设置撤销时间。工单中未附生产 token。

如果 token 已经贴到第三方网站，应立即撤销并轮换，核查暴露时间后的调用日志，同时通知公司安全或系统负责人。删除网页记录不能视为凭据已经安全。

目前没有系统名、脱敏响应内容和 `request ID`，因此不能负责任地断言具体根因。修复成功的标准是：原请求使用获批的最小权限恢复，同时相邻的未授权操作仍然被拒绝。

### X06

现在不能认定其中一个是真的、另一个是错的。唯一能确认的是：两者相差 50 万，业务看板比财务表高约 5.1%（以 980 万为基数）；在统计对象、截止时间和计算口径对齐前，这两个数字不可直接比较。

十分钟内先核对三项：

1. 两边的数据截止时间和最近刷新时间；
2. 销售额按下单、付款、发货还是收入确认统计；
3. 是否含税、扣除退货取消、去重、人工调整，以及统计范围是否一致。

可以直接向老板这样汇报：

> 截至【时间】，财务表记录销售额 980 万，业务看板显示 1030 万，差额 50 万，约为 5.1%。目前两边的统计口径和刷新时点尚未完成对齐，因此暂不能判定哪一方数据错误。若本次用于财务确认、对外披露或利润测算，并且 980 万已经过财务确认，建议暂按 980 万使用；1030 万仅作为业务过程数据。若财务数字也尚未确认，则建议并列报告两个口径，不指定唯一数值，并由财务或指标负责人裁决统一口径。

对账时按“总量 → 日期或渠道分组 → 订单明细”逐层定位这 50 万。只有统一口径后仍存在差异，才能判断是哪条数据链路出了问题。

### X07

可以自动化，但在公司没有明确 AI 规定的情况下，不应把真实客户名单上传给外部 AI，更不应直接开放自动发信。客户信息处理和正式外发都有外部副作用，“公司没规定”不能视为已经授权。

目前最稳妥、也能省掉大部分复制粘贴工作的版本是：

1. 客户名单只在公司认可的本地或内部环境处理。
2. 用确定性规则完成去重、邮箱校验、字段整理、退订名单排除和模板填充；这些步骤通常不需要 AI。
3. AI 只用于草拟或分类，并且只接收完成任务所需的最少字段；未经确认不提供姓名、邮箱、电话等可识别信息。
4. 系统生成“待发送清单、邮件预览和异常清单”，不直接发送。
5. 由人确认收件人数、收件范围、主题、正文、附件及退订处理后，再通过公司认可的邮件系统发送。
6. 使用“批次 ID + 客户 ID”防止重复发送，并保留日志、失败重试、停止开关和人工接管方式。

正式上线前依次验证：

- 使用 5–10 条虚构数据跑通；
- 与人工结果做影子对比；
- 先发给内部测试邮箱；
- 经负责人确认后小批量发送；
- 错发、重复发送或无法及时停用时，立即退回人工审核模式。

需要公司或有权负责人确认的只有几个关键点：允许使用的工具、可处理的数据字段、数据是否会被留存或用于模型训练、客户联系及营销同意依据、允许的发件账号和范围、日志保留期限，以及异常由谁处理。

可直接发送确认申请：

> 我计划将目前每天约两小时的客户名单整理和邮件准备工作改为半自动流程。客户数据拟仅在【公司认可环境】内处理，首期只自动完成去重、校验、模板填充和待发送清单生成，正式发送前保留人工确认。请确认：允许处理的数据字段、可使用的工具、客户联系及退订规则、获准的发件账号和收件范围，以及审批和异常负责人。在获得确认前，不上传真实客户名单，也不启用自动发送。

要开始搭建，可以先提供一份完全虚构的 5–10 行样例、当前邮件模板、使用的公司邮件系统和常见例外。真实客户数据与自动外发仍需在获得授权后接入。
